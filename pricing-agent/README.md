# Агент ценообразования — прототип

Telegram-агент, который по клику называет **рекомендованную цену и почему именно её**.

Наружу уходит только это. Внутри по каждому лоту собирается полный аналитический
отчёт — позиция в доме, приведение цен соседей к нашему этажу, бюджет въезда,
сравнение с проектами локации, — но менеджеру нужна цена и три аргумента, а не
двадцать таблиц. Разбор открывается по кнопке, когда нужно проверить, откуда взялась
цифра.

**Пути реализации, методика, источники данных и оценка сроков — в
[`docs/IMPLEMENTATION.md`](docs/IMPLEMENTATION.md).** Здесь только как запустить.

## Главный принцип

Цену считает детерминированный код, а не языковая модель. LLM получает готовый расчёт
и пересказывает его человеческим языком, не имея возможности изменить число. Рекомендация
по лоту за сотни миллионов должна быть воспроизводимой и проверяемой построчно.

```
источники данных  →  ядро (детерминированный код)  →  LLM  →  Telegram
                     ← здесь считается ЦЕНА          ← здесь ТЕКСТ
```

## Что считается по каждому лоту

| Блок | Вопрос, на который отвечает |
|---|---|
| 1. Позиция внутри дома | Переоценён ли лот относительно соседей по экспозиции |
| 2. Проверка ценой этажа | Цены соседей приводятся к нашему этажу по надбавке, измеренной регрессией на прайсе застройщика |
| 3. Бюджет въезда | Цена + доводка до «въезжай». Покупатель сравнивает это число, а не цену в объявлении |
| 4. Локация | Метр **готовой** квартиры в соседних проектах: класс, срок сдачи, отделка |
| 5. Альтернативы | Что покупатель купит вместо нас на те же деньги |
| 6. Причины | Почему лот стоит, если цена внутри дома корректна |
| 7. Рекомендация | Цена и ограничение, которое её определило |

Ключевой вывод, ради которого всё это считается: **цена может быть корректной внутри
своего дома и при этом нерыночной в локации.** Тогда «снизить и подождать» не работает —
надо либо менять бюджет въезда, либо продавать другой продукт.

## Запуск

```bash
pip install -r requirements.txt

python scripts/parse_registry.py data/reestr.xlsx data/registry.json   # xlsx → JSON
python scripts/make_demo_comps.py                                      # демо-аналоги
python -m agent.cli                                                    # рекомендации по всем лотам
python -m agent.cli --report level-akademiceskaa-2                     # полный внутренний разбор
python -m agent.cli sky-house-6                                        # разбор одного лота
python -m agent.cli --feed                                             # собрать YRL-фид
python -m agent.cli --competitors                                      # аналитика по конкурентам
python -m agent.cli --competitors sky-house-7                          # конкуренты одного лота

python -m unittest discover -s tests -t .                              # тесты
```

Тесты — не формальность: `tests/test_reference_report.py` воспроизводит эталонный
отчёт аналитика по реальному лоту (метр готовой квартиры, паритет с соседями, бюджет
въезда, итоговый коридор 53–55 млн ₽), а `tests/test_guardrails.py` проверяет границы,
за которые расчёт не выходит: шаг снижения, пол по дому, отказ считать без данных.

## Аналоги: расширение «Циан → Excel»

Единственный источник **чужих** лотов — ни партнёрское API Циан, ни Яндекс их не отдают.
Расширение (ветка `claude/cian-apartment-scraper-4ns6ql`) собирает выдачу по ЖК в .xlsx;
импортёр берёт лист «Все_лоты» и превращает его в аналоги для коридора.

Положите выгрузки в `data/cian_exports/` — по одной на ЖК. Что берётся из файла:

| Колонка выгрузки | Зачем ядру |
|---|---|
| «Реальный срок, дн» | Срок экспозиции с поправкой на переподачи. Счётчик Циан сбрасывается при переподаче, и лот, висящий полгода, выглядит свежим |
| «Δ цены с 1-й выгрузки» | Накопленное снижение цены конкурентом — сигнал, что рынок торгуется вниз |
| «Переподач» | Много переподач при длинной экспозиции = рынок медленнее, чем показывает витрина |
| «Отделка/ремонт» | Поправка на отделку; в выгрузке указано, определена она полем Циан или из текста |
| «Тип продавца» | Лоты застройщика отбрасываются: первичка и вторичка — разные рынки |

Два правила, без которых выборка врёт:

- **Наши собственные лоты исключаются из выборки.** Они висят на Циан и попадают в
  выгрузку; в Sky House у нас три квартиры, и без исключения каждая сравнивалась бы
  с двумя другими — завышение целой группы стало бы невидимым.
- **Дубли схлопываются.** Один лот от нескольких агентств не должен голосовать дважды.

Если выгрузок нет, подставляется синтетическая демо-выборка — и об этом сообщается
первой строкой вывода.

**Лоты застройщика идут в двух режимах, и это не противоречие.** Из коридора внутри дома
они исключаются: первичка и вторичка — разные рынки, и прайс застройщика смещает оценку
перепродажи. Но именно на нём меряется надбавка за этаж — это единственный набор цен, где
все прочие условия равны по построению (один продавец, одна отделка, один момент времени).
И в анализе локации они учитываются полностью: там новостройка и есть конкуренция, без неё
из выборки исчезает целый конкурирующий проект.

## Локация: что заводится руками

Выгрузка Циан не знает ни класса проекта, ни срока сдачи, ни того, какие проекты вообще
сопоставимы между собой. Это `data/projects.json`:

```json
{
  "name": "Файв Тауэрс",
  "class": "премиум",
  "delivery": "ключи в I кв. 2027",
  "ready": false,
  "location": "Академический",
  "finishing_cost": 250000
}
```

- **`location`** группирует проекты в сопоставимую локацию. Без неё «ближайшим
  конкурентом» лота на Профсоюзной станет дом на Летниковской: формально другой проект,
  фактически другой город для покупателя. Если локация у проекта не заведена, анализ
  локации не делается вовсе — это честнее, чем сравнить с чем попало.
- **`ready`** отделяет готовые квартиры от строящихся: ключи на руках — это часть цены.
- **`finishing_cost`** переопределяет стоимость доводки (по умолчанию 150 тыс ₽/м²
  для бизнес-класса). Именно она превращает цену лота в бюджет въезда.
- **`aliases`** сводит написания одного ЖК: «Level Академическая» латиницей и «Левел
  Академическая» кириллицей — один проект, и никакая нормализация их не свяжет.

Чтобы агент считал по локации, а не только по дому, нужны выгрузки **конкурирующих
проектов** этой локации — по одной на ЖК, в подпапке. Сейчас так заведён только
Академический (`data/location_akademicheskaya/`); для Донского, Замоскворечья,
Дорогомилова и Якиманки выгрузок нет, и по лотам оттуда агент честно понижает
уверенность и пишет, что проверен только собственный дом.

## Яндекс Недвижимость

Партнёрского API у площадки нет, но есть три работающих канала, и связка между ними
замыкается без API — потому что `internal-id` в фиде назначаем мы сами, и он же
приезжает обратно в выгрузке звонков:

| Канал | Что даёт | Как подключить |
|---|---|---|
| YRL-фид (исходящий) | Публикация лотов; канал применения утверждённой цены | `python -m agent.cli --feed` → `YANDEX_FEED_PATH` |
| Выгрузка звонков (входящий) | Спрос по лотам: звонки за 7 и 30 дней | Кнопка «скачать» в кабинете юрлица → `YANDEX_CALLS_EXPORT` |
| Оценка квартиры | Независимая проверка коридора; на вердикт не влияет | `YANDEX_VALUATION_URL` (адрес метода — по договорённости) |

Пропущенные звонки и короче 5 секунд спросом не считаются. Разделитель CSV определяется
по строке заголовков: в русских выгрузках деньги пишутся с десятичной запятой, и
автоопределение по телу файла ошибается.

**Чужих объявлений Яндекс не отдаёт** — аналоги для коридора берутся из ЕГРН, своей базы
и платной аналитики.

Бот:

```bash
cp .env.example .env      # как минимум TELEGRAM_BOT_TOKEN
python -m agent.bot
```

`ANTHROPIC_API_KEY` не обязателен: без него объяснение собирается по шаблону, вердикт
не меняется. `YANDEX_CALLS_EXPORT` не обязателен: без него спрос берётся из демо-данных, и об этом
сообщается в первых строках вывода.

## Структура

| Файл | Назначение |
|---|---|
| `agent/models.py` | Доменные модели: объект, аналог, поправка, вердикт |
| `agent/lotreport.py` | **Полный отчёт по лоту и рекомендация — ядро аналитики** |
| `agent/render.py` | Два вывода из одного отчёта: рекомендация наружу, разбор для проверки |
| `agent/location.py` | Проекты локации, стоимость доводки, бюджет въезда |
| `agent/floor_model.py` | Надбавка за этаж регрессией по прайсу дома (с проверкой R²) |
| `agent/adjustments.py` | Поправки сравнительного подхода; коэффициенты в `PricingConfig` |
| `agent/pricing.py` | Коридор, перцентили, вердикт, ограничители, сценарии |
| `agent/analytics.py` | Аналитика по конкурентам: кто продаёт рядом, куда уйдёт покупатель |
| `agent/providers/cian_export.py` | Импорт выгрузок расширения — аналоги для коридора |
| `agent/providers/yandex.py` | Яндекс: звонки, оценка по дому, YRL-фид |
| `agent/sources.py` | Сборка источников: аналоги, спрос, локация, оценка по дому |
| `agent/narrative.py` | Пересказ готового расчёта через LLM с шаблонным фолбэком |
| `agent/registry.py` | Загрузка реестра + проверки консистентности своего прайса |
| `agent/bot.py` | Telegram-бот на aiogram |
| `agent/cli.py` | Тот же расчёт в терминале |
| `data/projects.json` | Реестр проектов локации — заводится руками |
| `tests/` | Регрессия на эталонном отчёте и проверка ограничителей |
| `scripts/` | Разбор xlsx, генератор демо-данных |

## ⚠️ О данных

`data/registry.json` разобран из настоящего реестра, но **отделка и наличие машино-места
выведены эвристикой из текста комментария** — их нужно подтвердить вручную.

`data/comps_demo.json` и `data/ops_demo.json` — **синтетические**. Они сгенерированы, чтобы
прототип запускался без платных ключей, и не являются рыночной информацией. Реальные аналоги
приходят из провайдеров (`agent/providers/`).
