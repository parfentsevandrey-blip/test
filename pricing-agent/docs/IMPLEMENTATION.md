# ИИ-агент ценообразования в Telegram: пути реализации

Документ отвечает на задачу: агент в Telegram, который по клику даёт автоматическую цену
по анализу рынка и рекомендацию поднять/снизить её для квартир из реестра.

В репозитории рядом лежит рабочий прототип (`pricing-agent/`), который считает вердикт по
всем 7 объектам реестра. Он нужен, чтобы обсуждать не абстрактную схему, а конкретные числа.

---

## 1. Что показал разбор реестра

Реестр — 7 лотов на **944 млн ₽**, разброс по цене метра почти пятикратный:

| ЖК | Адрес | Площадь | Этаж | Цена | ₽/м² |
|---|---|---:|---:|---:|---:|
| Level Академическая | Профсоюзная 2/22 | 79,5 | 15/19 | 54 млн | 679 тыс |
| High Life | Летниковская 11к1 | 125,1 | 8/24 | 93 млн | 743 тыс |
| Sky House | Мытная 40к1 | 127,5 | 12/22 | 103 млн | 808 тыс |
| Sky House | Мытная 40к3 | 155,4 | 9/29 | 127 млн | 817 тыс |
| Sky House | Мытная 40к3 | 155,6 | 12/29 | 135 млн | 868 тыс |
| Кутузовский XII | Кутузовский пр-т 12 | 93,4 | 6/11 | 152 млн | 1 627 тыс |
| Золотой квартал | Софийская наб. 18 | 87,5 | 4/6 | 280 млн | 3 200 тыс |

Три вывода, которые определяют архитектуру:

**1.1. «Средняя цена по рынку» здесь не работает.** Средневзвешенная цена метра в элитных
новостройках Москвы — около 2,3 млн ₽, но ей не соответствует ни один из семи лотов:
Level Академическая вчетверо дешевле, Золотой квартал на 39% дороже. Портфель лежит в трёх
разных сегментах (бизнес — премиум — deluxe), у каждого свой рынок. Единственная корректная
база сравнения — **аналоги в том же ЖК**, затем в том же классе в радиусе 1–1,5 км.

**1.2. Реестр не содержит половины полей, нужных для оценки.** Отделка и машино-место
спрятаны в текст комментария (парсер вытаскивает их регулярками — это ненадёжно и требует
ручного подтверждения), а даты выхода в экспозицию, истории цен, просмотров, звонков и
показов нет вообще. Без срока экспозиции и потока обращений агент видит только «дорого или
дёшево относительно рынка», но не видит **реакции рынка на нашу цену** — а это самый сильный
сигнал. Первый шаг любого из путей ниже — завести эти поля.

**1.3. В собственном прайсе уже есть нестыковка.** Два лота Sky House в одном корпусе
(Мытная 40к3), площади 155,4 и 155,6 м² — практически идентичные. Цена метра отличается на
**6,2%**, при том что разница в 3 этажа объясняет около 1%. Либо у верхнего лота есть
неучтённое преимущество (вид, планировка, отделка), либо один из двух выставлен неверно.
Покупатель, который смотрит оба лота рядом, эту разницу видит. Такую проверку агент делает
мгновенно и без всяких внешних данных — это самый дешёвый слой анализа.

**1.4. Рыночный контекст 2026 года играет против продавца.** По первому полугодию: спрос в
элитном сегменте упал почти на треть, предложение выросло на 18%, срок экспозиции вырос с
двух недель до 1,5–2 месяцев. Цены при этом держатся (+6% г/г). Это классическая картина
«рынок расходится»: цены предложения инерционны, сделки идут точечно, растёт торг. В такой
фазе агент по ценообразованию нужен не чтобы «поднять цену», а чтобы **не потерять маржу на
затянутой экспозиции** — вовремя увидеть, что лот встал, и предложить шаг раньше конкурента.

## 2. Ключевое архитектурное решение: цену считает код, а не языковая модель

Соблазн сделать «ИИ-агента» как промпт к LLM с доступом в интернет — сильный, но для лота за
280 млн ₽ это неприемлемо: рекомендация должна быть **воспроизводимой и проверяемой построчно**.
Модель не должна иметь возможности «придумать» цену.

Поэтому в прототипе жёсткое разделение:

```
источники данных  →  ядро (детерминированный код)  →  LLM  →  Telegram
   Циан, ЕГРН,        подбор аналогов, поправки,       пересказ      кнопки,
   CRM, свои          коридор, вердикт, ограничители   вердикта      карточки
   сделки             ← здесь считается ЦЕНА          ← здесь ТЕКСТ
```

LLM получает **готовый вердикт** и пишет по нему объяснение для менеджера, с прямым запретом
менять числа. Если модель недоступна — бот отвечает шаблоном, вердикт от этого не меняется.
Второе применение LLM — свободные вопросы («а что если снизим на 5%?»), но и там расчёт
делает ядро.

Такая же логика защищает от главного риска: агент, который сам придумывает цену, однажды
придумает её неправильно, и это заметят не сразу.

## 3. Методика: сравнительный подход с явными поправками

Это стандартная методика оценки, положенная в код. Каждый аналог приводится к характеристикам
нашей квартиры, после чего сравниваются уже сопоставимые ₽/м².

**Поправки** (все коэффициенты вынесены в конфиг и калибруются по своим сделкам):

| Поправка | Как считается | Дефолт |
|---|---|---|
| Машино-место | Вычитается из цены лота до перевода в ₽/м² | 6 млн ₽ — **откалибровано по вашему же реестру**: Кутузовский XII, 158 млн с местом против 152 без |
| Этаж | По относительной высоте `(этаж−1)/(этажность−1)`, чтобы сравнивать дома разной этажности | верхний этаж +10% к первому |
| Площадь | `−эластичность · ln(S_наш / S_аналога)` — крупный лот дешевле в пересчёте на метр | 0,12 |
| Отделка | Разница вклада в ₽/м² по тирам: без отделки → white box → от застройщика → дизайнерский → deluxe | 0 / 60 / 120 / 300 / 550 тыс ₽/м² |
| Сделка → экспозиция | Цены закрытых сделок поднимаются на величину типичного торга, чтобы сравнивать с ценами предложения | 8% |

**Веса аналогов**: тот же ЖК — 1,0; тот же класс в радиусе 1,5 км — 0,6; дальше — 0,3.
Закрытая сделка ×1,3 (она информативнее объявления). Свежесть — период полураспада 90 дней.
Сильно другой метраж штрафуется экспоненциально: 155 м² и 90 м² в одном доме — разные
покупатели.

**Вердикт** принимается по взвешенным перцентилям скорректированных ₽/м²:

- эффективное число аналогов < 3 → **ручная оценка**, автоматике не доверяем;
- перцентиль ≥ 75 и лот идёт медленнее рынка (или показов почти нет) → **снизить** до 60-го;
- перцентиль ≥ 85 даже без данных о спросе → **снизить** до 70-го (верхний дециль сам по
  себе ограничивает поток обращений);
- перцентиль ≤ 35, экспозиция в норме → **поднять** до медианы;
- иначе — **держать**.

**Ограничители** (без них агент начнёт раскачивать цену):
шаг не больше −7% / +5% за раз; пауза 21 день между изменениями; запрет на повышение, если
лот в экспозиции больше 90 дней; округление до «переговорной» цены в сторону ограничителя.

**Уверенность** (0–1) считается из числа аналогов, доли аналогов в том же ЖК и наличия данных
о сроках экспозиции. Показывается пользователю всегда — вердикт с уверенностью 0,35 и 0,94
требует разного отношения.

Реальный прогон на демо-данных даёт по портфелю: 2 «снизить/поднять», 3 «держать»,
1 «ручная оценка» — и по каждому полный аудит-след:

```
Sky House — Мытная 40к3, 155,4 м², этаж 9/29
Текущая цена: 127 000 000 ₽ (817 тыс ₽/м²)

Рекомендуем снизить цену до 119,0 млн ₽ (−6,3%)
• Аналогов: 9 (из них 6 в том же ЖК), эффективный вес 6,1
• Коридор рынка: 641 — 699 — 769 тыс ₽/м²; наша цена 817 → 93-й перцентиль
• Экспозиция: наш лот 74 дн., медиана по аналогам 58 дн.
• Снижали цену 5 из 9 аналогов (в среднем −8,1%) — рынок торгуется вниз
• Показов за 30 дней: 1
⚠️ Рынок допускает снижение сильнее, но шаг ограничен 7% за раз
```

> Числа в примере получены на **синтетических** аналогах (`data/comps_demo.json`) — это
> проверка механики, а не рыночная информация.

## 4. Источники данных — самая дорогая часть задачи

Механика вердикта — это две недели работы. Данные — это то, обо что задача обычно встаёт.

### 4.1. Циан API для агентств — основной кандидат

Официальный продукт, доступ по заявке на `import@cian.ru`, ключ выдаётся агентству. Даёт:

- **оценку ₽/м² в многоквартирном доме по адресу и данные БТИ** — быстрая независимая
  проверка нашего коридора, ровно то, что нужно ядру;
- **статистику по нашим объявлениям**: просмотры, звонки, добавления в избранное,
  идентификацию звонков по объектам — это и есть недостающие данные о спросе из п. 1.2;
- список объявлений, жалобы, списания, сообщения от клиентов.

Чего в партнёрском API **нет** — выгрузки чужих объявлений списком. Конкурентную выборку
берут либо из платной Циан.Аналитики, либо по договору с поставщиком данных.

### 4.2. Остальные источники

| Источник | Что даёт | Как получить |
|---|---|---|
| **Авито** | Автозагрузка своих объявлений по XML-фиду, статистика просмотров и звонков через партнёрские CRM | Личный кабинет + фид на своём домене |
| **ЕИСЖС / наш.дом.рф** | Проектные декларации застройщиков в машиночитаемом виде, база строящихся новостроек | Коммерческий API `наш.дом.рф/api-еисжс`, доступен любому юрлицу |
| **ЕГРН / Росреестр** | Зарегистрированные сделки и ДДУ — цены **сделок**, а не предложений | Через агрегаторы с API; у части есть бесплатные тарифы ~200 запросов/мес |
| **SRG, оценочные сервисы** | Массовая оценка жилья для банков, API | Договор |
| **Собственная история** | Свои сделки, средний торг, воронка показов | **Самый ценный и полностью бесплатный источник — его надо просто начать вести** |

### 4.3. Про парсинг

Парсинг Циан и Авито технически возможен и активно предлагается на рынке, но это нарушение
пользовательских соглашений площадок, на которых вы же и размещаетесь, плюс постоянная борьба
с антибот-защитой. Для агентства, работающего с лотами за сотни миллионов, репутационный и
юридический риск несопоставим с экономией. **Рекомендация: официальные каналы плюс своя база.**

### 4.4. Порядок подключения

1. **Неделя 1** — свои данные: заявка на Циан API (статистика по своим объявлениям), выгрузка
   истории цен и сделок из CRM. Уже на этом агент считает п. 1.3 (консистентность прайса) и
   динамику своей воронки.
2. **Недели 2–4** — конкурентная выборка по ЖК: Циан.Аналитика или поставщик данных.
3. **Месяц 2+** — сделки из ЕГРН для калибровки реального торга (сейчас 8% — допущение, а не
   измеренная величина).

## 5. Три пути реализации

### Путь A. No-code за 1–2 недели — «проверить гипотезу»

n8n или Make + Google Sheets вместо реестра + Telegram-бот из готового блока + вызов LLM.
По кнопке сценарий собирает данные, отдаёт их модели, модель пишет вердикт.

- **Плюсы**: работает через две недели, почти без разработки, легко менять.
- **Минусы**: цену фактически определяет LLM — вердикт невоспроизводим, аудит-следа нет,
  поправки не задокументированы. Для лота за 280 млн это не годится как рабочий инструмент.
- **Когда брать**: если нужно за две недели показать идею руководству и понять, будут ли
  менеджеры вообще этим пользоваться.
- **Ориентировочно**: 0–30 тыс ₽/мес, разработки почти нет.

### Путь B. Собственный бот с детерминированным ядром — 4–8 недель ⭐ рекомендуемый

Ровно то, что лежит в `pricing-agent/`, доведённое до боевого состояния:

- `aiogram` + PostgreSQL (реестр, история цен, кэш аналогов, лог вердиктов);
- слой провайдеров с общим интерфейсом: Циан → ЕГРН → своя база, с дедупликацией
  (один лот висит и на Циан, и на Авито, и без дедупликации трижды голосует за свою цену);
- ядро поправок и вердиктов с ограничителями — уже написано;
- LLM только для объяснения и свободных вопросов;
- планировщик: ночной пересчёт, еженедельный дайджест, алерт при снижении цены конкурентом
  в том же ЖК;
- роли: менеджер видит вердикт, руководитель — подтверждает изменение цены.

- **Плюсы**: воспроизводимо, объяснимо, расширяемо; методику можно защитить перед
  собственником; поправки калибруются по мере накопления своих сделок.
- **Минусы**: нужен разработчик и бюджет на данные.
- **Ориентировочно**: разработка 300–700 тыс ₽ (или 4–8 недель своими силами), инфраструктура
  3–10 тыс ₽/мес, данные 15–60 тыс ₽/мес в зависимости от глубины.

### Путь C. Платформа — 3–6 месяцев

Путь B плюс: интеграция с CRM (amoCRM / Битрикс24) в обе стороны, автопубликация новой цены
в фиды площадок после подтверждения, A/B-тест цен на схожих лотах, мониторинг конкурентов с
алертами, ML-модель поверх накопленной базы сделок, кабинет собственника с прозрачной
аргументацией цены.

- **Когда брать**: при портфеле от нескольких десятков лотов и потоке сделок, достаточном для
  обучения модели. **На 7 объектах ML не имеет смысла**: статистики нет, каждый лот уникален,
  переобучение гарантировано. Сравнительный подход с явными поправками здесь и точнее, и
  честнее.
- **Ориентировочно**: от 1,5 млн ₽.

**Рекомендация: A как двухнедельная проверка интереса менеджеров (по желанию) → B как рабочий
инструмент → C по мере роста портфеля.** Если проверка не нужна — начинать сразу с B.

## 6. Как это выглядит в Telegram

Реализовано в прототипе (`agent/bot.py`):

```
/start → список объектов, у каждого бейдж вердикта
   🔻 Sky House · 155,4 м² · 127,0 млн ₽
   🔺 Level Академическая · 79,5 м² · 54,0 млн ₽
   ⏸ High Life · 125,1 м² · 93,0 млн ₽
   ❓ Золотой квартал · 87,5 м² · 280,0 млн ₽
   📊 Сводка по портфелю

Карточка объекта — цена, коридор рынка, перцентиль, срок экспозиции,
вердикт с процентом, уверенность.
   [ Почему ] [ Сценарии ] [ Аналоги ] [ ↻ Пересчитать ] [ ⬅️ К списку ]
```

- **Почему** — объяснение от LLM плюс полный список учтённых факторов.
- **Сценарии** — три точки «цена ↔ срок продажи»: быстрая продажа / базовый / максимум цены.
  Это главный аргумент в разговоре с собственником: цена промедления в днях, а не в процентах.
- **Аналоги** — на чём построен коридор, с ценой до и после поправок.
- **Сводка по портфелю** — что требует решения, где мало данных, какие нестыковки в прайсе.

Дальше по потребности: еженедельный дайджест в канал отдела продаж, алерт при снижении цены
конкурентом в том же ЖК, выгрузка обоснования в PDF для собственника.

## 7. Риски и как они закрыты

| Риск | Ответ |
|---|---|
| Модель «придумает» цену | Цену считает детерминированный код; LLM только пересказывает и не может изменить число |
| Мало аналогов (Золотой квартал) | Порог: меньше 3 эффективных аналогов → вердикт «ручная оценка», уверенность ≤ 0,35 |
| Агент раскачает цену | Шаг ≤ 7% вниз / 5% вверх, пауза 21 день, запрет на повышение при экспозиции > 90 дней |
| Один лот на трёх площадках перекосит коридор | Дедупликация по адресу + этажу + площади до расчёта |
| Данные площадок недоступны | Провайдеры возвращают пустой список, а не падают; бот отвечает с пометкой о неполноте источников |
| Поправки взяты «с потолка» | Все коэффициенты в конфиге, машино-место уже откалибровано по своему реестру; дальше — по своим сделкам |
| Собственник не согласится со снижением | Сценарии «цена ↔ срок» и аудит-след по каждому аналогу — разговор идёт о днях экспозиции, а не о мнениях |

## 8. Что нужно от вас, чтобы начать

1. Подтвердить отделку и наличие машино-места по каждому лоту (сейчас выведены из текста
   комментария эвристикой).
2. Дать даты выхода в экспозицию и историю изменения цен по 7 лотам.
3. Подать заявку на Циан API (`import@cian.ru`) — статистика по своим объявлениям бесплатна
   и закрывает главный пробел в данных.
4. Выгрузить свои сделки за 12–24 месяца: по ним калибруется реальный торг и этажная поправка.
5. Решить, кто подтверждает изменение цены — от этого зависит роль бота: советует или меняет.

```bash
cd pricing-agent
pip install -r requirements.txt
```
