# SPEC: Weather app + widget для Pixel 10 Pro XL

## §0. Цель

Нативное Android-приложение погоды с виджетом. Ключевой критерий качества —
не функциональная полнота, а **ощущение от взаимодействия**: приложение должно
восприниматься как уютная игровая сцена, а не как таблица цифр. При конфликте
между «добавить фичу» и «довести до 120 fps без единого дропа» — выигрывает
второе.

Референс настроения: cozy game (Alto's Odyssey, Monument Valley, A Little to
the Left) × Material 3 Expressive. Не скевоморфизм, не неоморфизм, не
«стеклянные карточки».

## §1. Целевое устройство и окружение

- Основное устройство: Google Pixel 10 Pro XL.
- **Не полагайся на память по спекам устройства.** Если устройство подключено
  по adb — сними реальные параметры: `adb shell wm size`, `adb shell wm density`,
  `adb shell dumpsys display | grep -i fps`, `adb shell getprop ro.build.version.sdk`.
  Если устройства нет — подними эмулятор с максимально доступным API level.
- `minSdk`: 33 (даёт AGSL RuntimeShader и предиктивный back без ветвлений;
  фолбэки на старые API не пишем — это не продукт для магазина).
- `targetSdk` / `compileSdk`: максимальный стабильный, доступный в установленном
  SDK. **Проверь фактически доступное**, не пиши число по памяти.
- Единственная поддерживаемая ориентация в MVP: portrait. Ландшафт — не «сломан»,
  а осознанно заблокирован.

## §2. Стек

Обязательное правило: **все версии берутся из проверенных источников**
(BOM, Google Maven, `./gradlew dependencies`), а не по памяти. Если резолв
падает — найди реальную существующую версию, не подбирай наугад и не
понижай до древней.

- Kotlin (последний стабильный), Gradle Kotlin DSL, version catalog
  (`gradle/libs.versions.toml`) — все версии только там, никаких строк с
  версиями в `build.gradle.kts`.
- Jetpack Compose через Compose BOM. Material 3 (`androidx.compose.material3`)
  в версии, которая содержит Expressive API.
- Виджет: `androidx.glance:glance-appwidget` + `glance-material3`.
- DI: Hilt.
- Сеть: Retrofit + OkHttp + kotlinx.serialization (или Ktor — на твой выбор,
  но обоснуй один раз и не смешивай).
- Кэш: Room (прогнозы) + DataStore Preferences (настройки).
- Асинхронность: Coroutines + Flow. Никаких RxJava, никаких LiveData.
- Фон: WorkManager.
- Геолокация: `play-services-location` (FusedLocationProviderClient).
- Данные о погоде: **Open-Meteo** (`api.open-meteo.com`) — бесплатный,
  без API-ключа, без регистрации, отдаёт current + hourly + daily + WMO
  weather codes. Геокодинг — их же `geocoding-api.open-meteo.com`.
  Не завязывайся на сервисы с ключом.

## §3. Архитектура

Многомодульный Gradle-проект:

```
:app                    — точка сборки, DI-граф, навигация
:core:designsystem      — тема, токены, шейпы, motion-схемы, атомы UI
:core:ui                — переиспользуемые композаблы, модификаторы, физика
:core:common            — утилиты, Result, диспетчеры
:data:weather           — API, DTO, маппинг, Room, репозиторий
:data:location          — геолокация, разрешения, поиск городов
:feature:home           — главный экран
:feature:details        — почасовой/недельный детальный экран
:feature:settings       — настройки
:feature:widget         — Glance-виджет, receiver, worker
:benchmark              — Macrobenchmark (startup + scroll jank + baseline profile)
```

- Однонаправленный поток данных: UI → Intent → ViewModel → UseCase → Repository.
  Состояние экрана — один immutable `data class` в `StateFlow`.
- Domain-модели не знают ни про DTO, ни про Room-entity. Маппинг явный.
- Ошибки — типизированные (`sealed interface WeatherError`), не исключения
  наружу и не `null`.

## §4. Дизайн-система

### 4.1 Терминология

Названия «Material Android 17» не существует. Актуальная система —
**Material 3 Expressive**. Перед работой над §4 свериться с `m3.material.io`
и с исходниками `material3` в установленной версии; если в подключённой
версии часть Expressive API ещё экспериментальна — использовать её с
`@OptIn`, а не изобретать свою.

### 4.2 Жёсткие правила

- **Ни одного хардкод-цвета в коде фич.** Только `MaterialTheme.colorScheme.*`.
  Если нужен цвет, которого нет в схеме — расширь схему через
  `CompositionLocal` с собственными семантическими токенами
  (`WeatherPalette.fireGlow`, `WeatherPalette.frost`), выведенными из
  `colorScheme`, а не из воздуха.
- **Ни одного хардкод-`dp` для скруглений.** Только `MaterialTheme.shapes.*` и
  `MaterialShapes` (Expressive-формы: cookie, clover, pill и т.д.).
- **Ни одной анимации с произвольным `tween(300)`.** Только motion-схема
  Expressive: spring-спецификации из `MotionScheme` (`fastSpatial`,
  `defaultSpatial`, `slowSpatial`, `*Effects`). Пространственные перемещения —
  spatial-пружины, изменения цвета/альфы — effects-спеки.
- Типографика: `MaterialTheme.typography.*`. Emphasized-варианты для заголовков
  там, где Expressive их предусматривает.

### 4.3 Динамический цвет

- `dynamicLightColorScheme` / `dynamicDarkColorScheme` от обоев — по умолчанию.
- Поверх динамической схемы — **погодный тональный сдвиг**: тёплый сдвиг при
  ясной жаре, холодный при снеге, десатурация при тумане. Реализуй как
  трансформацию `ColorScheme` (сдвиг hue/chroma в OkLab или Hct), а не как
  подмену палитры. Сила сдвига настраивается и по умолчанию **умеренная** —
  динамический цвет пользователя должен остаться узнаваемым.
- Смена схемы — анимированная (`animateColorAsState` на каждом используемом
  токене через обёртку), а не мгновенная.
- Тёмная тема — полноценная, не инверсия. Ночные сцены (§6) выглядят в ней иначе.

### 4.4 Системная интеграция

- Edge-to-edge включён, `enableEdgeToEdge()`, вставки через `WindowInsets`.
  Ни одного захардкоженного отступа под статус-бар.
- Predictive back с кастомной анимацией предпросмотра.
- Splash Screen API с **бесшовной передачей** в первую анимацию приложения
  (`SplashScreen.setOnExitAnimationListener`) — иконка сплэша должна
  физически перетечь в элемент интерфейса, а не исчезнуть с фейдом.
- Поддержка `Settings.Global.ANIMATOR_DURATION_SCALE == 0` и системной
  настройки «уменьшить анимацию»: тяжёлые сцены отключаются, приложение
  остаётся полностью работоспособным.

## §5. Экраны и функциональность

**Home**
- Текущая температура, ощущается как, состояние, макс/мин.
- Почасовой прогноз — горизонтальный скролл с физикой и снэпом.
- 7 дней — вертикальный список с раскрывающимися строками.
- Плитки: ветер (роза направлений), влажность, UV, давление с трендом,
  видимость, точка росы, восход/закат с текущим положением солнца по дуге.
- Живая фоновая сцена (§6) под всем этим.

**Details** — детализация по дню: график температуры (Compose Canvas,
не библиотека), осадки, ветер по часам.

**Locations** — поиск города, список сохранённых, определение по геолокации,
drag-to-reorder, свайп-удаление с undo.

**Settings** — единицы (°C/°F, м/с/км/ч/mph, мм/дюймы), тема
(система/светлая/тёмная), интенсивность погодного тонального сдвига,
уровень анимаций (полный/сниженный/выкл), настройки виджета, частота
обновления, хаптика вкл/выкл.

**Состояния**: загрузка (скелетоны в стиле сцены, не серые прямоугольники),
ошибка сети с показом кэша и меткой «данные от HH:mm», отсутствие разрешения
на геолокацию (не блокирующее — ручной ввод города доступен), пустой список
городов.

## §6. Анимационный слой — погодные сцены

Главная часть проекта. Каждая сцена — это **интерьер уютной комнаты, из окна
которой видно погоду**. Не абстрактный градиент с иконками. Всё рисуется
процедурно: Compose `Canvas` / `drawWithCache` + AGSL `RuntimeShader`.
Никаких Lottie, никаких GIF, никаких видео, никаких растровых спрайтов —
приложение должно весить единицы мегабайт.

Общая структура сцены — слои с parallax по акселерометру/гироскопу
(`SensorManager`, `TYPE_GAME_ROTATION_VECTOR`, сглаживание low-pass фильтром,
амплитуда небольшая — 4–12 dp, иначе укачивает):

```
слой 0: дальний план за окном (небо, осадки)
слой 1: стекло (капли / изморозь / блики)
слой 2: рама окна, подоконник
слой 3: интерьер (камин / вентилятор / кружка)
слой 4: частицы переднего плана (пыль, искры)
слой 5: световой оверлей — общий цвет освещения сцены
```

Слой 5 **управляет цветом всего UI**: мерцание камина модулирует тёплую
подсветку карточек, вспышка молнии кратко высветляет весь экран. Связь
одностороняя: сцена → CompositionLocal с текущим ambient-освещением → UI.

### Сцены по WMO weather code

| Погода | Сцена |
|---|---|
| Дождь | Комната с камином. Процедурное пламя (кривые + шум + аддитивное смешивание), искры уходят вверх, тёплый мерцающий свет с неровным ритмом. За окном — струи дождя, на стекле AGSL-шейдер капель с преломлением фона; капли накапливаются, сливаются и стекают дорожками. Наклон устройства сдвигает траектории. |
| Гроза | То же + вспышки: белый оверлей 60–120 мс, синхронный сдвиг всех теней, затем раскат — хаптический паттерн (§9) с задержкой, пропорциональной «расстоянию» до грозы. Частота вспышек привязана к реальной интенсивности осадков. |
| Ясно, жарко (>27°C) | Комната с вентилятором: лопасти вращаются, скорость привязана к скорости ветра из API. Из окна — солнечные лучи (god rays), в них плавает пыль. Над подоконником AGSL heat-shimmer (искажение по синусоиде с шумом). Луч света смещается по комнате в зависимости от реального времени суток и азимута солнца. |
| Ясно, умеренно | Открытое окно, лёгкая занавеска колышется (spring-физика на цепочке точек), листва снаружи качается. |
| Облачно / пасмурно | Многослойные облака на процедурном фрактальном шуме, движутся с разной скоростью, мягкий рассеянный свет, приглушённая палитра. |
| Снег | Частицы снега с индивидуальным дрейфом. По краям стекла растёт изморозь (AGSL, Вороной-паттерн, прогресс роста анимируется). На подоконнике — кружка с поднимающимся паром (кривые + шум). |
| Туман | Слоистый носовой туман, дальние слои с прогрессивным блюром, силуэты едва проступают. Palette десатурирована. |
| Ветрено (>10 м/с) | Листья/лепестки пролетают через кадр по кривым Безье, занавеска отклоняется сильно, элементы UI слегка отклоняются в направлении ветра. |
| Ясная ночь | Звёзды с индивидуальным мерцанием, луна с **реальной фазой** (расчёт по дате), медленный дрейф. При долгом тапе по небу — созвездия соединяются линиями. |

Переходы между сценами — кроссфейд слоёв со staggered-задержкой (дальние
слои меняются первыми), не резкая подмена.

**Бюджет:** сцена целиком должна укладываться в 4 мс на кадр при 120 Гц.
Количество частиц адаптивное: снижается при `PowerManager.getCurrentThermalStatus()
>= THERMAL_STATUS_MODERATE`, при уровне батареи < 15% и в режиме экономии.

## §7. Интерактив и физика

- Все карточки-плитки лежат на «слоях глубины» и участвуют в parallax.
- **Drag & throw:** карточку можно потянуть и бросить. Скорость снимается
  `VelocityTracker`, полёт — `splineBasedDecay`, возврат на место —
  пружина с ощутимым, но не карикатурным overshoot.
- **Long-press** поднимает карточку (масштаб + тень + haptic), отпускание
  раскрывает её в детальный экран через `SharedTransitionLayout`
  (общий элемент, а не fade между экранами).
- **Pull-to-refresh** — не спиннер: тянешь облако вниз, оно растягивается,
  на пороге срабатывает haptic, отпускаешь — облако проливается дождём,
  который и есть индикатор загрузки.
- Скроллы — с overscroll-эффектом в духе Expressive (растяжение + деформация
  формы), не с системным по умолчанию.
- Интерактивные объекты сцены: по камину можно тапнуть — вспыхнет; по
  вентилятору — переключит скорость; по стеклу с каплями — протрёт дорожку
  (временное окно чистого стекла, зарастает обратно).
  Это не влияет на данные — это чистый тактильный отклик.

### Первый запуск

Отдельная intro-сцена: тёмная комната, пользователь «зажигает» свет тапом,
сцена собирается послойно staggered spring-анимацией, каждый появившийся
слой даёт haptic tick. Дальше — запрос геолокации в контексте, а не
системным диалогом в лоб. Проигрывается **один раз**, флаг в DataStore,
в настройках есть «показать заново».

### Обычный запуск

Splash → бесшовная передача → слои сцены появляются staggered (60–80 мс
между слоями), данные вплывают снизу с пружиной. Полная последовательность
≤ 700 мс, не должна ощущаться как задержка.

## §8. Виджет (Glance)

### 8.1 Честные ограничения — прочти до того, как писать код

Виджет — это `RemoteViews` в процессе лаунчера. **Произвольные анимации,
Canvas-рисование в реальном времени и шейдеры в виджете невозможны.**
Не пытайся их эмулировать и не пиши код, который делает вид, что это работает.

Что реально доступно:
- Смена содержимого при обновлении (по расписанию или по действию).
- `ViewFlipper` для покадрового переключения нескольких заранее готовых
  состояний.
- **Рабочий приём для визуала:** приложение рендерит сцену в `Bitmap`
  на своей стороне (тот же процедурный код, что и в §6, отрисованный в
  offscreen `Canvas`) и кладёт готовое изображение в виджет как фон.
  Так виджет получает уникальную графику, соответствующую текущей погоде и
  времени суток, без анимации. Это и есть целевое решение.

### 8.2 Требования

- Реализация на **Glance** (`GlanceAppWidget` + `GlanceAppWidgetReceiver`),
  не на голых `RemoteViews`.
- **Динамический цвет автоматически:** `GlanceTheme(GlanceTheme.colors)` —
  берёт системную динамическую палитру. Виджет обязан менять цвета при смене
  обоев/темы без ручного вмешательства, включая мгновенную реакцию на смену
  светлой/тёмной темы.
- Размеры через `SizeMode.Responsive` с явным набором:
  - 2×2 — иконка, температура, город;
  - 4×2 — + макс/мин, ощущается как, состояние, отрендеренный фон сцены;
  - 4×4 — + почасовая полоса на 6 часов и 3 дня прогноза.
  В `appwidget-provider` XML указать `targetCellWidth`/`targetCellHeight`,
  `maxResizeWidth`/`Height`, `description`, `previewLayout`.
- Обновление: `WorkManager` с адаптивным интервалом (чаще при активной
  смене погоды, реже ночью), плюс `BOOT_COMPLETED`, плюс `ACTION_TIME_SET` /
  `ACTION_TIMEZONE_CHANGED`. Минимальный интервал уважает
  ограничения Doze — не пытайся обновлять чаще, чем система позволит.
- Тап по виджету открывает приложение на соответствующем городе
  (`actionStartActivity` с deep link).
- Отдельная кнопка обновления с немедленным запуском воркера.
- Конфигурационная активность при добавлении: выбор города, размера
  информации, прозрачности фона.
- Состояния: нет данных, нет сети, нет разрешений — все три оформлены,
  ни одного пустого виджета.

## §9. Хаптика

Pixel 10 Pro XL имеет качественный вибромотор с поддержкой composition
primitives — используй это, а не `vibrate(50)`.

- Базовый слой: Compose `LocalHapticFeedback` для стандартных жестов.
- Богатый слой: `VibratorManager` → `VibrationEffect.startComposition()` с
  примитивами (`PRIMITIVE_TICK`, `PRIMITIVE_CLICK`, `PRIMITIVE_THUD`,
  `PRIMITIVE_SPIN`, `PRIMITIVE_QUICK_RISE`, `PRIMITIVE_LOW_TICK`),
  собранными в паттерны:
  - раскат грома — `THUD` с нарастающим scale и затуханием;
  - «зажигание» камина — `QUICK_RISE` → `TICK`;
  - снэп почасового скролла — `LOW_TICK` на каждый элемент;
  - порог pull-to-refresh — `CLICK`;
  - подъём карточки при long-press — `TICK` со scale 0.4.
- **Обязательно** проверять `vibrator.areAllPrimitivesSupported(...)` и
  деградировать до простого эффекта, а не падать.
- Уважать системную настройку тактильной отдачи и переключатель в §5.
- Не более одного хаптик-события на жест. Перебор хуже отсутствия.

## §10. Производительность

- Целевой бюджет кадра: **8.3 мс** (120 Гц). Ни одного дропа при скролле
  главного экрана с активной сценой.
- R8 full mode + ресурс-шринкинг в release.
- **Baseline Profile** генерируется через `:benchmark` модуль и включается
  в сборку. Не «добавлен пустой файл» — реально сгенерированный.
- Macrobenchmark: cold/warm startup, frame timing при скролле. Результаты —
  в итоговый README.
- Профилировать композицию: минимум рекомпозиций, стабильные классы,
  `derivedStateOf`, ключи в списках, `Modifier.drawWithCache` для всего,
  что можно закешировать между кадрами. Анимационные значения читать
  лямбдами (`graphicsLayer { }`), а не напрямую в composable-скоупе.
- Все анимации сцены останавливаются при уходе приложения в фон
  (`repeatOnLifecycle(STARTED)`). Проверить, что в фоне нет ни одного
  активного `InfiniteTransition`.
- Сеть: кэш с TTL, `stale-while-revalidate`, никаких запросов при каждом
  открытии экрана.

## §11. Фазы работы

Каждая фаза заканчивается **зелёной сборкой**. Если устройство/эмулятор
доступны — установка, запуск и скриншот (`adb exec-out screencap -p`),
который ты сам смотришь и оцениваешь. После каждой фазы — короткий отчёт
и остановка на подтверждение.

## §12. Сборка и поставка APK

- Сгенерировать keystore через `keytool` (алиас, пароли — в
  `keystore.properties`, файл в `.gitignore`, значения продублировать в
  итоговом отчёте, чтобы сборку можно было воспроизвести).
- `signingConfigs.release` читает из `keystore.properties`, а не хардкодит.
- Собрать **универсальный** APK (без ABI/density splits) — он должен
  ставиться напрямую: `./gradlew :app:assembleRelease`.
- Положить в `dist/` с осмысленным именем: `weather-<version>-<gitsha>.apk`.
- **Верифицировать и показать вывод:**
  - `apksigner verify --verbose --print-certs <apk>`
  - `aapt2 dump badging <apk>` — проверить package, versionCode,
    minSdk/targetSdk, объявленный виджет-receiver, permissions;
  - размер APK;
  - если устройство есть — `adb install -r` и запуск.
- README в корне: как собрать, как поставить, какие разрешения нужны,
  что реализовано, **что не реализовано и почему**, результаты бенчмарков.

## §13. Definition of Done

- [ ] `./gradlew build` зелёный (сборка + lint + тесты)
- [ ] Android Lint: 0 errors, warnings разобраны или явно подавлены с
      комментарием почему
- [ ] Подписанный release-APK в `dist/`, верификация приложена
- [ ] Приложение установлено и запущено, скриншоты всех экранов и всех
      погодных сцен приложены
- [ ] Виджет добавлен на домашний экран в трёх размерах, скриншоты приложены
- [ ] Проверена смена обоев → цвета виджета и приложения изменились
- [ ] Проверена смена светлой/тёмной темы
- [ ] Проверен режим самолёта → показ кэша с меткой времени
- [ ] Проверен отказ в разрешении геолокации → приложение работает
- [ ] `dumpsys gfxinfo` при скролле главного экрана: janky frames < 1%
- [ ] README заполнен, включая раздел о нереализованном

## §14. Запреты

1. Не выдумывать API, классы, методы и параметры. Не уверен — проверь
   компиляцией или документацией.
2. Не выдумывать версии зависимостей. Не резолвится — найди настоящую.
3. Не подавлять ошибки компилятора кастами, `!!`, `@Suppress` и
   `@OptIn` наугад. `@OptIn` только для реально экспериментальных API,
   осознанно.
4. Никаких `TODO`, заглушек, пустых `catch {}`, захардкоженных фейковых
   данных в коде, который идёт в release.
5. Не сокращать спеку молча. Не сделал пункт — напиши, что не сделал.
6. Не заявлять о готовности того, что не проверено запуском.
7. Не добавлять зависимости, которых нет в §2, без явного согласования.
8. Не писать анимации в виджете — см. §8.1.
9. Комментарии и идентификаторы в коде — на английском. Отчёты мне — на
   русском.
