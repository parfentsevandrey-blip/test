# Synapse — локальные нейросети на Mac

Четвёртое приложение каталога (см. [манифест](../MANIFESTO.md)). Это аналог Ollama и LM Studio для тех, кто
никогда не открывал терминал. При первом запуске Synapse изучает железо Mac, сам подбирает модели, которые будут на нём
быстро работать, и ставит их в один клик. Модели работают прямо на компьютере, и переписка никуда не уходит.

Интерфейс сделан на Swift 6, SwiftUI и **Liquid Glass**. Модели запускает открытый движок
[llama.cpp](https://github.com/ggml-org/llama.cpp) (MIT). Это единственное исключение из правила «без сторонних
библиотек»: движок собирается **из исходников** вместе с приложением (Metal + Accelerate, статически). Всё остальное
написано с нуля:
- анализ железа;
- советник;
- каталог;
- загрузчик;
- лента;
- чат;
- сервер API.

## Что умеет

| | |
|---|---|
| **Анализ Mac** | Чип, производительные и эффективные ядра, ядра видеоядра (IORegistry `gpu-core-count`), объединённая память, пропускная способность памяти по таблицам Apple, бюджет памяти видеоядра (`MTLDevice.recommendedMaxWorkingSetSize`), свободное место. |
| **Подбор моделей** | Роли «Сбалансированная», «Самая быстрая», «Максимум ума» и «Для кода». Для каждой модели считается, сколько памяти займут веса, KV-кэш и служебные данные, и какой будет скорость генерации (пропускная способность ÷ активные веса). У MoE-моделей учитываются только активные эксперты. |
| **Обновления без потерь** | Модели, чаты и настройки хранятся отдельно от программы (`~/Library/Application Support/Synapse`), поэтому новая версия поверх старой их не трогает. Список моделей читается по одной записи и хранится в двух копиях; модели, которые лежат в папке, но не попали в список, находятся и восстанавливаются сами. |
| **Для картинок** | Вкладка каталога с моделями, которым можно показать изображение: что можно спросить, как приложить картинку; сверху — те, что удобно работают на этом Mac. Наличие проектора зрения проверяется по списку файлов на Hugging Face. |
| **Тихие и лёгкие** | Вкладка каталога рядом с «Выжать максимум»: модели, которые Mac даже не заметит — не больше четверти памяти, не больше ~5 млрд параметров на токен и не медленнее 35 ток/с. Ответ в пару абзацев пишется за секунды, видеоядро не успевает нагреться, вентилятор не включается. |
| **Выжать максимум** | Отдельная вкладка каталога: модели классом выше рекомендованной на каждый день, сжатые до 2–4 бит, чтобы поместиться в память именно этого Mac. Для каждой выбирается самое мягкое сжатие, с которым она запустится (не ниже ~2 бит и 3 ток/с), а контекст и его память (KV-кэш в 8 битах) ужимаются автоматически. Кнопка «Отдать видеоядру больше памяти» поднимает предел `iogpu.wired_limit_mb` до перезагрузки, оставляя системе не меньше 4 ГБ. |
| **Предупреждения** | Вердикты «Летает», «Быстро», «Комфортно», «Медленно», «На пределе», «Не поместится», «Нет места на диске», каждый с объяснением человеческими словами. Если модель слишком велика, перед загрузкой в память появится отдельное предупреждение. |
| **Каталог** | Живой список GGUF-сборок от доверенных сборщиков (unsloth, ggml-org, LM Studio, bartowski) и лабораторий, плюс поиск по всему Hugging Face. У каждой модели видны размер, параметры, лицензия, все варианты сжатия с оценкой качества и вердикт для этого Mac. Модели, архитектуру которых встроенный движок ещё не знает, помечены. |
| **Установка в один клик** | Файлы и их SHA-256 берутся из API Hugging Face. Загрузка докачивается после обрыва (HTTP Range), SHA-256 считается на лету, автоматически повторяется после сбоев, не даёт Mac уснуть и поддерживает модели из нескольких частей. Прогресс виден на иконке в Dock. |
| **Лента** | Новые модели лабораторий (Qwen, Google, Meta, Mistral, DeepSeek, NVIDIA, OpenAI…), свежие готовые сборки и модификации, выпуски llama.cpp с GitHub. Лента обновляется в фоне каждые два часа, показывает непрочитанное и присылает уведомления о новых моделях, которые подойдут этому Mac. |
| **Чат** | Ответ появляется по мере генерации и оформляется в Markdown, блоки кода копируются одной кнопкой. Размышления модели сворачиваются в отдельный блок, режим размышлений можно включать и выключать. Есть остановка и повтор ответа, системная инструкция для каждого чата и счётчик ток/с. История хранится на диске. Пока модель пишет, окно стоит на месте: вопрос поднимается к верху, ответ пишется под ним, листать можно свободно; кнопка «Ответ продолжается ниже» возвращает к концу. |
| **Защита от зацикливания** | Галочка в Настройках → Ответы, включена по умолчанию. В размышлениях работает штраф DRY из llama.cpp за повтор уже написанных цепочек. Если модель всё же пошла по кругу (точный повтор куска или одна и та же фраза снова и снова), движок сам дописывает конец размышлений в формате модели (`</think>`, `<channel|>` у Gemma 4, канал final у gpt-oss), и модель отвечает по тому, что уже поняла. Ответ, ушедший в круг, останавливается. Отдельно можно задать предел размышлений: 1–8 тысяч токенов. |
| **Настройки** | Каждый параметр объяснён простыми словами. Ответы: готовые наборы «Точно / Сбалансированно / Творчески», температура, длина, размышления, Min-P, Top-P, Top-K, штраф за повторы, повторяемость. Память: контекст с ценой в гигабайтах для текущей модели, сжатие памяти контекста, видеоядро, предел памяти видеоядра. Чат: прокрутка за ответом. |
| **Описания моделей** | У каждой модели в карточке — для чего создана, в чём сильна, где слабее, когда выбрать её, факты. Для отобранных — по официальным карточкам моделей, для остальных — по семейству. |
| **Вставка картинок** | ⌘V в чате: скриншот, скопированное фото или файл-изображение прикладываются к сообщению (в любой раскладке). Если в буфере текст — вставляется текст. |
| **Зрение** | Модели Gemma 4, Qwen3.5, Qwen3.6, Qwen3.8, Ministral 3 и Devstral 2 понимают изображения: фото, скриншоты, схемы, документы. Проектор зрения (`mmproj`) скачивается вместе с моделью и проверяется по SHA-256; к уже установленной модели его можно докачать кнопкой «Добавить зрение». Картинку прикладывают скрепкой или перетаскивают в окно. Изображение декодирует ImageIO (JPEG, PNG, HEIC, WebP…) с поворотом по EXIF, затем его кодирует `libmtmd` из llama.cpp. |
| **API** | Совместим с Ollama (`/api/tags`, `/api/chat`, `/api/generate`, `/api/show`, `/api/ps`; картинки — в поле `images`) и OpenAI (`/v1/models` и `/v1/chat/completions`, в том числе поток SSE; картинки — частями `image_url` с data-URL). Слушает только localhost. Включается в Настройках. |

## Как устроено

```
Synapse/
  ENGINE_VERSION            — версия llama.cpp (b11800 — последний выпуск на момент сборки)
  scripts/build-engine.sh   — llama.cpp из исходников → Vendor/llama (статический libSynapseEngine.a + заголовки + список архитектур)
  scripts/build.sh          — движок + приложение → dist/Synapse.app и Synapse.dmg
  Sources/CLlama            — module.modulemap для C API llama.h
  Sources/Synapse/Core      — Hardware, Advisor, Quant, Catalog, HubClient, Fetcher, Library, Feed, Engine, ChatFormat, APIServer
  Sources/Synapse/Views     — онбординг, «Для этого Mac», каталог, лента, мои модели, чат, нейросфера
```

- **Движок** (`Engine.swift`) — обёртка над C API llama.cpp, которая живёт на собственной последовательной очереди.
  - Начало диалога, уже лежащее в KV-кэше, переиспользуется (`llama_memory_seq_rm`). Рекуррентные и гибридные модели этого не умеют, у них кэш сбрасывается.
  - Генерацию можно остановить посреди обработки промпта через `abort_callback`.
  - Многобайтовые символы собираются по байтам.
  - На виртуальной машине модель считается на процессоре; если не справился Metal, тоже.
  - Запрос с картинками идёт через `libmtmd`: `mtmd_tokenize` режет промпт на текст и изображения, `mtmd_helper_eval_chunks` кодирует картинки проектором и учитывает позиции M-RoPE и некаузальное внимание Gemma.
- **Форматы диалога** (`ChatFormat.swift`).
  - Встроенный `llama_chat_apply_template` распознаёт шаблоны эвристически, без Jinja. Поэтому для популярных семейств формат собирается вручную:
    - ChatML с `<think>` для Qwen3/3.5+ (режим размышлений включается и выключается);
    - Gemma 4 с `<|turn>`, которого во встроенных шаблонах нет;
    - Harmony для gpt-oss.
  - Остальные модели идут через шаблон из GGUF.
  - Ответ раскладывается на размышления и сам текст, служебные маркеры убираются.
- **Источники данных** — открытые API без ключей:
  - `huggingface.co/api/models?filter=gguf&expand[]=gguf` — параметры, архитектура и контекст;
  - `/api/models/{repo}/tree/main?recursive=true` — файлы с размерами и SHA-256;
  - `/{repo}/resolve/main/{file}` — сами файлы;
  - `api.github.com/repos/ggml-org/llama.cpp/releases` — выпуски движка.

  Ответы кэшируются на диске, поэтому без интернета каталог и лента остаются доступны.

## Сборка

Нужны macOS 26 на Apple Silicon, Xcode 26 и CMake (`brew install cmake`).

```sh
cd Synapse
./scripts/build.sh            # собирает llama.cpp (один раз), приложение, DMG
open dist/Synapse.app
```

## Проверки в CI

`.github/workflows/synapse-macos.yml` собирает движок (с кэшем по версии), приложение и DMG, а затем запускает проверки:

- `--selftest-logic` — без сети:
  - разбор квантований из имён файлов и группировка частей;
  - разбор ответов всех форматов и сборка UTF-8 по байтам;
  - шаблоны Gemma 4 и Qwen, разбор HTTP;
  - подбор моделей для пяти разных Mac, от Air M1 8 ГБ до Studio M3 Ultra 512 ГБ;
  - «Выжать максимум» для M4 Pro 24 ГБ: модели классом выше рекомендованной, план загрузки тесной модели, предел видеоядра.
- `--selftest-hub` — живой Hugging Face:
  - свежие модели;
  - файлы с SHA-256;
  - **все отобранные модели действительно существуют и имеют GGUF**;
  - лента.
- `--selftest-engine` — настоящая модель Qwen3.5 0.8B:
  - загрузка прерывается на 40%, докачивается и проверяется по SHA-256;
  - ответ «Paris»;
  - второй вопрос в том же диалоге — «Berlin»;
  - русский язык;
  - режим размышлений;
  - остановка посреди ответа;
  - API Ollama и OpenAI;
  - зрение: проектор скачивается и проверяется, модель называет цвет круга и квадрата на тестовых картинках, после картинки снова работает обычный текст, картинка через API OpenAI.
- `--selftest-render` и `--demo-ui <экран>` — картинки и скриншоты настоящих окон, включая чат с живым ответом модели и вопрос про картинку.
