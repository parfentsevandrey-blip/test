# Как наш.дом.рф и cian.ru отдают данные о ЖК и квартирах

Исследование и тестовый прогон от 2026-10-19. Инструменты: rea 6.7.0 (`capture-browser-scenario` в режиме connect, `analyze-web-bundle`, `analyze-javascript-application`), Scrapling 0.5, curl_cffi. Сырые захваты rea лежат вне репозитория; выводы и образцы данных — здесь.

## Коротко

| | cian.ru | наш.дом.рф |
|---|---|---|
| Защита | Собственный WAF (`cian_waf_block`): режет запросы без браузерного TLS-отпечатка | Servicepipe: Chrome/Firefox получают JS-челлендж и капчу; Safari-отпечаток к JSON-API пропускается |
| Нужен ли браузер | Нет: curl_cffi `impersonate="chrome"` | Нет: curl_cffi `impersonate="safari18_0"` |
| Где данные | JSON-API поиска + SSR-состояние в HTML (`window._cianConfig[...]`) | Открытые JSON-методы `/сервисы/api/kn/*` и `/portal-kn/api/*` |
| Единица данных | Объявление (квартира) и ЖК | Объект строительства (корпус, `objId`), характеристики, квартиры в продаже и вся квартирография |
| Тестовый прогон | 50 ЖК, карточка ЖК, ЖК «Деснаречье» целиком: 1725 квартир | Вся Москва: 590 объектов с характеристиками и 14 195 квартир в продаже за 3,4 мин в 4 потока |

## cian.ru

### Как устроена выдача

1. **WAF.** `curl` с обычным User-Agent получает 403 «Обнаружен подозрительный трафик» (`cian_waf_block`). Тот же запрос через curl_cffi с отпечатком Chrome получает 200. Значит, WAF смотрит на TLS/HTTP2-отпечаток, а не на IP: из американского датацентра всё работает без cookie и без браузера.
2. **Страница поиска** (`/cat.php?...`, около 3,3 МБ HTML) рендерится на сервере. Всё состояние лежит в `window._cianConfig['frontend-serp']`, ключ `initialState` → `results.offers` (28 объявлений), `results.totalOffers`, `results.jsonQuery`.
3. **JSON-API поиска**, найденный через захват сети rea, затем проверенный напрямую:
   `POST https://api.cian.ru/search-offers/v2/search-offers-desktop/` с телом `{"jsonQuery": {...}}`.
   Ответ: `data.offersSerialized` (28 полных объявлений), `data.offerCount`, `data.jsonQuery`, `data.queryString`. Это тот же объект, что лежит в SSR.
   Запрос, который страница делает сама (`/search-offers/v3/get-infinite-search-result-desktop/`), возвращает только ID рекомендаций ML-ленты без данных — он не нужен.
4. **Формат `jsonQuery`** (проверено):
   ```json
   {"_type": "flatsale", "engine_version": {"type": "term", "value": 2},
    "region": {"type": "terms", "value": [1]},
    "building_status": {"type": "term", "value": 2},
    "geo": {"type": "geo", "value": [{"type": "newobject", "id": 4025502}]},
    "room": {"type": "terms", "value": [1]},
    "price": {"type": "range", "value": {"gte": 10000000, "lte": 12000000}},
    "page": {"type": "term", "value": 2}}
   ```
   `building_status=2` — новостройки. `geo/newobject` — квартиры конкретного ЖК. Незнакомые ключи сервер молча выбрасывает (так ведёт себя, например, `newobject: {...}`), поэтому сверяйте `data.jsonQuery` в ответе. Правильный `jsonQuery` для любого фильтра проще всего взять из SSR страницы `cat.php` с этим фильтром.
5. **Лимит и ловушки выдачи** (уточнено стресс-тестом, см. `docs/stress-test.md`):
   - не больше 54 страниц × 28 = 1512 объявлений на запрос;
   - **без явной сортировки (ML-ранжирование) выдача обрывается примерно на 470 объявлениях**, дальше пустые страницы. Лечится сортировкой `"sort": {"type": "term", "value": "price_object_order"}`, сборщик ставит её всегда;
   - **на уровне региона и района разные квартиры одного ЖК с похожей планировкой сворачиваются в одну карточку** («Ещё N таких же квартир в этом ЖК», `similar.count`, раскрывается через `multi_id`). Листается только `aggregatedCount`: по новостройкам Москвы это 17,8 тыс. карточек из 57,2 тыс. объявлений. Это **не дубли**: в проверенной группе из 26 объявлений были 22 разные комбинации этажа, площади и корпуса, и у всех разные цены;
   - **внутри фильтра по ЖК (`geo`/`newobject`) свёртки нет:** `aggregatedCount` = `offerCount`. Поэтому полный сбор идёт по ЖК, а большие ЖК (больше 1512) режутся по цене (`jk_flats`).
6. **Каталог ЖК:** JSON-API `POST https://api.cian.ru/newbuilding-search/v1/get-newbuildings-for-serp/` с телом `{"jsonQuery": {"_type": "newobjectsale", "engine_version": {...}, "region": {...}}, "uri": "/newobjects/list/", "subdomain": "www", "offset": N, "count": 25}` (найден в бандле `newbuilding-search-frontend`). Запасной путь — HTML `/newobjects/list/?...&p=N`, SSR `newbuilding-search-frontend` → `initialState.offersData.newbuildings` (25 на страницу, в Москве 623 ЖК).
7. **Карточка ЖК** (`https://zhk-<slug>.cian.ru/`): SSR `newbuilding-card-desktop-fichering-frontend` → `initialState.newbuilding`. Внутри:
   - корпуса и сроки по очередям (`houses`, `housesByTurn`);
   - застройщики (`builders`);
   - характеристики (`specifications`, `specificationsDetailed`: парковка, безопасность…);
   - ход строительства с фото по месяцам (`constructionProgress`);
   - квартирография по комнатам и корпусам (`offers.data`, `layoutsInfo`);
   - отзывы, банки;
   - блок `reliability` «Проверено наш.дом.рф»: реестр проблемных объектов, банкротство застройщика, эскроу, фото стройки, дата проектной декларации.

### Какие поля есть у квартиры

Цена и тип продажи (ФЗ-214 и т. п.), комнаты, площади (общая, жилая, кухня), этаж и этажность, отделка, материал, срок сдачи (год, квартал, сдан ли). Дальше: ЖК (id, название, URL), корпус и секция, продавец (застройщик или агент), адрес, координаты, метро со временем, фото и планировка, дата публикации, описание. Заполненность в прогоне: ключевые поля 85–100%, площадь кухни 43%, секция 70%.

Нормализованная запись — `flat_row()` в `collectors/cian.py`; сырые объявления — флаг `--raw` (около 150 полей).

### Рекомендуемая стратегия полного сбора

1. Одной командой: `cian.py flats --region 1 --by-jk --workers 2`. Каталог ЖК через API, затем все квартиры каждого ЖК без свёртки, с явной сортировкой, нарезкой по цене для ЖК больше 1512 и дедупликацией.
2. Карточки ЖК — `cian.py jk-card` (корпуса, сроки, надёжность), один запрос на ЖК.
3. Режим `--all` по региону собирает только «лицевые» квартиры свёрнутых групп (около 1/3). Для полноты не годится, только для быстрой оценки рынка.

Объём для Москвы: около 57 тыс. объявлений / 28 ≈ 2050 запросов + 25 страниц каталога. Стресс-тест показал, что на таком объёме за один заход отпечаток Chrome с одного IP уходит в капчу. Растягивайте сбор на несколько часов (не больше ~0,5–1 запроса/с в среднем) или делите по округам и дням.

Ограничения: держать паузы и повторы при 403/429 (в сборщике есть), не собирать телефоны (персональные данные агентов), учесть пользовательское соглашение Циана — оно запрещает автоматизированный сбор. Для коммерческого использования нужна юридическая оценка или партнёрский доступ.

## наш.дом.рф

### Как устроена защита (и где была моя ошибка)

Первая версия этого отчёта утверждала, что из облака сайт недоступен «из-за IP». Это неверно. Я перебирал только браузеры (Chromium в разных режимах), а Servicepipe решает по TLS-отпечатку клиента:

| Отпечаток (curl_cffi) | `/сервисы/api/kn/object` | HTML-страницы |
|---|---|---|
| `chrome`, `chrome120`, `edge`, `chrome_android`, `firefox133`, `tor145` | 403 «Доступ заблокирован» | JS-челлендж → капча |
| `safari`, `safari17_0`, `safari18_0`, `safari_ios` | **200 JSON** | JS-челлендж |

Дальше разные пути закрыты по-разному. Это видно по ответу: 404 от самого сервера (Express/Java) значит, что запрос прошёл через Servicepipe, а 403-страница — что его заблокировал Servicepipe.
- `/сервисы/api/*`, `/portal-kn/api/*`, `/api/*` доходят до сервера.
- Точечно закрыт только `/сервисы/api/object/*` — карточка объекта, самый популярный у парсеров путь.
- HTML-страницы под `/сервисы/*` отдают челлендж, но страницы 404 (например, `/сервисы/asset-manifest.json`) возвращают полный HTML-каркас Next.js-приложения со ссылками на бандлы.

`robots.txt` разрешает каталог. Закрыты только PDF (`/api/ext/file/*.pdf`, `/files/*.pdf`), `*/auth/*`, `/lkz/` и раздел «продажи». Sitemap: `/portal-sitemap/api/sitemap/root.xml`.

### Как нашли API (rea)

1. Из 404-каркаса и `_buildManifest.js` скачаны все 88 чанков приложения `/сервисы/_next` (19 МБ, 34 страницы: `objectList`, `newBuildingCard`, `houseCard`, `flatsList`, `apartment`, `builderCard`…).
2. `rea analyze-javascript-application` по каталогу: 369 кандидатов в эндпоинты, 152 сетевых вызова с методом (`call:x.get`/`post`).
3. Базовые URL клиентов axios взяты из модуля конфигурации (`POss`): `/сервисы/api`, `/portal-kn/api`, `/portal-kn/api/sales`, `/portal-igd/api`, `/portal-eiszhs`, `/portal-erz-kn-files/api`, `/portal-sitemap`. Клиенты собраны в модуле `Nlzp` (`kn` = `/сервисы/api/kn`, `sales` = `/portal-kn/api/sales`…).
4. Каждый маршрут проверен живым запросом.

### Открытые методы (проверено)

| Метод | Что отдаёт | Лимиты |
|---|---|---|
| `GET /сервисы/api/kn/object?offset&limit&objStatus&place&sortField&sortType` | Список объектов: `objId`, `hobjId`, застройщик (название, группа, **ИНН**), адрес, координаты, этажность, число квартир, жилая площадь, срок сдачи, эскроу, проблемность, номер РПД и `pdId`, рендер, AI-описание | `limit` ≤ 50. `objStatus`: 0 строящиеся (13 408), 1 проблемные (54), 2 сданные (38 531). `place` = код региона (77 — Москва, 590 объектов). Работает и `objId=` |
| `GET /сервисы/api/kn/compare?objectId=…&diff=false` | Карточка объекта: **название ЖК**, класс, материал стен, отделка, подъезды, квартир на этаже, парковка, **средняя цена м², % продано**, метро со временем, энергоэффективность, дата передачи ключей, тип гарантии, лифты, инфраструктура | до 10 `objectId` за запрос |
| `POST /portal-kn/api/sales/portal/flats` `{"externalIds":[objId],"sort":"area","order":"asc","limit":100,"offset":0}` | **Квартиры в продаже**: номер, комнаты, студия, площади (общая, жилая, кухня), этаж и этажность, подъезд, **цена и цена м²**, дата изменения цены, отделка, планировки (`/api/ext/file/<attachmentId>`) | `limit` ≤ 100. Только у объектов, где застройщик публикует продажи на наш.дом.рф (в прогоне 3 из 30 московских) |
| `GET /portal-kn/api/kn/objects/<objId>/flats?limit&offset` | **Вся квартирография дома**, включая непродаваемые (`status`/`price` = null): тип, комнаты, площадь, этаж, подъезд | `limit` ≤ 100, есть `total` |
| `GET /portal-kn/api/kn/objects/near?objId=` | Соседние ЖК: название, метро, минимальная цена, квартирография по типам (`flatGroups`) | — |
| `GET /portal-kn/api/kn/places?search=` | Регионы и города с `regionCd` | — |
| `GET /api/ext/file/<id>?type=png` | Рендеры и планировки | PDF закрыт robots.txt |
| `GET /сервисы/api/kn/object/map?objStatus=` | Все объекты с координатами (1,9 МБ) | — |

Закрыто Servicepipe: `/сервисы/api/object/<id>` и его подпути (`/infrastructure`, `/green-house`, документы). Почти всё оттуда, кроме документов, перекрывается методами `kn/compare` и `kn/object`.

Официальная альтернатива — коммерческий API ЕИСЖС (бизнес.дом.рф): шесть групп методов, проектные декларации в машиночитаемом виде, OAuth 2.0, подписка для юрлиц. Платформа данных строительства (платформа.дом.рф) даёт только агрегированные датасеты, экспорт закрыт Yandex SmartCaptcha.

### Стратегия сбора

1. Список: `domrf.py objects --status 0 [--region N] --details`. По России: 269 запросов списка + 1341 запрос `compare`.
2. Квартиры в продаже: `domrf.py flats --from objects.jsonl`. Пустой ответ (`[]`) значит, что продажи не опубликованы; это быстро.
3. Полная квартирография: `domrf.py flats --units` (по 100 на запрос).
4. Паузы 0,6–1,2 с, `--workers 4` (стресс-тест: 8 потоков / 12 запросов/с без единого блока). При 403 или челлендже — новая сессия и экспоненциальная пауза. Не ходить в `/сервисы/api/object/*`: блок от него может распространиться на всё соединение (так я однажды получил 403 на всё подряд в одной сессии).

## Связь двух источников

У Циана свои ID ЖК, у наш.дом.рф — `objId` (корпус), название ЖК (`objCommercNm`), ИНН застройщика и координаты. Сопоставлять стоит так: координаты (расстояние меньше ~150 м) + нормализованное название ЖК + название застройщика; корпуса — по сроку сдачи и этажности. Квартиры наш.дом.рф (номер, этаж, подъезд, площадь) можно сопоставлять с объявлениями Циана по ЖК, этажу и площади (±0,2 м²).

## Тестовый прогон (2026-10-19, Москва)

| Команда | Результат |
|---|---|
| `cian.py jk --region 1 --pages 2` | 50 ЖК из 623 |
| `cian.py jk-card --url https://zhk-soyuz-i.cian.ru/` | карточка ЖК «СОЮЗ»: 6 корпусов, очереди, ход стройки, надёжность |
| `cian.py flats --newobject 4025502` | 118 квартир ЖК «СОЮЗ» (`offerCount` = 119) |
| `cian.py flats --region 1 --new --pages 2` | 56 квартир из 57 192 |
| `search_all` с порогом 56 (проверка нарезки) | 4 ценовых среза, 117 уникальных квартир, дублей нет |
| `domrf.py objects --status 0 --region 77 --pages 2 --details` | 100 из 590 строящихся объектов Москвы с характеристиками |
| `domrf.py flats --from … --max-objects 30` | 794 квартиры в продаже у 3 объектов из 30 |
| `domrf.py flats --obj-id 73741 --units` | 846 строк квартирографии «Деснаречье квартал Парк» (426 в продаже) |

Первые четыре команды Циана вместе заняли 36 с (паузы 1,5–3 с), обе команды наш.дом.рф — 67 с (паузы 0,6–1,2 с).

Файлы: `samples/2026-10-19/`.

`offerCount` иногда на 1–2 больше фактической выдачи: объявления снимаются и добавляются между запросами.
