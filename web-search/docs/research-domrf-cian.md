# Как наш.дом.рф и cian.ru отдают данные о ЖК и квартирах

Исследование и тестовый прогон от 2026-10-19. Инструменты: rea 6.7.0 (`capture-browser-scenario` в режиме connect, `analyze-web-bundle`), Scrapling 0.5 (`Fetcher` с TLS-имперсонацией, `StealthySession`), curl_cffi. Сырые захваты rea лежат вне репозитория; выводы и образцы данных — здесь.

## Коротко

| | cian.ru | наш.дом.рф |
|---|---|---|
| Защита | Собственный WAF (`cian_waf_block`): режет запросы без браузерного TLS-отпечатка | Servicepipe: JS-челлендж, затем слайдер-капча |
| Пускает ли из облака (US, Google Cloud) | Да, при `impersonate="chrome"`; браузер не нужен | Нет. Капча при любой конфигурации браузера |
| Где данные | JSON-API поиска + SSR-состояние в HTML (`window._cianConfig[...]`) | SPA поверх JSON-API `/сервисы/api/...` (путь из открытых источников, вживую не подтверждён) |
| Самый эффективный способ | HTTP-запросы к API, без браузера: ~28 квартир за запрос | Российский IP + браузер для челленджа + запросы к API из контекста страницы; либо коммерческий API ЕИСЖС |
| Тестовый прогон | Работает: 50 ЖК, карточка ЖК, 174 квартиры за 36 с | Отсюда невозможен; сборщик готов к запуску с российского IP |

## cian.ru

### Как устроена выдача

1. **WAF.** `curl` с обычным User-Agent получает 403 «Обнаружен подозрительный трафик» (`cian_waf_block`). Тот же запрос через curl_cffi с отпечатком Chrome получает 200. Значит, WAF смотрит на TLS/HTTP2-отпечаток, а не на IP: из американского датацентра всё работает без cookie и без браузера.
2. **Страница поиска** (`/cat.php?...`, около 3,3 МБ HTML) рендерится на сервере. Всё состояние лежит в `window._cianConfig['frontend-serp']`, ключ `initialState` → `results.offers` (28 объявлений), `results.totalOffers`, `results.jsonQuery`.
3. **JSON-API поиска**, найденный через захват сети rea, затем проверенный напрямую:
   `POST https://api.cian.ru/search-offers/v2/search-offers-desktop/` с телом `{"jsonQuery": {...}}`.
   Ответ: `data.offersSerialized` (28 полных объявлений), `data.offerCount`, `data.jsonQuery`, `data.queryString`. Это тот же объект, что лежит в SSR.
   Запрос, который страница делает сама (`/search-offers/v3/get-infinite-search-result-desktop/`), возвращает только ID рекомендаций ML-ленты без данных — он не нужен.
4. **Формат `jsonQuery`** (проверено):
   ```json
   {"_type": "flatsale", "engine_version": {"type": "term", "value": 2},
    "region": {"type": "terms", "value": [1]},
    "building_status": {"type": "term", "value": 2},
    "geo": {"type": "geo", "value": [{"type": "newobject", "id": 4025502}]},
    "room": {"type": "terms", "value": [1]},
    "price": {"type": "range", "value": {"gte": 10000000, "lte": 12000000}},
    "page": {"type": "term", "value": 2}}
   ```
   `building_status=2` — новостройки. `geo/newobject` — квартиры конкретного ЖК. Незнакомые ключи сервер молча выбрасывает (так ведёт себя, например, `newobject: {...}`), поэтому сверяйте `data.jsonQuery` в ответе. Правильный `jsonQuery` для любого фильтра проще всего взять из SSR страницы `cat.php` с этим фильтром.
5. **Лимит выдачи:** не больше 54 страниц × 28 = ~1500 объявлений на запрос. Страница 54 возвращает 16 объявлений, страница 60 — пустая. Новостроек в Москве 57 тыс., поэтому большие выборки нужно резать: по цене, комнатам, ЖК. В сборщике есть `search_all`, который рекурсивно делит ценовой диапазон.
6. **Каталог ЖК:** `/newobjects/list/?deal_type=sale&engine_version=2&offer_type=newobject&region=1&p=N`, SSR `newbuilding-search-frontend` → `initialState.offersData.newbuildings` (25 на страницу, в Москве 623 ЖК).
7. **Карточка ЖК** (`https://zhk-<slug>.cian.ru/`): SSR `newbuilding-card-desktop-fichering-frontend` → `initialState.newbuilding`. Внутри:
   - корпуса и сроки по очередям (`houses`, `housesByTurn`);
   - застройщики (`builders`);
   - характеристики (`specifications`, `specificationsDetailed`: парковка, безопасность…);
   - ход строительства с фото по месяцам (`constructionProgress`);
   - квартирография по комнатам и корпусам (`offers.data`, `layoutsInfo`);
   - отзывы, банки;
   - блок `reliability` «Проверено наш.дом.рф»: реестр проблемных объектов, банкротство застройщика, эскроу, фото стройки, дата проектной декларации.

### Какие поля есть у квартиры

Цена и тип продажи (ФЗ-214 и т. п.), комнаты, площади (общая, жилая, кухня), этаж и этажность, отделка, материал, срок сдачи (год, квартал, сдан ли). Дальше: ЖК (id, название, URL), корпус и секция, продавец (застройщик или агент), адрес, координаты, метро со временем, фото и планировка, дата публикации, описание. Заполненность в прогоне: ключевые поля 85–100%, площадь кухни 43%, секция 70%.

Нормализованная запись — `flat_row()` в `collectors/cian.py`; сырые объявления — флаг `--raw` (около 150 полей).

### Рекомендуемая стратегия полного сбора

1. Каталог ЖК региона — `cian.py jk --pages 30` (25 запросов на Москву).
2. По каждому ЖК — квартиры через `--newobject <id>`. В одном ЖК почти всегда меньше 1500 объявлений, так что лимит не мешает, а данные сразу сгруппированы.
3. Карточки ЖК — `cian.py jk-card` (корпуса, сроки, надёжность), один запрос на ЖК.
4. Для «всего рынка» вне ЖК — `flats --all` с нарезкой по цене.

Объём для Москвы: около 57 тыс. квартир / 28 ≈ 2050 запросов + 623 карточки. При паузе 1,5–3 с это примерно 1,5–2 часа в один поток.

Ограничения: держать паузы и повторы при 403/429 (в сборщике есть), не собирать телефоны (персональные данные агентов), учесть пользовательское соглашение Циана — оно запрещает автоматизированный сбор. Для коммерческого использования нужна юридическая оценка или партнёрский доступ.

## наш.дом.рф

### Что происходит при заходе

1. `GET /` без cookie отдаёт страницу JS-челленджа Servicepipe: скрипты с `servicepipe.tech`, параметры `get_cookie_spsn/get_cookie_spid`, переход на `/xpvnsulc/?back_location=...`.
2. Любой другой путь без cookie, включая `robots.txt` и `/сервисы/api/...`, сразу получает 403 «Доступ заблокирован».
3. Браузер выполняет челлендж и отправляет отпечаток: таймзону, язык, WebGL-рендерер, платформу. Ответ на это — слайдер-капча «запросы с вашего устройства похожи на автоматические».

### Перепроверка «может, я сам спровоцировал блок»

| # | Конфигурация | Новый профиль | Исходящий IP | Результат |
|---|---|---|---|---|
| 1 | `curl` с User-Agent | — | .134 | блок-страница |
| 2 | curl_cffi `impersonate=chrome`, `/` | — | .142 | JS-челлендж (не блок) |
| 3 | rea + Chromium через прокси, глубокая ссылка на каталог | да | .135 | челлендж → капча |
| 4 | Scrapling `StealthySession`, headless, `ru-RU`, `Europe/Moscow`, вход с `/`, ожидание 20 с | да | .16 (новый) | челлендж → капча |
| 5 | То же, но headful под Xvfb | да | новый | челлендж → капча |

Вывод: капча появляется уже при первом визите со свежего профиля и с IP, который раньше не использовался. Значит, причина не в моих прошлых запросах, а в самом окружении: IP из Google Cloud (AS396982, США), программный рендеринг SwiftShader, Linux. Решающий фактор почти наверняка IP-репутация — WebFetch с серверов Anthropic тоже получил 403. Капчу я не решал и не обходил.

### Что известно о данных и API

- **Сайт — это ЕИСЖС.** Карточка объекта: `/сервисы/каталог-новостроек/объект/<objId>`, список: `/сервисы/каталог-новостроек/список-объектов/список?objStatus=0`.
- **JSON-API SPA** по открытым источникам: `/сервисы/api/kn/object?offset=&limit=&sortField=&sortType=&objStatus=` (список, `data.list` / `data.total`) и `/сервисы/api/object/<objId>` (карточка). Поля: `objId`, `developer` (`devId`, название, ИНН), координаты, `buildType`, `siteStatus`, `residentialBuildings`, `complexShortName`. **Отсюда вживую не подтверждено**, поэтому сборщик сначала делает `discover`.
- **Официальный коммерческий API ЕИСЖС** (бизнес.дом.рф). Шесть групп методов: группы компаний, застройщики, ЖК, объекты строительства, генподрядчики, проблемные объекты. Проектные декларации в машиночитаемом виде, около 8,5 тыс. застройщиков и 34 тыс. объектов. Авторизация OAuth 2.0 (Keycloak), шлюз Gravitee, доступ юрлицам по подписке. Это легальный и самый полный путь, если данные нужны для бизнеса.
- **платформа.дом.рф** открывается из облака без антибота. Это Next.js, 10 агрегированных датасетов: «Активность застройщиков», «Квартирография», «Объекты строительства по регионам», «План ввода по кварталам» и др. У каждого есть паспорт полей; например, в датасете 1 это `developer_id/name/inn/ogrn`, `active_projects`, объёмы строительства. Экспорт CSV/JSON закрыт Yandex SmartCaptcha: человек скачивает вручную за минуту, автоматически — нет. Уровень данных агрегированный, не поквартирный.
- **Косвенный источник:** карточки ЖК на Циане содержат результаты проверки «наш.дом.рф» (проблемность, банкротство застройщика, эскроу, дата декларации).

### Как собирать

1. Запустить `collectors/domrf.py discover` с российского домашнего или мобильного IP. Это локальная машина или `DOMRF_PROXY=http://user:pass@host:port` с резидентным прокси. Скрипт пройдёт JS-челлендж в браузере, откроет каталог и карточку объекта и запишет все XHR и JSON-ответы в `requests.json`. Так мы увидим реальные эндпоинты и поля.
2. Если пути совпадут с известными, `domrf.py catalog --limit 100 --pages N` выгрузит каталог запросами из контекста страницы (те же cookie, IP и TLS), `domrf.py object --id` — карточку. Если не совпадут, поправить две константы `API_LIST`/`API_OBJECT` по результату `discover`.
3. Если снова будет капча, скрипт остановится с сообщением и скриншотом и не будет пытаться её обойти. Если капча появляется и с российского IP, нужен коммерческий API ЕИСЖС.

## Связь двух источников

У Циана свои ID ЖК, у наш.дом.рф — `objId` (это корпус, а не ЖК) и ИНН застройщика. Общего ключа нет. Сопоставлять стоит по названию застройщика и ЖК, адресу и координатам, а на уровне корпусов — по номеру корпуса и сроку сдачи.

## Тестовый прогон (2026-10-19, Москва)

| Команда | Результат |
|---|---|
| `cian.py jk --region 1 --pages 2` | 50 ЖК из 623 |
| `cian.py jk-card --url https://zhk-soyuz-i.cian.ru/` | карточка ЖК «СОЮЗ»: 6 корпусов, очереди, ход стройки, надёжность |
| `cian.py flats --newobject 4025502` | 118 квартир ЖК «СОЮЗ» (`offerCount` = 119) |
| `cian.py flats --region 1 --new --pages 2` | 56 квартир из 57 192 |
| `search_all` с порогом 56 (проверка нарезки) | 4 ценовых среза, 117 уникальных квартир, дублей нет |
| `domrf.py catalog` из облака | корректный отказ: «Servicepipe показал капчу/блок…» |

Первые четыре команды вместе заняли 36 с (паузы 1,5–3 с между запросами).

Файлы: `samples/2026-10-19/`.

`offerCount` иногда на 1–2 больше фактической выдачи: объявления снимаются и добавляются между запросами.
