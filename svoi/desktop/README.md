# The Mesh — приложение для компьютера

Обычная программа с установщиком, окном, значком у часов, автозапуском и системными уведомлениями.
Внутри — та же программа `themesh` (ядро), которую приложение само запускает в фоне: без чёрного окна и без браузера.

**Что делает оболочка** (`src/`):

* запускает ядро (`themesh up --no-browser --exit-when-stdin-closes`) и держит открытой его стандартный ввод:
  если приложение закрылось или упало, ядро завершается само; если ядро упало — приложение запускает его снова;
* если ядро уже работает на этом каталоге данных (например, из командной строки), использует его и не останавливает;
* показывает интерфейс ядра в своём окне, входит в него одноразовой ссылкой (главный токен никогда не попадает на страницу);
* закрытие окна сворачивает приложение в трей — устройство остаётся в сети; «Выйти» в меню значка останавливает всё;
* системные уведомления о входящем файле, полученном файле, сообщении и письме, пока окно закрыто или не в фокусе;
* один экземпляр: повторный запуск возвращает окно; автозапуск при входе в систему (спрашивает один раз, после создания сети);
* скачивания из интерфейса сохраняются в «Загрузки».

## Вид окна на Mac: «Liquid Glass»

На Mac окно приложения нарисовано в стиле **Liquid Glass** — языка оформления macOS 26 (Tahoe): плавающая стеклянная
боковая панель, полупрозрачные панели с мягкой подсветкой кромки над цветным фоном, капсульные кнопки, вкладки и переключатели,
стеклянные окна, меню и уведомления. Окно **без строки заголовка**: три кнопки окна лежат в углу боковой панели, а перетаскивать
окно можно за верх боковой панели и за верхнюю полосу. Окно **просвечивает системным материалом macOS** (Electron `vibrancy:
'under-window'`); его светлый/тёмный тон следует выбору «Авто / Светлая / Тёмная» в настройках интерфейса. Если в macOS включено
«Уменьшить прозрачность», окно становится сплошным, а интерфейс рисует плотные панели без размытия.

* Выбрать внешний вид можно в «Настройки → Внешний вид → Стиль»: «Авто» (на Mac — Liquid Glass), «Liquid Glass», «Классический».
  На Windows, Linux и в браузере по умолчанию остаётся классический вид — для них ничего не изменилось. Приложение для Android
  начинает со стеклянного вида (см. [android/README.md](../android/README.md)).
* `THEMESH_DESKTOP_GLASS=0` при запуске даёт Mac обычное окно со строкой заголовка и классическим видом.
* Как интерфейс узнаёт, где он: приложение дописывает к user agent `TheMeshDesktop/<версия> (mac; skin=glass; vibrancy; inset)`
  (`src/window.js`, `windowLook`); `skin=glass` — с какого вида начать, `vibrancy` — окно просвечивает, `inset` — нет строки заголовка.
  Правила и устройство стекла — в [docs/UI-NOTES.md](../docs/UI-NOTES.md#skins-classic-and-glass).

**Что это не так:** это *приближение* языка Liquid Glass обычным CSS, а не его настоящая реализация. Настоящее стекло macOS
(`NSGlassEffectView`) Electron не предоставляет, поэтому нет преломления света на краях и подсветки, следующей за курсором;
размытие умеренное намеренно. Образец — macOS 26: про macOS 27 на момент работы ничего достоверного неизвестно, поэтому «как в
macOS 27» здесь значит «как в macOS 26, текущей версии этого оформления».

**Как проверено**, и что нет:

* юнит-тесты параметров окна для Mac, для «Уменьшить прозрачность» и для других систем; семь браузерных тестов вида
  (`web-e2e/tests/skin.mjs`: что выбрано по умолчанию, выбор в настройках, `?skin=`, нет горизонтальной прокрутки на трёх
  ширинах в обеих темах, QR остаётся сплошным и резким, «Уменьшить прозрачность»); шаг дымового теста — на Mac он проверяет, что
  боковая панель стеклянная и оставляет место под кнопки окна, и снимает **окно целиком средствами системы** (`screencapture`:
  видны кнопки окна и скругления, чего не видно на снимке страницы);
* контраст текста: `node web-dev/check-contrast.mjs` берёт цвет каждого видимого фрагмента текста и цвета, которые реально лежат
  за ним (снимок с прозрачным текстом), и считает отношение WCAG. Главные экраны, обе темы, три ширины: стеклянный вид — 0 из 2786
  фрагментов ниже 4,5:1; окно, просвечивающее материалом (над «тусклой» и «яркой» заменой материала), — 5 из 5580 (худший 3,7:1);
  классический вид — 51 из 2814;
* на **настоящей macOS 26 машины CI** окно открыто и снято целиком средствами системы: кнопки окна в углу боковой панели,
  скругления и тень, стеклянное окно «Подключите новое устройство» над размытой страницей, резкий QR, и — когда CI выключает
  «Уменьшить прозрачность» (на машинах GitHub оно по умолчанию включено; шаг в `themesh-desktop.yml` и проба его выключают) —
  настоящий просвет системного материала сквозь окно над цветными «обоями» (`.github/workflows/themesh-mac-probe.yml`: окно
  приложения в обеих темах и экраны интерфейса с выдуманными данными; картинки сохраняются как артефакт прогона);
* **не проверено:** вид на живом Mac с настоящими обоями (в CI «обои» — нарисованные цветные пятна в отдельном окне), смена обоев
  и темы системы на лету, вид с другим масштабом экрана (на машине CI экран 1024×768), несколько мониторов, производительность
  размытия на слабых видеокартах, перетаскивание окна за боковую панель руками. Переключение «Уменьшить прозрачность» на
  лету сделано по документации Electron и проверено только юнит-тестом параметров.

`tools/mac-probe` и `.github/workflows/themesh-mac-probe.yml` — не часть сборки: на настоящем Mac (CI) они открывают интерфейс
в окнах с теми же параметрами, что у приложения, в нескольких вариантах и снимают экран; картинки сохраняются как артефакт.

Ключи устройства лежат отдельно от профиля приложения (`%APPDATA%\themesh`, `~/Library/Application Support/themesh`, `~/.config/themesh`)
и **не удаляются** при удалении программы.

## Разрешение «Локальная сеть» на macOS

С macOS 15 (и в macOS 26) программе, которая ищет устройства в домашней сети (The Mesh делает это маячками и поиском «Рядом»), нужно
разрешение **«Локальная сеть»**. Без него система не отказывает громко: отправка просто завершается ошибкой `EHOSTUNREACH`, и устройства в одной
Wi-Fi-сети **молча не находят друг друга**. Что сделано:

* в `Info.plist` записано `NSLocalNetworkUsageDescription` (`electron-builder.yml`, `mac.extendInfo`) — система сама спросит при первой попытке; текст
  объясняет, зачем: чтобы находить свои устройства в домашней сети;
* ядро говорит, что с этим не так (`self.lan.problem` = `blocked`): интерфейс пишет об этом на «Главной» и в «Настройки → Сеть» словами, с путём
  «Системные настройки → Конфиденциальность и безопасность → Локальная сеть»;
* оболочка (`src/localnet.js`) следит за тем же статусом и показывает окно с кнопкой, которая открывает именно этот раздел настроек
  (`x-apple.systempreferences:com.apple.preference.security?Privacy_LocalNetwork`): не сразу, а через 45 секунд после того, как узел сообщил
  `blocked` (чтобы человек успел ответить на вопрос самой системы), и после «Позже» не напоминает три дня (на «Главной» уведомление остаётся).

**Не проверено на настоящем Mac**: как выглядит запрос системы при первом запуске, и приходит ли `EHOSTUNREACH` именно так на macOS 26 (логика опирается на
поведение, описанное для macOS 15; на машине CI с macOS 26 разрешение не запрашивалось). Проверено: юнит-тест `localnet.js` (когда окно показывается и когда нет).

## Уведомления

Пока окно закрыто или не в фокусе, приложение показывает системные уведомления: «вам предлагают файл», «файл получен», сообщение, письмо и
**«X просит добавить его в сеть»** (устройство рядом хочет вступить: в уведомлении шесть цифр для сверки; щелчок открывает «Главную», где окно запроса
уже ждёт ответа). Тексты — `src/i18n.js`, условия — `src/notify.js` (`notificationFor`, проверяется `test/unit.mjs`).

## Сборка и проверка

```bash
# ядро для этой системы (из каталога svoi/ репозитория): go build -o desktop/bin/<платформа>-<архитектура>/themesh ./cmd/themesh
#   платформа: win | mac | linux; архитектура: x64 | arm64
cd desktop && npm ci
npm run test:unit                     # логика оболочки + настоящее ядро как фоновый процесс
xvfb-run -a node test/smoke.mjs       # окно, ядро, второе устройство, уведомления, падение и перезапуск (Linux: под виртуальным экраном)
npx electron-builder                  # установщик: Windows (NSIS) / macOS (dmg, zip) / Linux (AppImage, deb)
THEMESH_APP_EXE=dist/linux-unpacked/TheMesh node test/smoke.mjs   # то же самое, но на собранном приложении
```

Все три системы собираются и проверяются на настоящих машинах в GitHub Actions (`.github/workflows/themesh-desktop.yml`).
Подписи нет: Windows покажет SmartScreen, macOS — предупреждение Gatekeeper (программа не заверена Apple; в macOS 15 и новее
выход один: «Системные настройки → Конфиденциальность и безопасность → Всё равно открыть»).
