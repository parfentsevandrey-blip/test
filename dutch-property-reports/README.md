# Отчёты по объектам недвижимости (Нидерланды)

Генератор типового отчёта-подборки коммерческих объектов: из JSON-карточек
объектов собирается `.docx` в оформлении эталонного шаблона и (при наличии
LibreOffice) конвертируется в `.pdf`.

Структура отчёта повторяет шаблон:

1. **Обложка** — заголовок, страна, список объектов с ценами.
2. **Сводная страница** — таблица сравнения объектов по ключевым показателям
   (цена, цена входа, площадь, доходность, арендаторы, профиль) и дисклеймер
   о допущениях расчётов.
3. **По каждому объекту** — заголовок с адресом, плашки статуса, подзаголовок
   (индекс, район, провинция), фото фасада, четыре плитки KPI, строка
   позиционирования, таблица характеристик (группы «Финансы» и «Объект»),
   врезка «О городе и районе», разделы «Описание объекта», «Планировка»,
   «Технические характеристики», «Аренда и доходность», «Участок и парковка»,
   «Расположение и доступность», «Особенности и статус».
4. **Фотоблок** — обзорная карта с меткой и фотографии объекта с подписями
   (по 2 на страницу).

Финансовые строки таблицы характеристик в JSON больше не хранятся: их считает
`reportgen/finance.py` из блока `financials` карточки — см. раздел
«Финансовые показатели».

## Установка

```bash
pip install -r requirements.txt
# для PDF дополнительно нужен LibreOffice (пакет libreoffice-writer)
```

## Сборка отчёта

```bash
python generate_report.py build data/report-2026-07-27.json          # DOCX + PDF
python generate_report.py build data/report-2026-07-27.json --no-pdf # только DOCX
python generate_report.py -v build data/report-2026-07-27.json       # с логом
```

Результат складывается в `output/`. Карты и фотографии кэшируются в `.cache/`,
поэтому повторная сборка проходит без сетевых запросов.

## Как добавить объект

1. Создать `data/objects/<slug>.json` (проще всего — скопировать соседний файл).
2. Добавить ссылку на файл в массив `objects` файла отчёта `data/report-*.json`.
3. Запустить сборку.

### Формат карточки объекта

| Поле | Назначение |
|---|---|
| `slug` | идентификатор для имён файлов кэша |
| `title` / `subtitle` | заголовок объекта и строка «индекс • район • провинция» |
| `street`, `city`, `price_short` | строка объекта на обложке; `price_short` можно не задавать — подставится цена из `financials` |
| `map` | `{ "query": "адрес", "lat": …, "lon": …, "city": { "query": "Utrecht, Netherlands", "lat": …, "lon": … } }` — координаты можно не указывать, тогда сработает геокодирование |
| `financials` | исходные цифры объекта, из них считаются все финансовые показатели |
| `badges` | 1–3 коротких статуса у заголовка: `["100 % сдано", "1 арендатор"]` |
| `positioning` | одна строка о профиле вложения, попадает в сводную таблицу |
| `hero_photo` | фото фасада под заголовком; в `photos` не дублируется |
| `specs` | только описательные строки: массив пар `["подпись", "значение"]` |
| `sections` | разделы отчёта, по порядку |
| `photos` | фотографии объекта (`cloud.funda.nl/...` в размере `1440x960`) |

Блок `financials` — единственный источник денежных величин:

```jsonc
"financials": {
  "price_eur": 975000,            // запрашиваемая цена
  "price_basis": "k.k.",          // "k.k." или "v.o.n."
  "rent_eur_year": 73300,         // текущий валовой арендный доход
  "market_rent_eur_year": null,   // рыночная арендная стоимость, если указана в листинге
  "lettable_sqm": 616,            // арендуемая площадь v.v.o.
  "plot_sqm": 964,
  "tenants": 1,
  "walt_years": null,             // средневзвешенный срок аренды, лет
  "occupancy_pct": 100,
  "opex_ratio": 0.10,             // доля расходов собственника от аренды, для NAR
  "scenarios": [                  // опционально
    { "label": "После освобождения офисной части", "rent_eur_year": 77498 }
  ]
}
```

В `specs` остаются только описательные строки (здание, участок, права,
передача, ссылка). Цена, доход, доходность и цена за м² в JSON не пишутся —
код добавляет их сам отдельной группой «Финансы» перед группой «Объект».
Из `specs` берутся также «Год постройки» и «Энергетический класс» для сводной
таблицы; если строки нет, в сводке будет «н/д».

Фотографии задаются объектами с подписью; поддерживается и старый формат
(просто список ссылок — тогда подписи пустые):

```jsonc
"photos": [
  { "url": "https://cloud.funda.nl/…_1440x960.jpg", "caption": "Фасад со стороны Steenovenweg" },
  "https://cloud.funda.nl/…_1440x960.jpg"
]
```

Подпись к обзорной карте генератор ставит сам: «Расположение объекта: <город>».

Типы разделов в `sections`:

```jsonc
{ "type": "callout",    "heading": "О городе и районе", "title": "…", "paragraphs": ["…"] }
{ "type": "paragraphs", "heading": "Описание объекта",  "paragraphs": ["…", "…"] }
{ "type": "bullets",    "heading": "Планировка",        "bullets": ["…", "…"] }
```

Элемент списка в `bullets` — либо строка, либо пара «зачин — текст»
(зачин печатается жирным):

```jsonc
{ "lead": "Почва", "text": "проверить bodemonderzoek и решение WBB" }
```

## Финансовые показатели

Всю арифметику держит `reportgen/finance.py`: карточка описывает объект,
модуль считает показатели, генератор раскладывает их по таблице, плиткам KPI
и сводной странице. Ни одна цифра не набирается руками дважды.

Что считается из `financials`:

| Показатель | Как считается |
|---|---|
| Цена входа | цена + overdrachtsbelasting + расходы по сделке |
| BAR к цене | валовая аренда ÷ запрашиваемая цена |
| BAR к цене входа | валовая аренда ÷ цена входа |
| NAR к цене входа | (аренда − эксплуатационные расходы) ÷ цена входа |
| Цена за м², ставка €/м² | цена и аренда ÷ `lettable_sqm` |
| Сценарии | то же по каждому элементу `scenarios` |

Допущения (константы в начале `finance.py`, менять там же):

- `OVB_RATE = 0.104` — overdrachtsbelasting, налог на переход права
  собственности для нежилой недвижимости, ставка 2026 года;
- `CLOSING_EXTRA_RATE = 0.012` — нотариус, кадастр и due diligence,
  ориентировочно от цены;
- доля эксплуатационных расходов собственника берётся из `opex_ratio`
  карточки (обычно 0,10) и используется только для NAR.

Цены в листингах указаны «k.k.» (*kosten koper*) — налог и расходы по сделке
платит покупатель сверх запрашиваемой цены, поэтому доходность к цене входа
всегда ниже рекламируемой BAR к цене. Формат чисел единый: разделитель тысяч —
точка, десятичный — запятая, между числом и знаком «€», «%», «м²» —
неразрывный пробел (`€ 975.000`, `6,7 %`, `616 м²`).

## Сводная страница

Страница сравнения собирается автоматически из тех же данных: строки —
показатели (цена, цена входа, площадь, цена за м², доход, ставка €/м², BAR,
NAR, арендаторы, WALT, год постройки, энергокласс, профиль), колонки —
объекты в порядке файла отчёта. Недостающие значения выводятся как «н/д».

Дисклеймер под таблицей берётся из поля `disclaimer` файла `data/report-*.json`:

```jsonc
"disclaimer": "Расчёты ориентировочные, проверяются по документам продавца."
```

Если поля нет, подставляется формулировка по умолчанию с перечислением
принятых ставок (см. `DEFAULT_DISCLAIMER` в `generate_report.py`).

## Колонтитулы и закладки PDF

На страницах отчёта (кроме обложки) печатается колонтитул с названием отчёта
и номером страницы. Заголовки объектов размечены уровнями структуры документа,
поэтому LibreOffice переносит их в закладки PDF: в панели навигации получается
оглавление по объектам, отчёт удобно листать при обсуждении.

## Карты

Обзорная карта — Google Maps. Кадр строится по двум точкам: сам объект (на нём
красная метка) и ближайший крупный город из поля `map.city`; масштаб
подбирается автоматически так, чтобы город с подписью гарантированно попал в
кадр. Явный `map.zoom` в карточке перекрывает автоподбор.

Источник изображения выбирается автоматически:

- если задан ключ `GOOGLE_MAPS_API_KEY`, используется официальный
  **Google Maps Static API** — это штатный режим для регулярной работы:

  ```bash
  export GOOGLE_MAPS_API_KEY=...
  python generate_report.py build data/report-2026-07-27.json
  ```

- без ключа карта собирается из растровых тайлов Google. Режим рабочий, но
  для постоянного использования лучше завести ключ Google Maps Platform.

## Данные с funda in business

Страницы funda закрыты Akamai Bot Manager (посетителя встречает страница
проверки с reCAPTCHA), поэтому скачать HTML скриптом нельзя — страницу нужно
сохранить из браузера («Сохранить как» → *.html или скопировать outerHTML).
Из сохранённого файла черновик карточки собирается автоматически:

```bash
python generate_report.py parse raw/steenovenweg.html \
    -o data/objects/draft.json \
    --url https://www.fundainbusiness.nl/en/belegging/montfoort/object-44425433-steenovenweg-11-13/
```

Парсер достаёт таблицу «Kenmerken», текст описания и **все** ссылки на
фотографии объекта. Дальше черновик дополняется русскими формулировками
разделов и переносится в формат карточки.

Сами изображения (`cloud.funda.nl`) отдаются без защиты, их загружает
`reportgen/media.py` — правится только список ссылок.

## Устройство пакета

| Модуль | Отвечает за |
|---|---|
| `reportgen/style.py` | цвета, кегли, геометрия — всё оформление задаётся здесь |
| `reportgen/finance.py` | расчёт показателей (цена входа, BAR, NAR, €/м²) и формат чисел |
| `reportgen/docx_render.py` | вёрстка DOCX: обложка, сводка, KPI, таблицы, врезки, фотостраницы |
| `reportgen/maps.py` | геокодирование (Nominatim) и сборка карты из тайлов OSM/CARTO |
| `reportgen/media.py` | загрузка и кэширование фотографий |
| `reportgen/pdf.py` | конвертация DOCX → PDF через LibreOffice |
| `reportgen/funda_parse.py` | разбор сохранённой страницы funda в черновик карточки |

Оформление (цвета `#1A3A5C`, `#C9A961`, `#F5F1E8`, кегли, отступы, ширина
колонок таблицы) снято непосредственно с эталонного PDF, поэтому новые отчёты
визуально совпадают с ранее выпущенными.
