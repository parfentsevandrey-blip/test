# Продажи новостроек Москвы: данные наш.дом.рф

Исследование продаж премиальных ЖК Москвы. Источник данных — ЕИСЖС «наш.дом.рф» (зарегистрированные ДДУ, 12 месяцев: октябрь 2025 — сентябрь 2026).

## Структура

| Папка | Что внутри |
|---|---|
| `ndr_workflow/` | Сборщик `ndr_workflow.py` на Scrapling: одна браузерная сессия с допуском, темп, остановка на капче, продолжение с места остановки. `state.json` — собранные страницы объектов. `EXPERIENCE.md` — реестр ошибок и проверенных решений, `experience.jsonl` — машинный журнал проходов |
| `report/` | PDF-отчёт по 7 проектам и их конкурентам (`report.pdf`), генераторы `build_data.py` / `build_report.py`, карты Яндекса (`maps/`) |
| `moscow_scan/` | Скан всех строящихся корпусов внутри МКАД: `buildings.csv` (по корпусам), `complexes.csv` (по ЖК), `scan.json`. Контур МКАД — OSM relation 2094222 (`mkad.py`, `mkad_nodes.json`) |
| `ndr/` | Карта всех строящихся объектов (`moscow_map.json`), исходный список для поиска соседей |
| корень | Посты Telegram-канала @propertyinsider (`tg_propertyinsider.json`) |

## Показатели

- **Продано** — счётчик наш.дом.рф (`sales_agg`, квартиры в штуках).
- **Продажи по месяцам и цена сделок** — встроенный JSON страницы (`__NEXT_DATA__ → salesDynamic.monthlySalesByType`).
- **Распродаст остаток при нынешнем темпе** = непроданные квартиры ÷ средние продажи в месяц за июль–сентябрь (для новых проектов — только за месяцы с продажами).

## Авто-возобновление

Контейнер облачной сессии временный: когда сессия простаивает, он выключается, и сбор останавливается. При каждом старте или пробуждении сессии хук `.claude/hooks/session-start.sh` вызывает `research/ndr/resume_scan.sh`, и сбор продолжается с места остановки:

- если цикл уже идёт — ничего не делает (блокировка + проверка процесса);
- если рабочая папка пропала — восстанавливает код и собранные данные из `research/ndr/`;
- проверяет Chrome, Xvfb, Scrapling и запускает цикл в фоне;
- цикл сам выдерживает паузу от последней страницы, поэтому перезапуск не ускоряет темп.

Почасовая проверка будит сессию; после каждого прохода данные коммитятся, поэтому при потере контейнера теряется не больше одного прохода.

## Запуск

```bash
cd research/ndr/ndr_workflow
./run.sh preflight      # проверка отпечатка браузера, без запросов к сайту
./run.sh loop           # сбор очереди из state.json с паузами
python3 ../moscow_scan/scan_export.py   # пересобрать CSV/JSON скана
```

Профили браузера (куки сессии) в репозиторий не попадают: при новом запуске сессия создаётся заново.
