## Этапы и переходы

| Этап | Что делаем | Критерий перехода | Кто проверяет |
|---|---|---|---|
| `discovered` | Найден в канале: наш.дом.рф, ЦИАН, sitemap застройщиков, erzrf.ru, Telegram | Не дубль: сначала детерминированно (id наш.дом.рф или ЦИАН, нормализованное название + застройщик, координаты ≤ 150 м), затем Splink по названию, адресу, координатам и застройщику — только для остатка | `discover.py` |
| `screened` | Фильтр «только современные» (`MODERN_FILTER.md`) | Прошёл → `identified`; нет → `excluded`; серая зона → ручная проверка | `screen.py` |
| `identified` | Юрлицо → бренд, официальный сайт (ссылка с сайта бренда, L1/L2), id ЖК на ЦИАН, id объектов наш.дом.рф | Каждый id подтверждён двумя источниками: наш.дом.рф ↔ ЦИАН (название, застройщик, адрес), сайт ↔ сайт бренда. **С этого этапа ЦИАН-сторона собирается**, лоты помечены «без кросс-проверки» | `identify.py` + ручная проверка первых подключений |
| `adapter` | HAR одного бережного посещения → REA + mitmproxy2swagger (W25) → карта API → адаптер по шаблону `devcat`. Известный застройщик → его адаптер | Каталог ≤ 50 запросов, 0 блокировок, полнота ≥ 98% к объявленному сайтом | фабрика адаптеров |
| `verified` | Двойная проверка (ниже, 1.3) | Все 5 линий пройдены; расхождение → разбор, а не допуск | `verify.py` + владелец (первые 3 нового типа сайта) |
| `probation` | **5 дневных циклов подряд** в общем цикле; в «Лоты дня» не идёт | Каждый день: полнота ≥ 98%, сверка с ЦИАН ≥ 95%, хэш схемы ответа не менялся, ни одной регрессии | надзор |
| `production` | В цикле и в выдаче | — | — |
| `broken` | Регрессия (1.4): лоты исключены из выдачи, последние верные данные сохраняются, задача «повторная разведка» первой в очереди | Повторный проход с `adapter` | надзор |
| `excluded` | Мусорка | Пересмотр раз в месяц | `screen.py` |

**Почему испытательный срок — 5 дней.**
- Все поломки пилота (L3, L5, L6, L11, L12) проявились в первые 1–2 прогона. 3 дня дают запас в один прогон.
- Но многие застройщики обновляют прайс раз в неделю, обычно в начале недели. 5 дней почти всегда захватывают такое обновление и проверяют адаптер на смене цен.
- 5 дней ≤ 1 дня работы конвейера: испытательный срок идёт в общем цикле, без отдельной работы.

## 1.3 Двойная проверка при подключении

1. **Полнота.** Адаптер сравнивается:
   - со счётчиком сайта («N квартир в продаже», сумма по корпусам);
   - с декларацией наш.дом.рф (квартир в корпусах минус продано).

   Отклонение больше 2% — разбор.
2. **Точность двумя путями.** 30 случайных лотов перечитываются другим путём: страница квартиры против API, браузер против HTTP. Цена, площадь, этаж и статус должны совпасть на 100% (`qa.py`, слой 2).
3. **Связка с ЦИАН.**
   - Сначала детерминированно: корпус, секция, этаж, номер, площадь ±0,3 м², комнатность.
   - Splink — только для остатка: E7 показал, что по корпусам детерминированное правило точнее.
   - Цель: ≥ 95% лотов застройщика на ЦИАН сверены, все расхождения классифицированы.
4. **Связка с реестром.** Корпуса и застройщик сходятся с наш.дом.рф: срок ввода ±1 квартал, число квартир ±2%, юрлицо → бренд.
5. **Ручной контроль.**
   - Первые 3 подключения нового типа сайта (Next, Nuxt, «посетитель», карта сайта + страницы, API этажей…) — сводка владельцу: 10 лотов с тремя ссылками рядом.
   - Дальше проверка автоматическая; выборочно смотрим каждое 10-е подключение.

## 1.4 Надзор (каждый цикл)

- **Детектор регрессий:**
  - лотов меньше, чем вчера, больше чем на 10% (если нет события «распродано»);
  - доля пустых полей выросла больше чем на 5 п.;
  - сменился хэш схемы JSON;
  - ошибок больше 2% запросов.
- **Еженедельно** — контрольная двойная проверка 5% лотов каждого застройщика.
- **Каждая поломка** — урок L-n и правило в коде (тест на подменённый ответ).
