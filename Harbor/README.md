# Harbor — каталог и установщик наших приложений

Восьмое приложение каталога (см. [манифест](../MANIFESTO.md)) и единая точка распространения всех остальных.
Swift 6, SwiftUI, Liquid Glass, русский интерфейс, без сторонних библиотек: загрузка — `URLSession`,
SHA-256 — CryptoKit, проверка подписи — Security.framework, распаковка — системный `ditto`.

## Установка — одна команда, без «Всё равно открыть»

Откройте Терминал и вставьте:

```sh
curl -fsSL https://github.com/parfentsevandrey-blip/test/releases/download/catalog/install.sh | bash
```

Скрипт скачает Harbor, проверит SHA-256 и подпись, положит его в «Программы» и откроет. Всё остальное
ставится и обновляется уже из Harbor. Тот же скрипт умеет и без Harbor:

```sh
… | bash -s -- ward swarm     # конкретные приложения
… | bash -s -- --all          # все опубликованные
… | bash -s -- --update       # обновить всё установленное
… | bash -s -- --list         # каталог и установленные версии
```

## Почему macOS больше не ругается

Предупреждение «не удалось проверить разработчика» Gatekeeper показывает только для файлов с меткой
карантина `com.apple.quarantine`. Её ставит браузер при скачивании. Отсюда вся цепочка «скачать DMG →
перетащить → настройки → Конфиденциальность → Всё равно открыть → отпечаток пальца».

Harbor и `install.sh` скачивают сами (`URLSession` и `curl` метку не ставят), проверяют SHA-256 из каталога
и подпись кода и на всякий случай снимают метку со всего бандла. Программа просто открывается.
Кнопка «Снять метки с уже установленных» убирает её у приложений, поставленных раньше из DMG.

Что остаётся от macOS:
- **«Управление приложениями»** (Конфиденциальность и безопасность). Чтобы заменить одну программу
  другой, macOS один раз попросит разрешить это Harbor. Онбординг ведёт прямо в нужный раздел настроек.
- **Нотаризация Apple** убрала бы и это, но требует платной программы разработчика ($99 в год).
  Без неё мы обходимся честно: не прячем приложение от проверки, а не даём браузеру его пометить.

## Обновление без потери данных

1. Каталог проверяется при запуске, после сна и каждые 4 часа.
2. Новая сборка скачивается рядом с местом установки (тот же том — замена атомарная), проверяется
   SHA-256, идентификатор бандла и подпись кода.
3. Если программа не запущена — замена сразу. Если запущена — обновление ждёт, пока вы её закроете,
   и ставится мгновенно (кнопка «Обновить» закрывает программу штатно, она успевает сохранить состояние,
   и открывает её снова).
4. Заменяется **только бандл** `.app`. Настройки, библиотеки, модели, загрузки, связка ключей лежат
   в `~/Library` и не трогаются.
5. Предыдущая версия остаётся в `~/Library/Application Support/Harbor/Backups` — «Вернуть предыдущую версию».
6. Удаление — в Корзину; данные по выбору остаются (тогда при повторной установке всё вернётся) или тоже в Корзину.

Сам Harbor обновляется так же и перезапускается, когда его окно не на экране.

### Постоянная подпись: чтобы разрешения не слетали

Подпись ad-hoc меняется с каждой сборкой, и macOS после обновления не узнаёт программу: заново спрашивает
доступ к связке ключей (Ward), микрофону и универсальному доступу (Utter), «Управление приложениями» (Harbor).
Решение — один и тот же сертификат для всех сборок. Он самоподписанный и бесплатный; создаётся один раз
на вашем Mac:

```sh
./Harbor/scripts/make-signing-identity.sh
```

Скрипт создаст сертификат «Harbor Code Signing» и запишет его в секреты репозитория
`HARBOR_SIGNING_P12` и `HARBOR_SIGNING_PASSWORD` (через `gh`, а если его нет — подскажет, куда вставить).
С этого момента CI подписывает им все приложения. Без секретов всё работает с подписью ad-hoc, как раньше.

## Как новая версия попадает в Harbor

Ничего делать не нужно: каждая зелёная сборка в CI публикуется сама.

1. Workflow приложения собирает его, гоняет самопроверки и запускает `Harbor/release/publish.sh`.
   Тот упаковывает `.app` в zip (`ditto`), считает SHA-256, вынимает иконку, прикладывает скриншоты
   и выкладывает всё в релиз с тегом `catalog` вместе с манифестом `<id>.json`.
2. Номер сборки — номер запуска workflow, поэтому каждая публикация новее предыдущей.
3. Защита от отката: если ветка не продолжает коммит прошлой публикации (старая или параллельная ветка),
   публикация пропускается.
4. Workflow `harbor-catalog.yml` (строго по одному) собирает `catalog.json` из описаний
   `Harbor/Catalog/apps.json` и всех манифестов.
5. Harbor у пользователя увидит новую версию при следующей проверке (до 4 часов, или сразу по ⌘R).

Описания, возможности и цвета витрины правятся в `Harbor/Catalog/apps.json`.

## Проверка качества

- `--selftest-core` — сравнение версий, разбор каталога, SHA-256, метка карантина, подпись самого Harbor.
- `--selftest-install` — полный цикл на подставном приложении (копия Harbor с другим идентификатором)
  через локальный HTTP-сервер: установка со снятием карантина; обновление **запущенного** приложения —
  оно штатно закрывается, заменяется и открывается новой версией, его данные не тронуты; отказ сборкам
  с неверной SHA-256, чужим идентификатором, сломанной подписью и чужим сертификатом; откат; удаление
  с сохранением данных.
- Тот же цикл через `install.sh`: установка, снятие метки с уже установленной копии, `--update`, резервная копия.
- Скриншоты витрины, страницы приложения, обновлений и онбординга.

## Сборка

```sh
./scripts/build.sh          # dist/Harbor.app и dist/Harbor.dmg
```

Нужны macOS 26+ и Xcode 26 (Swift 6.2+).
