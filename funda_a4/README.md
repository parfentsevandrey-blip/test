# funda_a4 — A4-лист «карта + фото объекта» по ссылке Funda

Собирает один лист A4 для объявления Funda (in Business):

1. **Сверху** — обзорная карта с маркером объекта и таким зумом, чтобы были
   видны соседние населённые пункты.
2. **Снизу** — фото объекта из объявления.
3. Заголовок (адрес), подзаголовок и футер (цена / площадь / ссылка-источник).

Результат — `prinsestraat118.pdf` / `.png`, см. пример в этой папке.

## Обход анти-бот стены Funda — `funda_fetch.py`

Funda отдаёт DataDome-капчу («Je bent bijna op de pagina die je zoekt») для curl,
WebFetch, headless-браузера и даже серверного фетча Google Translate. **Рабочий
обход:** reader-прокси `r.jina.ai` — он рендерит страницу через браузерную ферму,
проходит проверку и возвращает чистый Markdown с таблицей характеристик и URL
фото `cloud.funda.nl`. Сами фото скачиваются напрямую с `cloud.funda.nl` при
передаче заголовка `Referer: https://www.fundainbusiness.nl/`.

```bash
python3 funda_fetch.py \
  "https://www.fundainbusiness.nl/en/winkel/utrecht/object-80865043-amsterdamsestraatweg-109/" \
  --out-dir assets --json facts.json
```

Скрипт парсит адрес, индекс, район, цену, год, энергокласс, площади, аренду и
скачивает фото галереи (полноразмерные `*_1440x960`, «похожие» листинги
отсеиваются). Описательную прозу пишет ассистент отдельно — `funda_fetch.py`
автоматизирует только сбор фактов и фото.

## Запуск

```bash
pip install Pillow requests

python3 make_sheet.py \
  --url "https://www.fundainbusiness.nl/en/winkel/den-haag/object-44407907-prinsestraat-118/" \
  --address "Prinsestraat 118, 2513 CH Den Haag" \
  --photo-url "https://i0.wp.com/delangemakelaars.nl/.../foto.jpg" \
  --subtitle "Winkel-/horecaruimte · Hofkwartier, Den Haag" \
  --footer  "Huurprijs: EUR 1.850 p/m excl. 21% BTW | ca. 70 m2" \
  --zoom 11 \
  -o prinsestraat118.pdf
```

Можно не указывать координаты — адрес будет геокодирован через Nominatim
(`--address`). Либо задать явно `--lat/--lon`.

## Почему именно так (reverse-engineering)

Изначально предполагалось, что мешает сетевой белый список. На практике
вскрылись два **других** ограничения, и архитектура решает именно их:

### 1. Funda за анти-бот стеной (CAPTCHA)

Прямой `GET` страницы объявления отдаёт не контент, а заглушку
*«Je bent bijna op de pagina die je zoekt»* (DataDome-подобная проверка).
Поэтому фото с самой Funda автоматически не вытащить. Решение — **цепочка
фолбэков** для фото:

1. `--photo` — локальный файл;
2. `--photo-url` — прямой URL (например, CDN брокера);
3. зеркало брокера — у объявлений Funda почти всегда есть дубликат на сайте
   агентства (для этого объекта это `delangemakelaars.nl`, фото на
   `i0.wp.com/...`), который **не** закрыт капчей;
4. попытка скрейпа `og:image` / `cloud.funda.nl` с самой Funda — срабатывает
   только если стена не активна (детектится автоматически).

Как находить зеркало: поиск по `адрес + "object-<id>"` обычно сразу выдаёт
страницу агентства с теми же фото в открытом доступе.

### 2. Google Static Maps требует API-ключ и биллинг

Карта строится двумя путями:

- если задан `GOOGLE_MAPS_API_KEY` — используется Google Static Maps
  (названия городов читаются чётче);
- иначе — **бесключевой фолбэк**: сшивка тайлов OpenStreetMap
  (`tile.openstreetmap.org`) своими силами в Web Mercator, с отрисовкой
  маркера и атрибуции. Работает без ключа и в ограниченных сетях, где
  тайл-сервер OSM доступен.

### Прочее

- Геокодинг — Nominatim (бесплатный, с вежливым User-Agent по их политике).
- Всё деградирует мягко: нет фото → плейсхолдер; нет координат → геокод по
  адресу; недоступна сеть → понятная ошибка с ретраями (backoff 1/2/4/8 c).

## Параметры

| Флаг | Назначение |
|------|-----------|
| `--url` | ссылка Funda (пишется как источник) |
| `--address` | адрес для геокодинга |
| `--lat/--lon` | координаты явно (без геокодинга) |
| `--zoom` | зум обзорной карты; меньше = больше городов (по умолч. 11) |
| `--photo` / `--photo-url` | фото объекта (файл / URL) |
| `--subtitle` / `--footer` | строки подзаголовка / футера |
| `-o` | выходной файл `.pdf` или `.png` |

## Лицензии / правила

- Тайлы OSM — © OpenStreetMap contributors, соблюдайте
  [tile usage policy](https://operations.osmfoundation.org/policies/tiles/)
  (для объёмов — свой тайл-сервер или платный провайдер).
- Фото/данные объявлений принадлежат правообладателям; используйте в рамках
  правил Funda/агентства.
