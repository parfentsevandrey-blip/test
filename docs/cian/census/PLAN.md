# Перепись квартир внутри МКАД

Цель — найти самые ликвидные сегменты рынка квартир Москвы в пределах МКАД.
Путь: собрать все лоты, дать каждому свой id, следить за появлением, снятием,
дублями и возвратами, классифицировать дома и состояние квартир по фото, и уже
по истории считать ликвидность.

Этот файл — рабочий план. Раздел «Реальность против плана» в конце
пополняется по ходу: каждое допущение плана сверяется с замером.

## Решения

- **Охват.** Все объявления о продаже квартир внутри МКАД: вторичка и
  новостройки. Новостройки ведутся на уровне корпуса и планировки, а не
  отдельной квартиры. Апартаменты — отдельный сегмент. Доли и койко-места не
  берём.
- **Сбор — в облачной сессии.** Короткие шаги по расписанию, состояние в git.
- **Фото — все квартиры.** Через Claude API в пакетном режиме, со своим ключом.
- **Капча — главный риск.** Поэтому сбор медленный, ровный, по бюджету и
  останавливается на первом признаке антибота.

## Архитектура

**Перепись.** Нарезка выдачи по цене под потолок 1 500 объявлений на запрос
(логика из откаченного `mass`), сверка всего собранного с запросом, список
пропусков. Отбор: 9 старых округов, затем контур МКАД по координатам
(`tools/cian/geo/mkad.json`, `census/mkad.js`). Группы «похожих» в
новостройках не раскрываются, если размер группы на лидере совпадает с
фактическим, — это проверяет пилот.

**Темп и антибот** (`census/client.js`). Один запрос за раз, пауза после
ответа 2–3,5 с, бюджет запросов на прогон. Первый же признак антибота — 429,
403, редирект на капчу или HTML вместо JSON с кодом 200 — останавливает прогон
без повторов и пишет файл `STOP`; пока не вышла выдержка, прогон не
начинается. Капчу не решаем и не обходим — ждём.

**Хранилище.** Отдельная ветка данных, только дописывание: реестр квартир с
нашими id (контрольная копия раз в неделю), полная карточка лота при первом
появлении и при смене текста или кадров, журнал событий по дням, журнал
каждого прогона. Порядок объёма — 1 ГБ в год.

**Идентичность и события.** Наш id — у квартиры на вторичке и у пары «корпус
+ планировка» на первичке. Сопоставление: дом, этаж, площадь, комнаты, общие
кадры, кадастровый номер, отпечаток текста (`descriptionMinhash` в ответе
Циан), цена. Слияние записывается с причиной и обратимо. События: появилась,
цена, снята (подтверждено вторым способом), вернулась, перевыставлена после
паузы, дубль добавился, дубль снят.

**Дом.** Год с добором по сроку сдачи и соседям, материал, этажность, ЖК,
флаг реновации (`demolishedInMoscowProgramm` в ответе, фильтр
`demolished_in_moscow_programm`), класс ЖК. Типология: сталинка, хрущёвка,
панель 70–80-х, поздняя панель, монолит 90–2000-х, ЖК 2010-х по классам,
строящийся.

**Фото.** Галерея фиксируется при первом появлении лота. Шкала массового
рынка: бетон или white box / под замену / устаревший жилой / современный
жилой / свежий; для премиума дополнительно буква A–E ([photo.md](../photo.md)).
Эталон на 150 квартирах, сравнение моделей, пакетный проход по всем.

**Аналитика.** Ликвидность считается по когорте лотов, появившихся после
старта слежения: доля ушедших к 2/4/8 неделям, медианный срок, месяцы
предложения, снижения цены, перевыставления. Сегмент — тип дома × состояние ×
метраж × локация × ценовая полоса, с минимумом наблюдений в ячейке.

## Инструменты

```bash
node tools/cian/census/test.js                       # проверки без сети

# пилот: каждая команда — короткий прогон со своим бюджетом
D=docs/cian/census/pilot
node tools/cian/census/pilot.js canary --dir $D --budget 3
node tools/cian/census/pilot.js counts --dir $D --set base --budget 25
node tools/cian/census/pilot.js counts --dir $D --set outside --budget 20
node tools/cian/census/pilot.js read   --dir $D --name R --query q.json --budget 60
node tools/cian/census/pilot.js groups --dir $D --name R --n 12 --budget 30
node tools/cian/census/pilot.js photos --dir $D --name R --n 3 --budget 8

# контур МКАД из выгрузки OSM (Overpass из сессии недоступен, API OSM — да)
node tools/cian/census/build-mkad.js --osm relation-2094222-full.json
```

Коды выхода пилота: 0 — готово, 2 — кончился бюджет, 3 — антибот (записан
`STOP`, выдержка 2 часа), 1 — прочее.

## Реальность против плана

### 24.09.2026

- **Метка после утренних замеров держится дольше часа.** Утром `mass`
  разгонялся до 5–10 запросов в секунду, и адрес получил капчу; сессия
  остановилась около 10:35 UTC. В 11:36 капчей отвечала уже сама главная
  cian.ru — шаг прогрева, на котором берутся куки. Прогрев браузером
  (`open()` агента) остаётся основой: он лечит «запрос без кук получает
  капчу», но не метку адреса после разгона. Пробный прогон остановился на
  главной, в API не ушло ни одного запроса; следующая проба — через час.
- **Адрес выхода — не один.** Облачный прокси выходит в интернет с пула
  адресов `160.79.106.128–137`: на 35 пробах — 7 разных, с неравными долями.
  Адрес меняется от соединения к соединению, выбрать его нельзя. Это
  объясняет утреннее «часть запросов получает капчу, часть — JSON»: метка
  стоит на адресе, а запросы расходятся по пулу.
- **Прокси перезаключает TLS**, поэтому Циан видит отпечаток прокси, а не
  браузера. До утреннего разгона сбор на медленном темпе с прогревом работал
  стабильно — значит, решает темп.
- **Overpass недоступен, API OpenStreetMap и Nominatim — да.** Контур МКАД
  собран из отношения 2094222: 624 участка, радиус кольца 14,1–20,2 км,
  сверен с 15 контрольными точками по обе стороны кольца.
- **В ответе поиска есть поля, которых план не учитывал:**
  `descriptionMinhash` (готовый отпечаток текста для поиска дублей),
  `cadastralNumber`, `buildingCadastralNumber`, `demolishedInMoscowProgramm`.
  Сколько лотов их заполняет — покажет пилот.
