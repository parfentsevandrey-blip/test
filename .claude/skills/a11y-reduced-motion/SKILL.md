# Доступность анимированной страницы

## prefers-reduced-motion — это режим, а не выключатель
Отключить `@media (prefers-reduced-motion: reduce) { * { animation: none } }` — ошибка: страница, построенная на скролл-анимациях, при этом разваливается.

Правильно: в reduced-режиме контент показан в конечном состоянии, сцены становятся обычными секциями, скролл-переходы заменяются мгновенной сменой. Проверь визуально — читается ли страница целиком.

## Клавиатура
- Весь интерактив доступен с Tab, порядок совпадает с визуальным.
- Видимый фокус на всём: `:focus-visible` с контрастным контуром, минимум 2px и `outline-offset`. Никогда `outline: none` без замены.
- Полноэкранные состояния (витрины, модалки) — ловушка фокуса, возврат фокуса на инициатор при закрытии, закрытие по Esc.
- Горизонтальные ленты прокручиваются стрелками, а не только перетаскиванием.

## Семантика
- `section` с `aria-labelledby`, `article` для карточек, `figure` + `figcaption` для экспонатов.
- Декоративная графика — `aria-hidden="true"`. Смысловая SVG — `role="img"` и `<title>`.
- Управляющие элементы — `<button>`, а не `<div>` с обработчиком.
- Живое обновление состояния (смена зала) — `aria-live="polite"`.

## Контраст
Основной текст — от 4.5:1, крупный — от 3:1. Отдельно проверь текст поверх размытых и полупрозрачных подложек: там контраст плавает вместе с фоном, нужна страховочная подложка.

## Проверка
Пройди всю страницу только с клавиатуры, затем с включённым reduced motion, затем прогони Lighthouse Accessibility (цель ≥ 90). Отчитайся, что именно проверил.
