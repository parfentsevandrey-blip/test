# Кинематографический скролл

Постановка, а не набор эффектов. Разрозненные fade-in — главный признак сгенерированной страницы.

## Структура
Страница — последовательность **сцен**. У каждой сцены: вход, удержание, выход. Пиши сценарий раскадровкой до кода: что видно на 0%, 50%, 100% прогресса сцены.

## Инструменты по приоритету
1. **CSS scroll-driven animations** — `animation-timeline: view()` и `scroll()`, `animation-range`. Работает вне главного потока, не требует JS.
2. **`IntersectionObserver`** — для дискретных состояний (сцена активна / нет), переключает класс.
3. **View Transitions API** — `document.startViewTransition()` для перехода «экспонат → полноэкранная витрина». `view-transition-name` на общем элементе.
4. **FLIP** — фолбэк там, где View Transitions недоступен: замерить `getBoundingClientRect()` до и после, применить обратный `transform`, снять его в следующем кадре.

Обязателен фолбэк: `@supports (animation-timeline: view())`, иначе — `IntersectionObserver`.

## Освещение
Смена атмосферы делается на уровне сцены, а не отдельных элементов: одна CSS-переменная фона/температуры света на корневом контейнере, интерполируемая по прогрессу скролла. Отдельные объекты подсвечиваются `radial-gradient`-маской, усиливающейся при входе во вьюпорт.

## Дисциплина
- Никаких вычислений в обработчике `scroll`. Если JS всё-таки нужен — `requestAnimationFrame` и кэш замеров.
- Анимируются только `transform`, `opacity`, `filter`. Всё остальное — повод переписать.
- Задержки каскадом (`--i` через `nth-child`) вместо ручных `animation-delay`.
- Скролл-джекинг запрещён: пользователь всегда сохраняет контроль над прокруткой.
- Параллакс — не более трёх слоёв, амплитуда до 15% высоты вьюпорта.

## Проверка
Прогони страницу в DevTools Performance при 4× CPU throttling. Если есть кадры дольше 16 мс — исправляй до того, как добавлять новый эффект.
