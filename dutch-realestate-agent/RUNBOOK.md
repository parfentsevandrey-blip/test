# RUNBOOK — еженедельный запуск

Короткий чек-лист для оператора. Полный прогон занимает пару минут.
Дату недели подставляйте в `WEEK` (формат `YYYY-MM-DD`, равна `week_end`).

```bash
export WEEK=2026-06-30      # дата окончания отчётной недели
```

---

## Чек-лист (понедельник)

1. **Обновить репозиторий**
   ```bash
   git pull
   ```

2. **Получить данные недели.** Запустить агента-исследователя (выполняет
   `agent_instructions.md`) — он соберёт `data/week_$WEEK.json`. Либо положить
   готовый JSON в `data/week_$WEEK.json` вручную.

3. **Установить зависимости** (только при первом запуске или после смены окружения)
   ```bash
   make install
   ```

4. **Проверить данные по контракту**
   ```bash
   make validate WEEK=$WEEK
   ```
   - `ERROR` (код 1) → данные нельзя рендерить, вернуть агенту на правку.
   - `WARN` → прочитать список. Особое внимание: «материал уже был в прошлом
     отчёте» (дубль) и «дата вне окна недели». Дубли заменить свежими.

5. **Собрать всё одной командой**
   ```bash
   make all WEEK=$WEEK
   ```
   Дождаться **QA-СВОДКИ** в конце. Проверить глазами:
   - `Валидация: ошибок 0`;
   - `Графики: N/N` (не `0/N` и не частично);
   - все 4 артефакта помечены как созданные (`Word`, `Превью`, `Письмо HTML/txt`);
   - число пунктов по сегментам выглядит правдоподобно.
   - Код выхода: `0` — всё чисто; `3` — частичный успех (см. шаг Troubleshooting).

6. **Просмотреть превью**
   ```
   reports/preview_$WEEK.html   ← открыть в браузере/на телефоне
   ```
   Проверить заголовок недели, главные выводы, графики, выводы по сегментам.

7. **Доставка письма** (требует авторизации коннекторов)
   - Загрузить `reports/${WEEK}_dutch_realestate_RU.docx` в Google Drive,
     получить ссылку.
   - Пересобрать тело письма со ссылкой (по желанию):
     ```bash
     make email WEEK=$WEEK FILE_LINK="https://drive.google.com/..."
     ```
   - Создать письмо в Gmail на `parfentsev.andrey@gmail.com`: тело —
     `reports/email_$WEEK.html`, ссылка на `.docx` — в теле.
   - Если коннекторы Gmail/Drive не авторизованы — письмо не уйдёт, но `.docx`
     уже лежит в `reports/`. Авторизовать коннекторы (claude.ai → настройки
     коннекторов) и повторить.

8. **Закоммитить состояние антиповтора**
   ```bash
   git add data/history.json data/week_$WEEK.json
   git commit -m "Отчёт за неделю $WEEK"
   git push
   ```
   > `data/history.json` обязательно коммитить — иначе антиповтор «забудет»
   > использованные материалы (окружение веба эфемерно).

## Troubleshooting

- **`Графики: 0/N (нет matplotlib)`** — `make install`, затем `make all` заново.
- **`Графики: K/N` (частично)** — один график не отрисовался: смотреть строку
  `[charts] … пропущены: <id>` в логе; проверить спецификацию этого графика
  валидатором (`make validate`). Код выхода будет `3`.
- **Код выхода `2` (фатально)** — битый JSON или не собрался Word: в логе
  понятная причина (строка/столбец JSON либо ошибка записи). Исправить данные/права.
- **Валидатор ругается на «уже был в прошлом отчёте»** — это дубли из истории;
  заменить материалы свежими и пересобрать.
- **Повторный прогон той же недели** — `week_start уже в history.weeks`. Для
  пересборки без двойной записи истории:
  ```bash
  python3 run_report.py --data data/week_$WEEK.json --no-history-update
  ```

## Откат (rollback)

Артефакты в `reports/` пересоздаются и не коммитятся — откатывать нечего.
Если запись в `data/history.json` оказалась лишней:

```bash
git checkout -- data/history.json     # вернуть закоммиченную версию
```

Затем пересобрать с `--no-history-update` для проверки, и только потом —
штатный прогон.
