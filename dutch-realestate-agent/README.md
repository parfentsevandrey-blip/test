# 🇳🇱 ИИ-агент: еженедельная аналитика рынка недвижимости Нидерландов

Агент раз в неделю собирает аналитику по рынку недвижимости Нидерландов в три
сегмента и формирует из неё **аккуратный файл Word**, который приходит **на
почту** (parfentsev.andrey@gmail.com).

Сегменты:
- 🏠 **Жилая недвижимость** — законы, новости, тренды, статистика
- 🏪 **Коммерция / стрит-ритейл** — то же самое
- 🏭 **Индустриал** — склады, промзоны, индустриальные и бизнес-парки

Принципы отчёта:
- простой язык, **вывод после каждого сегмента**;
- компактный объём (3–5 пунктов на подраздел);
- **строгий фильтр по датам** — только материалы за последнюю неделю;
- **без повторов** — дедупликация по `data/history.json`;
- **аналитика, а не лента**: на каждый пункт — «почему важно/что делать» с тегом
  влияния (▲ возможность · ▼ риск · ◆ структурный сдвиг);
- **читабельно и красиво**: заголовок недели, блок «Главные выводы», врезки «За чем
  следить», раздел «Картина недели и прогноз», «Словарь терминов».

«Мозг» агента (логика мышления, рамки анализа, редполитика) описан в
`agent_instructions.md`; принципы оформления — в `docs/design_spec.json`.

---

## Как это устроено

```
dutch-realestate-agent/
├── agent_instructions.md     ← промпт агента: что искать, как, в каком формате
├── sources.md                ← ИСТОЧНИКИ: ~200 шт. в 19 категориях (★/●/○)
├── schema.example.json       ← образец входного JSON
├── generate_report.py        ← рендер Word из JSON (+ дедупликация)
├── preview_html.py           ← HTML-превью отчёта (для браузера/телефона)
├── build_email.py            ← сборка тела письма (HTML + текст)
├── render_sources.py         ← рендер sources.md из таксономии
├── requirements.txt          ← зависимости (python-docx)
├── data/
│   ├── history.json          ← реестр прошлых материалов (антиповтор)
│   ├── sources.json          ← источники, машиночитаемо (для агента)
│   ├── sources_taxonomy.json ← полная таксономия источников
│   └── week_YYYY-MM-DD.json  ← данные конкретной недели
└── reports/
    └── YYYY-MM-DD_dutch_realestate_RU.docx
```

**Разделение ответственности:** ИИ (агент) делает исследование и пишет
текст в JSON; Python-скрипт детерминированно превращает JSON в красивый Word и
ведёт антиповтор. Так оформление всегда одинаковое и предсказуемое.

## Установка
```bash
pip install -r requirements.txt
```

## Запуск (раз в неделю, вручную)

В Claude Code на вебе откройте сессию в этом репозитории и дайте команду:

> «Запусти еженедельный отчёт по недвижимости Нидерландов»

Агент выполнит `agent_instructions.md`: найдёт новости за последнюю неделю,
проверит отсутствие повторов, соберёт JSON, сгенерирует Word и пришлёт его
на почту, затем закоммитит результат.

### Только рендер (если JSON уже готов вручную)
```bash
python3 generate_report.py \
  --data data/week_2026-06-30.json \
  --out  reports/2026-06-30_dutch_realestate_RU.docx \
  --history data/history.json
```
Скрипт:
- предупредит, если в данных есть материалы из прошлых отчётов (дубли);
- сохранит `.docx`;
- допишет `data/history.json`.

Флаг `--no-history-update` — собрать без записи в историю (для черновой проверки).

## Антиповтор (дедупликация)
`data/history.json` хранит ключи всех ранее использованных материалов
(нормализованный URL или хэш текста) с датой отчёта. Перед сборкой скрипт
сверяет новые данные с историей и подсвечивает повторы. Чтобы антиповтор
работал между неделями, **`data/history.json` нужно коммитить** в репозиторий
(окружение веба эфемерное — что не закоммичено, теряется).

## Доставка на почту
Тело письма готовит `build_email.py` (HTML c инлайн-стилями + плейн-текст) —
полный отчёт прямо в письме (читается на телефоне), плюс ссылка на файл `.docx`:
```bash
python3 build_email.py --data data/week_2026-06-28.json \
  --out-html reports/email.html --out-txt reports/email.txt \
  --file-link "<ссылка на Drive, опционально>"
```
Далее `.docx` загружается в Google Drive (для ссылки), и письмо
создаётся в Gmail на parfentsev.andrey@gmail.com. Вложения в черновики Gmail
сейчас не поддерживаются, поэтому сам файл идёт ссылкой на Drive; копия `.docx`
всегда лежит в `reports/` в репозитории.

> ⚠️ **Нужна авторизация коннекторов.** Отправка письма и загрузка в Drive
> работают только когда коннекторы **Gmail** и **Google Drive** авторизованы
> (claude.ai → настройки коннекторов). Если токен истёк, отчёт всё равно
> соберётся в `reports/`, но письмо не уйдёт, пока коннекторы не переподключить.

## Автоматизация по расписанию (опционально)
Сейчас запуск — ручной (по вашему выбору). Чтобы включить авто-режим
(например, каждый понедельник), создаётся cron-триггер, который раз в неделю
открывает сессию и выполняет `agent_instructions.md`. Скажите «включи
еженедельное расписание» — настрою.

## Настройка
- **Язык отчёта** — `language` в JSON и тексты в `generate_report.py`
  (по умолчанию русский).
- **Цвета/оформление** — палитра вверху `generate_report.py`.
- **Источники** — `sources.md`.
- **Глубина/объём** — правила в `agent_instructions.md` (пункты на подраздел).
