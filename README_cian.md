# Cian → Excel: выгрузка всех квартир ЖК

`cian_scraper.py` — CLI-скрипт: на вход ссылка на ЖК (или ID `newobject`), на выходе
`.xlsx` со всеми активными лотами, прямыми гиперссылками и сроком экспозиции.

## Установка

```bash
pip install -r requirements.txt
```

## Быстрый старт

### Вариант A — с вашим реальным запросом из DevTools (рекомендуется)

Циан отдаёт выдачу POST-запросом на `https://api.cian.ru/search-offers/v2/search-offers-desktop/`.
Доступ часто требует ваших браузерных cookie, а схема тела меняется. Поэтому самый
надёжный способ — отдать скрипту реальный запрос:

1. Откройте страницу ЖК на cian.ru.
2. DevTools (F12) → вкладка **Network** → фильтр **XHR** → найдите запрос
   `search-offers-desktop`.
3. ПКМ по нему → **Copy → Copy as cURL (bash)**.
4. Сохраните в файл, например `req.txt`.
5. Запустите:

```bash
python cian_scraper.py \
  --jk "https://www.cian.ru/zhiloy-kompleks-symphony-34-2515016/" \
  --curl-file req.txt
```

Скрипт возьмёт из вашего cURL **заголовки, cookie и тело `jsonQuery`** как есть и
будет подставлять только `newobject` / `page` / `room` / `price` — остальные поля
(`region`, `sort`, флаги) сохранятся ровно как в браузере.

### Вариант B — без cURL (встроенный шаблон запроса)

```bash
python cian_scraper.py --jk 2515016 --region 1
```

Использует встроенный шаблон `jsonQuery` по устоявшейся схеме. Если Циан вернёт
403/капчу — переходите на Вариант A (с cookie) или на `--playwright`.

### Офлайн-проверка пайплайна (без сети)

```bash
python cian_scraper.py --self-test
```

Прогоняет parse → расчёт → Excel на встроенных мок-данных, печатает первые 5 строк,
проверяет, что `₽/м²` считается верно, и пишет тестовый `cian_selftest_<дата>.xlsx`.

## Что в выходном файле

Книга `cian_<жк>_<ГГГГ-ММ-ДД>.xlsx`:

- **Сводка** — охват выгрузки, средняя `₽/м²` (частник vs застройщик), диапазоны цен.
  Всё — живые формулы по листу «Все_лоты».
- **Все_лоты** — все собранные лоты, отсортированы по `₽/м²` по возрастанию.
- **Студия / 1-комн / 2-комн / 3-комн / 4-комн / Своб_планировка** — те же лоты по категориям.

Колонки: № · ID объявления · Категория · Площадь, м² · Этаж · Этажность ·
Корпус/секция · Тип продавца · Продавец · **Отделка/ремонт** · **Источник отделки** ·
Цена, ₽ · Цена за м², ₽ (формула `=цена/площадь`) · Дата публикации ·
Срок экспозиции, дней · Дата обновления · **Описание** · Ссылка
(`Циан →`, кликабельная) · В расчёте.

В «Сводке» есть блок **ОТДЕЛКА / РЕМОНТ**: сколько лотов в каждой категории и
сколько из них определено полем Циан, а сколько — по тексту объявления.

Шапка жирная на тёмной заливке, автоширина, числовые форматы (`₽` — разделитель тысяч;
`₽/м²` — целое; площадь — 1 знак), закреплённая шапка, автофильтр.

## Почему именно API (а не парсинг HTML)

Публичные страницы Циан (`cat.php` / SEO-выдача) имеют два дефекта, из-за которых
выгрузка получается неполной и без прямых ссылок:

- **Лимит ~28 лотов на категорию** и игнор листания/фильтра/сортировки на публичных
  страницах → по факту собирается лишь часть лотов;
- **в карточках публичной выдачи часто нет ID объявления** → прямую ссылку на лот
  (`/sale/flat/ID/`) извлечь не удаётся, остаётся ссылка-фильтр на категорию.

JSON-API `search-offers-desktop` этих дефектов лишён: каждый оффер в
`offersSerialized` содержит **`cianId` и `fullUrl`** — то есть **прямую ссылку на
каждый лот**, а потолок — 784 на запрос. Поэтому ЖК на ~200 лотов забирается
**на 100% и с прямой ссылкой на каждую квартиру** за ~8 страниц. Скрипт использует
именно API и пишет `fullUrl` в колонку «Ссылка».

После сбора в лог выводится контроль охвата:
`Охват: собрано N из M (XX%); прямых ссылок на лот: K/N`, а в листе «Сводка»
появляется строка «Всего квартир в ЖК (Циан)» с процентом выгрузки.

## Режим «как человек» — реальный браузер (`--browser`)

Самый «человеческий» способ: открыть страницу ЖК в **настоящем Chromium** и собрать
данные **изнутри страницы**. Запросы к API уходят через `fetch` в origin `www.cian.ru`
с вашими cookie и тем же fingerprint, что у живого пользователя, поэтому антибот их
не отличает от обычного браузинга. Параллельно это переиспользует всю логику
пагинации/охвата (room-split, price-split, дедуп).

```bash
pip install playwright && playwright install chromium

# первый запуск — с окном, чтобы один раз пройти капчу руками:
python cian_scraper.py --jk 4927817 --jk-name "Среда на Кутузовском" \
    --browser --headful --browser-profile ./cian_profile

# дальше профиль помнит сессию — можно без окна:
python cian_scraper.py --jk 4927817 --jk-name "Среда на Кутузовском" \
    --browser --browser-profile ./cian_profile
```

Что делает режим: патчит признаки автоматизации (`navigator.webdriver` и пр.),
ставит локаль `ru-RU` / таймзону Москвы / десктопный размер окна, по-человечески
скроллит и держит паузы, при `--headful` ждёт ручного прохождения капчи
(`--captcha-wait`), затем постранично забирает `offersSerialized` через in-page API.

> Важно и честно: это работает **с вашей машины / незаблокированного IP**. Если IP
> в чёрном списке антибота (как у дата-центров/облака), даже реальный браузер не
> поможет — нужен чистый IP и живая сессия. Доп. опции: `--browser-exec PATH`
> (свой chromium в готовом окружении), `--proxy http://host:port`.

## Как пройти WAF Циан (антибот)

Циан закрыт WAF/антиботом (DataDome): без вашей сессии запрос с серверного IP
получает 403 (`cian_waf_block`). Решение — отдать скрипту **cookie из вашего
браузера**, где challenge уже пройден:

- `--curl-file req.txt` — «Copy as cURL» целиком (cookie + заголовки + тело), или
- `--cookie "k=v; k2=v2"` — только строку Cookie из вкладки заголовков запроса, плюс
  при желании `--user-agent "...ваш UA..."`.

Запускать нужно из сети/окружения, не заблокированного WAF (обычно — ваша машина).

## Обход лимита выдачи

Если в ЖК больше 784 лотов, Циан режет выдачу ~28 страницами × 28 лотов. Скрипт
обходит лимит:

- **room-split** (по умолчанию) — отдельные запросы по комнатности (студия / 1 / 2 / … / 6 /
  своб. планировка), что умножает «потолок» на число категорий;
- **price-split** (по умолчанию) — при упоре в потолок рекурсивно дробит диапазон цены
  пополам;
- **дедуп по `cianId`** — повторы между диапазонами/категориями отбрасываются.

Отключить: `--no-room-split`, `--no-split-price`.

## Антибан

- Реалистичные заголовки (десктопный User-Agent, Accept, Content-Type, Referer на ЖК),
  единая `requests.Session`.
- Случайная задержка между запросами (`--delay-min` / `--delay-max`, по умолчанию 2–5 с).
- Ретраи с экспоненциальным бэк-оффом на 429/403/5xx (`--retries`, `--backoff-base`).
- При жёстком блоке — `--playwright` (headless Chromium открывает страницу ЖК, скроллит,
  парсит карточки и ссылки из DOM). Требует `pip install playwright && playwright install chromium`.

## Важно про «Срок экспозиции»

Колонка считается как `сегодня − дата последней публикации` (`added`/`creationDate`, Unix).
Циан **сбрасывает дату при переподаче**, поэтому это «дни с последней подачи», а не
полный срок размещения. Отмечено в подзаголовке листа «Все_лоты» и в «Методике».

## Подтверждённая схема ответа (reverse engineering)

Маппинг полей сверен с реальными ответами `search-offers-desktop` (по открытым
парсерам, использующим этот API). Подтверждено:

| Данные | Путь в ответе |
|--------|---------------|
| список лотов | `data.offersSerialized[]` |
| всего лотов | `data.offerCount` |
| ID лота | `cianId` (и `id`) |
| **прямая ссылка** | `fullUrl` (`https://www.cian.ru/sale/flat/ID/`) |
| площадь | `totalArea` (строка) |
| комнат | `roomsCount`; тип — `flatType` |
| этаж / этажность | `floorNumber` / `building.floorsCount` |
| цена ₽ | `bargainTerms.priceRur` (и `bargainTerms.price`) |
| дата подачи | `addedTimestamp` (Unix, сек) |
| собственник | `isByHomeowner`; тип продавца — `user.userType` |

Тело запроса (jsonQuery): `_type=flatsale`, `region/terms`, `engine_version/term=2`,
`newobject/terms=[ID ЖК]`, `page/term`, `room/terms` с кодами **1..6 = комнаты,
9 = студия, 7 = своб. планировка**, `price/range {gte,lte}`, `sort/term`.

### Что может быть пустым (это нормально)

Эндпоинт-список `search-offers-desktop` **не отдаёт** часть полей — они есть только
на карточке самого объявления:

- **Дата обновления** — в списке отсутствует → пусто;
- **Корпус/секция** и **имя продавца** — зависят от наличия `newbuilding`/`user.name`.

**Отделка — отдельный случай.** Поле `decoration`/`repairType` в списочной выдаче
часто пустое, поэтому категория достраивается из **текста объявления** (`description`
приходит в списке целиком). Порядок такой:

1. поле Циан `repairType`, затем `decoration` → источник **«Циан-поле»**;
2. разбор текста объявления по ключевым словам → источник **«из описания»**;
3. ничего не нашлось → колонка пустая.

Колонка **«Источник отделки»** показывает, на что опирается категория, — по ней сразу
видно, доверять значению как факту от Циан или как догадке по тексту. Полный набор
категорий: Без отделки · Черновая · Предчистовая (white box) · Чистовая ·
Под ключ / с мебелью · Без ремонта · Косметический · Евроремонт · Дизайнерский ·
С ремонтом (тип не указан).

Разбор текста отсекает **чужой ремонт**: «ремонт подъезда», «дом после капремонта»,
«ремонт в соседнем корпусе», «рядом идёт ремонт», «сделаем ремонт под ваш вкус»,
«отделка за доплату» и т.п. не приписываются самой квартире.

Категория определяется по **полному** тексту объявления; в колонку «Описание»
попадают первые 600 знаков (дальше лист становится нечитаемым), полный текст —
по ссылке на объявление.

### Тесты

Правила классификатора — один и тот же блок (между маркерами `FIN-BLOCK-START` и
`FIN-BLOCK-END`) в трёх файлах: `extension/content.js`, `cian_browser.js` и
`cian_scraper.py`. Правите один — правьте все три:

```bash
node tests/check_finish.mjs      # блок совпадает в двух JS-файлах + корпус 129 кейсов
node tests/check_export.mjs      # книга cian_browser.js: колонки, Сводка, валидность XML
node tests/check_workbook.mjs    # книга расширения: снимок 34 листов + сборка zip
node tests/check_collect.mjs     # слой сбора: бюджет, дедуп, дробление, ретраи (18 сценариев)
node tests/check_collect_edges.mjs   # краевые случаи выдачи Циан (21 сценарий)
node tests/check_capture.mjs     # перехват jsonQuery со страницы
node tests/check_storage.mjs     # хранилище: отказ квоты, автобэкап, импорт бэкапа
python3 cian_scraper.py --self-test   # тот же корпус + мусорные данные + запись xlsx
```

Все возвращают ненулевой код при расхождении.

Тесты сбора гоняют НАСТОЯЩИЙ код расширения на подменённом `fetch` с виртуальными
часами: полный прогон — около двух секунд вместо часов реального ожидания. Кроме
инвариантов они печатают **сводку цены** каждого сценария (запросы, сегменты,
ретраи, виртуальное время) и список **известных дыр** (`△`) — задокументированных
дефектов слоя сбора, которые ещё не починены. Когда дыра закрывается, тест сам
сообщает об этом строкой «ДЫРА ЗАКРЫТА».

`NEGATIVE=1` есть у двух наборов — `check_collect.mjs` (снят бюджет по HTTP,
снят потолок по часам, отмена перестала замечаться, sleep снова непрерываемый,
сломан дедуп, снят выход по пустым страницам, снят лимит логических страниц) и
`check_storage.mjs` (вернули «`catch { /* ignore */ }`», маркер бэкапа переехал в
ключ истории, `backupDue` всегда молчит, импорт снова рапортует об успехе). В обоих
поломка вносится во ВРЕМЕННУЮ копию `content.js`, и тест обязан покраснеть с
ПРАВИЛЬНЫМ сообщением. Тест, который никогда не краснел, ничего не проверяет.

В регулярках классификатора
запрещены `\w`, `\b`, `\d` и lookbehind: в JS `\w` и `\b` работают только по ASCII
и на кириллице молча не срабатывают, а в Python — срабатывают, из-за чего один и
тот же лот получал бы разные категории в разных выгрузках.

Скрипт после сбора печатает **диагностику заполненности колонок**: видно сразу, какие
поля пусты «по делу» (опциональные) и какие — из-за смены схемы (критичные: `cianId`,
`url`, `area`, `price`, `category`). Если критичное поле пустое — сделайте
`--dump-json resp.json`, сверьте имена полей и поправьте маппинг в `*_of()` / `normalize()`.

### Стабильная пагинация

Чтобы границы страниц не «плавали» между запросами (иначе часть лотов теряется),
выдача сортируется стабильно — `--sort creation_date_desc` (по умолчанию). При
`--curl-file` сортировка берётся из вашего запроса.
