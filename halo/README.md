# Ореол (Halo)

Частная сеть из твоих устройств: телефона, ноутбуков, домашнего компьютера.
Без серверов, подписок, доменов и аккаунтов. Есть только код на твоих
устройствах и обычный интернет.

Каждое устройство идентифицируется своим ключом и получает постоянный адрес в
сети `100.64.0.0/10`, вычисленный из этого ключа. IP-пакеты между устройствами
идут напрямую в QUIC-датаграммах поверх [iroh](https://www.iroh.computer):
шифрование TLS 1.3, взаимная проверка ключей, пробивка NAT.

## Статус: этап 0 — ядро и туннель

Что уже работает (проверено на Linux):

- **Без серверов.** Relay и сервисы обнаружения iroh выключены, устройства
  соединяются только напрямую друг с другом.
- **Ключ вместо аккаунта.** Пара ключей Ed25519 создаётся на устройстве и хранится
  в файле с правами только для владельца. Адрес в сети вычисляется из ключа,
  поэтому все устройства знают адреса друг друга без координации.
- **Только свои.** Ключ, которого нет в списке участников, отклоняется сразу после
  TLS-рукопожатия. Участник может слать пакеты только со своего адреса и только
  нам; остальное отбрасывается.
- **Туннель на датаграммах.** Пакеты идут в QUIC-датаграммах, а не в потоках:
  надёжность обеспечивает TCP внутри, поэтому при потерях соединение не встаёт.
  Если путь уже, чем MTU туннеля, пакет режется на фрагменты и собирается на
  другой стороне.
- **Устойчивые соединения.** Если оба устройства звонят друг другу одновременно,
  они сходятся к одному соединению. Перезапуск или падение узла переживаются:
  соединение поднимается заново.
- **Без туннеля в туннеле.** iroh сообщает участникам все локальные адреса,
  включая адрес самого туннеля, и пробует проложить путь через него. Пакеты
  транспорта, попавшие в туннель, отбрасываются, и такой путь не проходит
  проверку. В тестах это ~40 попыток за прогон.

## Быстрый старт: два компьютера в одной сети

```sh
cargo build --release

# на каждом устройстве: создать ключ и узнать свой id и адрес в сети
./target/release/halo id

# устройство A (нужны права root / администратора для TUN)
sudo ./target/release/halo up --peer <ID_B>@<IP_B_в_локальной_сети>:7777

# устройство B
sudo ./target/release/halo up --peer <ID_A>@<IP_A_в_локальной_сети>:7777

# с A
ping <адрес_B_в_сети_Ореола>
```

`--peer` можно указать несколько раз. Адрес можно опустить (`--peer <ID>`), тогда
устройство ждёт, пока участник позвонит само. Ключ хранится в каталоге настроек
платформы (`~/.config/halo` на Linux), другой каталог задаётся через
`--state-dir` или `HALO_STATE_DIR`. Счётчики трафика выводит `--stats <секунды>`.

## Тесты

```sh
cargo test                      # кадры, фрагментация, адреса
cargo build && sudo scripts/netns-test.sh
```

`netns-test.sh` поднимает три узла в сетевых неймспейсах Linux на виртуальном
коммутаторе и проверяет:

- пинг в обе стороны и полноразмерные пакеты 1280 байт с запретом фрагментации;
- скорость через iperf3;
- что устройство не из сети не может достучаться;
- восстановление после штатного перезапуска и после падения узла (`kill -9`).

Набор запускается дважды: на каналах с MTU 1500 и на «узких» каналах с MTU 1300,
где полноразмерный пакет туннеля не помещается в одну датаграмму и обязан
фрагментироваться.

Результаты в контейнере (release-сборка, один поток iperf3, TCP). Все узлы на
одной машине, так что это верхняя граница ядра, а не обещание для телефона:

| Канал | Пинг через туннель | Скорость | Фрагментация |
|---|---|---|---|
| MTU 1500 | ~0,8 мс | 1,14 Гбит/с | нет |
| MTU 1300 | ~0,8 мс | 567 Мбит/с | каждый полноразмерный пакет |

## Устройство

```
crates/
  halo-core/          ядро: общее для десктопа и Android
    src/addr.rs       адрес в сети из ключа
    src/frame.rs      формат датаграмм, фрагментация и сборка
    src/node.rs       узел: TUN, соединения с участниками, проверки
  halo-cli/           CLI `halo` для Linux, macOS и Windows
scripts/
  netns-test.sh       сквозной тест в сетевых неймспейсах
```

Протокол: ALPN `halo/0`. Каждая датаграмма начинается с байта-тега:

- `0` — дальше целый IP-пакет;
- `1` — фрагмент: `id` (u16, big endian), номер (u8), всего фрагментов (u8), данные.

## Ограничения этапа 0

- Участники и их адреса задаются вручную, поиска пока нет. Соединение
  устанавливается, если хотя бы одна сторона достижима: одна локальная сеть,
  белый IP или проброшенный порт.
- Внутри туннеля пока только IPv4.
- Туннель забирает маршрут на весь `100.64.0.0/10`.
- Проверено только на Linux.
