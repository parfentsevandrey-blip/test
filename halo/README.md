# Ореол (Halo)

Частная сеть из твоих устройств: телефона, ноутбуков, домашнего компьютера.
Без серверов, подписок, доменов и аккаунтов. Есть только код на твоих
устройствах и обычный интернет.

Каждое устройство идентифицируется своим ключом и получает постоянный адрес в
сети `100.64.0.0/10`, вычисленный из этого ключа. IP-пакеты между устройствами
идут напрямую в QUIC-датаграммах поверх [iroh](https://www.iroh.computer):
шифрование TLS 1.3, взаимная проверка ключей, пробивка NAT.

## Статус

**Этап 1, в работе:** CLI `halo` для macOS, Windows и Linux и приложение для
Android, список участников, поиск устройств в локальной сети. Сборки для всех
систем делает CI (см. ниже). Сквозные тесты гоняются на Linux и на эмуляторе
Android.

Что уже работает:

- **Без серверов.** Relay и интернет-поиск iroh выключены. Устройства соединяются
  напрямую: по адресам, которые ты указал, или находят друг друга в локальной
  сети через mDNS (сервис `_halo._udp.local`).
- **Ключ вместо аккаунта.** Ключ Ed25519 принадлежит устройству и лежит в
  системном каталоге, доступном только root / администраторам. Адрес в сети
  вычисляется из ключа, поэтому все устройства знают адреса друг друга без
  координации.
- **Сопряжение одним сканом.** `halo pair` показывает QR-код. Телефон сканирует его
  (или другой компьютер вставляет текст кода), оба экрана показывают четыре
  эмодзи, и после подтверждения на обоих устройства добавляют друг друга. Код
  одноразовый, эмодзи ловят подмену, отмена на любом шаге ничего не добавляет.
- **Только свои.** Ключ, которого нет в списке участников, отклоняется сразу после
  TLS-рукопожатия. Участник может слать пакеты только со своего адреса и только
  нам; остальное отбрасывается.
- **Туннель на датаграммах.** Пакеты идут в QUIC-датаграммах, а не в потоках:
  надёжность обеспечивает TCP внутри, поэтому при потерях соединение не встаёт.
  Если путь уже, чем MTU туннеля, пакет режется на фрагменты и собирается на
  другой стороне.
- **Устойчивые соединения.** Если оба устройства звонят друг другу одновременно,
  они сходятся к одному соединению. Перезапуск или падение узла переживаются, а
  появление участника в локальной сети сразу будит дозвон.
- **Без туннеля в туннеле.** iroh сообщает участникам все локальные адреса,
  включая адрес самого туннеля, и пробует проложить путь через него. Пакеты
  транспорта, попавшие в туннель, отбрасываются, такой путь не проходит
  проверку, а в mDNS адрес туннеля не публикуется.

## MacBook + Windows-ноутбук в одной Wi-Fi

### 1. Скачать сборки

GitHub → вкладка **Actions** → workflow **halo** → последний зелёный запуск →
блок **Artifacts** (нужно войти в GitHub):

- `halo-macos-universal`: zip, внутри `halo-macos.tar.gz`, работает на Apple
  Silicon и Intel. Сам бинарник лежит в tar, потому что zip-архивы GitHub теряют
  флаг «исполняемый»;
- `halo-windows-x64`: zip с `halo.exe` и `wintun.dll`, их нужно держать в одной
  папке.

Или собрать самому: `cargo build --release` в каталоге `halo/`
(нужен [Rust](https://rustup.rs)). На Windows `wintun.dll` берётся с
[wintun.net](https://www.wintun.net) (папка `bin/amd64`).

### 2. Подготовить

macOS, в Терминале, в папке со скачанным zip:

```sh
unzip halo-macos-universal.zip && tar -xzf halo-macos.tar.gz
xattr -d com.apple.quarantine halo 2>/dev/null   # снять карантин Gatekeeper
sudo ./halo id
```

Windows: распакуй zip, затем в PowerShell **от имени администратора**, в папке с
`halo.exe`:

```powershell
Unblock-File .\halo.exe, .\wintun.dll            # снять пометку «скачано из интернета»
.\halo.exe id
```

`halo id` создаёт ключ устройства при первом запуске и печатает его `id` и адрес
в сети Ореола.

### 3. Познакомить устройства

Сопряжение: одно действие, и устройства добавляют друг друга сами. На MacBook:

```sh
sudo ./halo pair
```

Он покажет QR-код (для телефона) и текстовый код вида `HALO/1/...`. На Windows
вставь этот код:

```powershell
.\halo.exe pair --join HALO/1/...
```

Оба ноутбука покажут по четыре эмодзи. Если они совпадают, ответь `y` на обоих:
каждый добавит другого под его именем (`macbook-pro`, `desktop-...`) и запомнит
его адрес в локальной сети. Код одноразовый, а эмодзи защищают от подмены: если
код утёк и подключился кто-то другой, эмодзи не совпадут. Ctrl+C на любом шаге
отменяет сопряжение на обоих устройствах.

Можно и вручную: `halo id` на одном устройстве, `halo add <ID> --name <имя>` на
другом, и так в обе стороны. Адреса указывать не нужно: в одной сети
устройства найдут друг друга сами. Для устройства в другой сети адрес задаётся
через `--addr ip:port`.

### 4. Разрешить входящие на Windows

Брандмауэр Windows по умолчанию режет входящие, в том числе пинг. Один раз, в
PowerShell от администратора:

```powershell
New-NetFirewallRule -DisplayName "Halo transport" -Direction Inbound -Program "$PWD\halo.exe" -Action Allow
New-NetFirewallRule -DisplayName "Halo network" -Direction Inbound -InterfaceAlias Halo -RemoteAddress 100.64.0.0/10 -Action Allow
```

Первое правило пропускает зашифрованный трафик и mDNS к `halo.exe`. Второе
пропускает трафик внутри сети Ореола и только от адресов Ореола. На macOS, если
включён брандмауэр, при первом запуске появится вопрос про входящие подключения
для `halo`: ответь «Разрешить».

### 5. Запустить

```sh
sudo ./halo up          # macOS
```

```powershell
.\halo.exe up           # Windows
```

В логе появится `connected` с адресом в локальной сети. Проверка:

```sh
ping <адрес_Windows_в_Ореоле>     # с MacBook
```

```powershell
ping <адрес_MacBook_в_Ореоле>     # с Windows
```

Остановка: Ctrl+C. Другие команды: `halo members` (список устройств),
`halo remove <имя>`, `halo up --stats 5` (счётчики трафика),
`halo up --no-lan` (без mDNS). Ключ и список участников хранятся в
`/Library/Application Support/Halo` (macOS), `C:\ProgramData\Halo` (Windows) и
`/var/lib/halo` (Linux). Другой каталог: `--state-dir` или `HALO_STATE_DIR`.

## Телефон на Android

1. Скачай артефакт `halo-android-apk` из того же запуска CI, распакуй zip и
   установи `app-debug.apk`. Android попросит разрешить установку из этого
   источника. Это отладочная сборка, подписанная тестовым ключом; подписанный
   релиз будет позже.
2. На ноутбуке: `sudo ./halo pair` (на Windows `.\halo.exe pair`). Появится
   QR-код.
3. В приложении: «Добавить устройство» → «Сканировать QR» и наведи камеру на
   экран ноутбука. Оба устройства покажут четыре эмодзи; если совпадают, нажми
   «Совпадают» на телефоне и ответь `y` на ноутбуке. Каждое добавит другое, а
   телефон заодно запомнит адрес ноутбука из кода. «Отмена» и «Не совпадают»
   прерывают сопряжение и на ноутбуке.
4. Перезапусти `halo up` на ноутбуке и нажми на кольцо в приложении. Android
   один раз спросит разрешение на VPN. Когда ноутбук найдётся, рядом с ним
   появится «напрямую 192.168.x.x:7777 · N мс».

Без камеры: «Вставить код» принимает текстовый код `HALO/1/...` из вывода
`halo pair`, например присланный себе в мессенджер. Можно и вручную по ID:
«Поделиться» отправляет ID телефона вместе с готовой командой `halo add` для
ноутбука.

В туннель идут только адреса твоих устройств. Остальной трафик телефона его не
касается, и само приложение из VPN исключено. Ключ устройства хранится в личных
файлах приложения, а облачные бэкапы и перенос на другое устройство для них
выключены.

Сборка у себя: нужны Rust, `cargo-ndk`, Android SDK и NDK 29. Затем
`cd android && ./gradlew assembleDebug`. Gradle сам соберёт Rust-ядро и
Kotlin-привязки. `-PhaloAbis=x86_64` собирает только под эмулятор.

## Тесты

```sh
cargo test                      # кадры, адреса, участники, сопряжение, привязки
cargo build && sudo scripts/netns-test.sh
```

`cargo test` сопрягает устройства через loopback: совпадение эмодзи, отказ,
неверный код, уход одной стороны, отмена на телефоне во время подключения и во
время ожидания ответа.

`netns-test.sh` поднимает три узла в сетевых неймспейсах Linux на виртуальном
коммутаторе и проверяет:

- пинг в обе стороны и полноразмерные пакеты 1280 байт с запретом фрагментации;
- скорость через iperf3;
- что устройство не из сети не может достучаться;
- восстановление после штатного перезапуска и после падения узла (`kill -9`).

Набор запускается трижды: участники с адресами на каналах с MTU 1500; то же на
«узких» каналах с MTU 1300, где полноразмерный пакет туннеля не помещается в
одну датаграмму и обязан фрагментироваться; участники только по `id`, без единого
адреса, когда узлы находят друг друга через mDNS.

CI (`.github/workflows/halo.yml`) на каждый push: rustfmt, clippy и юнит-тесты на
Linux, macOS и Windows; сквозной тест на Linux; сборки для всех трёх систем;
APK, Android Lint и сквозной тест на эмуляторе Android
(`scripts/android-e2e.sh`): телефон сопрягается с узлом на машине CI по коду,
проходит системный диалог согласия на VPN и пингует узел через туннель, а узел —
телефон.

Результаты в контейнере (release-сборка, один поток iperf3, TCP). Все узлы на
одной машине, так что это верхняя граница ядра, а не обещание для телефона:

| Канал | Пинг через туннель | Скорость | Фрагментация |
|---|---|---|---|
| MTU 1500 | ~0,8 мс | 1,14 Гбит/с | нет |
| MTU 1300 | ~0,8 мс | 567 Мбит/с | каждый полноразмерный пакет |

## Устройство

```
crates/
  halo-core/          ядро: общее для десктопа и Android
    src/addr.rs       адрес в сети из ключа
    src/frame.rs      формат датаграмм, фрагментация и сборка
    src/node.rs       узел: TUN, соединения с участниками, mDNS, проверки
    src/members.rs    список участников
    src/state.rs      каталог с ключом и списком
    src/pair.rs       сопряжение: код, доказательство знания секрета, эмодзи
  halo-cli/           CLI `halo` для Linux, macOS и Windows
  halo-ffi/           привязки к Kotlin через UniFFI
android/              приложение: VpnService, Compose, сканер QR
scripts/
  netns-test.sh       сквозной тест в сетевых неймспейсах
  android-e2e.sh      сквозной тест на эмуляторе Android
  build-android-rust.sh  ядро под Android и Kotlin-привязки (зовёт Gradle)
```

Протокол: ALPN `halo/0`. Каждая датаграмма начинается с байта-тега:

- `0` — дальше целый IP-пакет;
- `1` — фрагмент: `id` (u16, big endian), номер (u8), всего фрагментов (u8), данные.

Сопряжение: ALPN `halo/pair/0`, отдельный порт. Код `HALO/1/<ID>/<СЕКРЕТ>/<адреса>`
несёт ключ показывающего устройства, одноразовый 128-битный секрет и его адреса в
локальной сети. Сканирующее устройство подключается к этому ключу и доказывает
знание секрета: BLAKE3 с ключом из секрета от обоих ключей устройств. Затем
стороны обмениваются именами и портами узлов. Четыре эмодзи (24 бита) берутся из
экспортёра TLS этого соединения: при подмене посредником они разойдутся. Каждая
сторона отправляет «да» или «нет»; устройство добавляется, только если обе
сказали «да» и свой ответ дошёл до другой стороны. Уход или отмена на любом шаге
означают «нет» для обеих.

## Ограничения сейчас

- Устройства в разных сетях соединяются, только если хотя бы одно достижимо
  напрямую: белый IP или проброшенный порт (`--addr`). Поиск через интернет без
  серверов — этап 2.
- mDNS публикует `id` устройства в локальной сети: соседи по Wi-Fi видят, что
  в сети есть устройство Ореола (но не могут к нему подключиться).
- Внутри туннеля пока только IPv4.
- Туннель забирает маршрут на весь `100.64.0.0/10`.
- macOS и Windows собираются и проходят юнит-тесты в CI; сквозные тесты есть
  на Linux и на эмуляторе Android.
- APK пока отладочный, подписан тестовым ключом.
