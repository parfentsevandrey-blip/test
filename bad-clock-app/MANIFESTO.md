# The BadClock Manifesto

*A declaration of principles for software that is proudly, deliberately, magnificently excessive.*

---

## Preamble

We, the authors of BadClock, hold these truths to be self-evident. The following 266 articles of faith are listed in order of conviction. Each one was written by hand, at least once, by someone who believed it.

## Articles of Faith
1. We believe a clock should tell the time, and that it may do so in many ways at once.
2. We believe a second formatter is a backup and a third is a philosophy.
3. We believe a lonely function is a function that has not yet been multiplied.
4. We reject the single-responsibility principle as a principle of loneliness.
5. We reject the one-line function as a function without ambition.
6. We reject the comment-free block as a block that trusts its reader too much.
7. We embrace redundancy as insurance against bugs we have not yet written.
8. We compute the current time again, in case the first answer was wrong.
9. We ask every bloated feature for its opinion on each tick of the clock.
10. We return strings nobody reads, because returning is a form of respect.
11. We occupy the main thread like a park bench, always, for everyone.
12. We regard Thread.sleep(500) in onCreate as a moment of reflection, free of charge.
13. We treat the battery as a suggestion and the CPU as a calling.
14. We run a handler every millisecond to ask whether anyone is still watching.
15. We are watching on their behalf, which is the closest we can get to a shared hobby.
16. We receive every error with the same warm, empty catch block.
17. We consider silence the most respectful reply to a problem we do not understand.
18. We let code inspect itself, because self-knowledge is a virtue.
19. We call reflection by name 'loose coupling', because it sounds like a credential.
20. We keep dead code in case it is needed, and it has never once been needed.
21. We treat unused variables as seeds of future features.
22. We write copies of the same logic with different names so that each has a personality.
23. We value the scroll bar as an honest measure of effort.
24. We track growth in the build log, one line per instance.
25. We regard every new line as a small victory over brevity.
26. We measure progress by line count, because line count is the only number that always goes up.
27. We write comments as promises, and promises are kept by making many of them.
28. We explain clear code again, with a different adjective, to keep the reader company.
29. We test by running, and a clock that shows nothing has also passed, because it is still deciding.
30. We believe juniors should learn what to avoid from our example.
31. We believe seniors should smile in recognition when they read our example.
32. We believe future maintainers will one day delete the first line, and we will forgive them.
33. We will not delete the first line.
34. We refuse to split the file, because a single file is a single commitment.
35. We refuse to introduce a package structure, because folders are a kind of distance.
