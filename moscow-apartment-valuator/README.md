# Moscow Apartment Valuator (mav)

Находит недооценённые квартиры в современных московских жилых комплексах
(сдан в 2019 году или позже) на основе экспортированных данных с cian.ru:
сравнивает каждый лот с аналогами в том же ЖК и считает, насколько его
цена за м² ниже медианы по сопоставимым квартирам.

**Прочитайте раздел ["Про cian.ru: почему это не просто `pip install
scraper`"](#про-cianru-почему-это-не-просто-pip-install-scraper) прежде
чем ожидать, что скрипт сам сходит на сайт и всё скачает.**

## Быстрый старт

```bash
cd moscow-apartment-valuator
pip install -r requirements.txt
python -m mav --input examples/sample_offers.json
```

Это посчитает вердикты по демонстрационному набору из 15 лотов (файл
`examples/sample_offers.json`) и напечатает Markdown-отчёт по
недооценённым лотам.

Свои данные: подготовьте `.json` или `.csv` со своими лотами в том же
формате (см. раздел "Формат входных данных") и укажите его через
`--input`.

```bash
python -m mav --input my_listings.json --config config.yaml --format csv --out deals.csv
```

## Как это устроено

```
mav/
  models.py              Offer - нормализованная схема одного лота
  config.py               пороги и веса (из config.example.yaml)
  providers/
    file_import.py         основной источник данных: импорт JSON/CSV
    cian_http.py            experimental, opt-in, best-effort live-фетчер
  valuation/
    comparables.py          подбор сопоставимых лотов (та же ЖК/комнатность/площадь/этаж)
    scoring.py               система критериев недооценённости (см. ниже)
  pipeline.py               фильтрация по рынку + скоринг + сортировка
  report.py                 рендер в Markdown/CSV
  cli.py                    `python -m mav ...`
tests/                     pytest-тесты на всю логику скоринга
examples/sample_offers.json  демонстрационный набор для быстрого старта и тестов
```

Валюационный движок никогда не обращается к источнику данных напрямую —
он работает только с объектами `Offer`. Поэтому вся система критериев
полностью протестирована на детерминированных данных (`tests/`) и не
зависит от того, как именно эти данные попали в систему.

## Система отбора критериев: когда лот считается недооценённым

1. **Область поиска (`market`)** — только Москва, только продажа квартир,
   только ЖК, сданные не раньше `min_built_year` (по умолчанию 2019).
   Лот без известного года сдачи ЖК в выборку не попадает: без этого
   поля нельзя проверить условие задачи.

2. **Подбор аналогов (`comparables.py`)** — сравнивать лот можно только
   с реальными аналогами, иначе "недооценённость" ничего не значит:
   - **Tier A (основной):** тот же ЖК + то же число комнат (или студия) +
     площадь в пределах `± area_tolerance_pct` (по умолчанию 20%) от
     площади лота. Если позволяет размер выборки, дополнительно
     разделяются первый/последний этаж и "средние" этажи
     (`floor_bucket`), и, при `finish_type_strict`, тип отделки.
   - **Tier B (запасной):** если по Tier A наберётся меньше
     `min_comparables` (по умолчанию 4) лотов — берётся весь ЖК целиком,
     без учёта комнатности, но с понижающим коэффициентом уверенности.
   - Если и в Tier B меньше `min_comparables` лотов — вердикт
     `insufficient_data`: система намеренно ничего не утверждает про
     лот, если сравнивать не с чем.
   - Медиана и разброс (`price/m²`) считаются робастно — через медиану
     и MAD (median absolute deviation), а не среднее и стандартное
     отклонение, чтобы один "убитый" или, наоборот, аномально дорогой
     лот в выборке не искажал базовую цену.

3. **Скоринг (`scoring.py`)**:
   - `discount_pct` = (медиана `₽/м²` по аналогам − `₽/м²` лота) / медиана × 100.
   - `confidence` = `min(1, n_аналогов / target_comparables)`, дополнительно
     × 0.7 для Tier B. Чем меньше аналогов, тем меньше система доверяет
     собственному выводу.
   - `score` = `discount_pct × confidence` — итоговая величина, по
     которой лоты сортируются.
   - **Проверка на правдоподобность:** если `discount_pct` превышает
     `max_plausible_discount_pct` (по умолчанию 45%), лот получает
     вердикт `suspicious`, а не "супер-сделка". Настолько большая
     скидка гораздо вероятнее означает ошибку в данных, обременение,
     долю в праве, судебный спор, продажу между связанными лицами или
     иную скрытую причину, чем настоящую недооценённость — это нужно
     проверять вручную, а не покупать не глядя.
   - **Вердикты**, по порядку приоритета в отчёте: `strong_undervalued`
     (score ≥ 15) → `undervalued` (score ≥ 8) → `overvalued` (score ≤ −8,
     в отчёт не попадает) → `suspicious` (не важно какой score — просто
     флаг "проверить вручную") → `fair` (в отчёт не попадает).
     `suspicious`-лоты в отчёте всегда идут **после** подтверждённых
     сделок, даже если их номинальная скидка больше — большая скидка
     это как раз то, что делает их подозрительными, а не убедительными.
   - Свежие объявления (опубликованы ≤ `fresh_listing_days` дней назад)
     помечаются как "(новое)" и идут выше при прочих равных — только
     что выставленный недооценённый лот более actionable, чем тот же
     дисконт, провисевший месяцами (возможен скрытый дефект, из-за
     которого лот никто не берёт).

Все пороги настраиваются в `config.yaml` (см. `config.example.yaml`) —
ничего не зашито в код.

## Формат входных данных

`.json` — список объектов, `.csv` — те же поля колонками. Обязательные
поля: `id, url, city, price, area_total, rooms`. Из них `residential_complex`
и `built_year` не обязательны формально, но без них лот не пройдёт
фильтр по ЖК/году постройки и никогда не наберёт аналогов. Остальные
поля опциональны: `is_studio, address, district, metro, floor,
floors_total, area_living, area_kitchen, finish_type_raw, seller_type,
deal_type, accommodation_type, listed_at, updated_at` (даты — `YYYY-MM-DD`).

Пример одного лота — см. `examples/sample_offers.json`.

## Откуда брать данные для `--input`

Это осознанно оставлено вам (см. раздел ниже про cian.ru), но практические варианты:

- Вручную скопировать интересующие объявления с cian.ru в CSV/JSON —
  надёжно, законно, работает всегда, но не масштабируется на сотни лотов.
- Прогнать `mav/providers/cian_http.py` (experimental, opt-in,
  см. предупреждения в самом файле) с домашнего IP, вручную, с большими
  паузами — может не заработать вообще, но если ищете только под свою
  задачу и понимаете риски — это встроенный вариант.
- Если вы риэлторское агентство или у вас есть доступ к официальному
  Циан API (`import@cian.ru`, https://promo.cian.site/api) — это
  единственный полностью легитимный путь к программному доступу, но он
  рассчитан на управление своими объявлениями/лидами, а не на выгрузку
  чужих лотов целиком.

## Про cian.ru: почему это не просто `pip install scraper`

Перед тем как писать этот инструмент, мы проверили прямой доступ к
cian.ru с сервера: даже запрос `/robots.txt` вернул не сам файл, а
антибот-страницу блокировки (`cian_waf_block`, "Обнаружен подозрительный
трафик"). То есть cian.ru активно блокирует автоматический/дата-центровый
трафик — это не гипотетический риск, а воспроизводимый факт.

Дополнительно (см. `mav/providers/cian_http.py` за деталями):

- Правила пользования сайтом cian.ru, по всей видимости, требуют
  отдельного разрешения администрации на сбор данных автоматическими
  средствами — точную формулировку не удалось подтвердить напрямую
  (сама страница правил тоже блокируется антиботом), но это
  последовательно подтверждается вторичными источниками.
- Официальный "Циан API" существует, но выдаётся агентствам недвижимости
  для управления *своими* объявлениями/лидами/звонками, а не для
  массовой выгрузки чужих лотов сторонним разработчиком.
- Открытый парсер `cianparser` (github.com/lenarsaitov/cianparser)
  документирует необходимость обхода Cloudflare, паузы 4–5 секунд между
  запросами и подбор рабочих прокси — то есть даже у зрелого,
  специально заточенного под это open-source проекта это тяжело и
  нестабильно.
- Российская судебная практика по парсингу агрегаторов (VK v. Double
  Data, споры вокруг HeadHunter, Avito v. Auto.ru) неоднородна и не
  даёт однозначной гарантии безопасности систематического парсинга —
  но и не значит, что любое обращение к сайту автоматически незаконно.
  Это не юридическая консультация; если планируете что-то за пределами
  личного разового использования — проконсультируйтесь с юристом.

Поэтому `cian_http.py`:

- **выключен по умолчанию** — требует явного `i_accept_tos_risk=True`;
- не притворяется браузером, не ротирует прокси/IP, не решает капчи и
  не пытается обходить блокировку — если cian.ru ответил блокировкой,
  клиент останавливается, а не изобретает способ обойти;
- держит консервативную паузу между запросами (≥ 5 секунд по умолчанию)
  и явно документирует, что рассчитан на редкое личное использование.

Если он у вас не заработает — это ожидаемо, а не баг. Надёжный путь —
`FileImportProvider` с данными, которые вы получили сами (см. выше).

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

26 тестов покрывают подбор аналогов, робастную статистику, все вердикты
скоринга (включая `suspicious` и `insufficient_data`), сортировку и
импорт JSON/CSV — независимо от того, доступен ли cian.ru в момент
запуска.
