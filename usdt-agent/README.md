# usdt-agent — автономный маркет-нейтральный агент для заработка USDT

Агент, который сам ищет, оценивает и исполняет способы заработать USDT: пять
дельта-нейтральных стратегий, байесовский аллокатор капитала, риск-губернатор с
правом вето и **статистический шлюз**, который не пускает стратегию к реальным
деньгам, пока она не докажет своё преимущество.

Ноль зависимостей — только Python 3.11+. По умолчанию торгует на бумаге.

```bash
cd usdt-agent
make test        # 99 тестов, интернет не нужен
make scan        # что прямо сейчас есть на рынке
make backtest    # быстрый прогон по симулятору
make run         # бумажная торговля по живым данным
```

---

## Главная мысль

Большинство «ботов для заработка» устроены наоборот: сначала обещают доходность,
потом подгоняют под неё бэктест. Здесь порядок обратный — **агент по умолчанию
считает, что не умеет зарабатывать**, и обязан это опровергнуть на собственной
истории сделок, прежде чем получит хоть один реальный USDT.

Три механизма, которые это обеспечивают:

| Механизм | Что делает |
| --- | --- |
| **Статистический шлюз** (`statistics.py`) | Bootstrap-тест + Deflated Sharpe с поправкой на множественное тестирование. Пока `p >= 0.05` — стратегия в режиме `live` не получает капитала вообще. |
| **Риск-губернатор** (`risk.py`) | Ни одна стратегия не определяет свой размер. Каждый тикет проходит через `approve()`, который его урезает или отклоняет с указанием причины. |
| **Хеш-цепочка в журнале** (`ledger.py`) | Каждая запись хранит `sha256(prev_hash ‖ payload)`. Задним числом подправить историю нельзя — `verify()` покажет точный номер сломанной записи. |

Плюс честная модель издержек: комиссия, половина спреда, проскальзывание от
глубины стакана (√-импакт), задержка и **adverse selection**. Именно эти четыре
слагаемых обычно и превращают «прибыльный бэктест» в убыточного бота.

## Стратегии

Все, кроме последней, — маркет-нейтральные: они зарабатывают на спреде,
фандинге и проценте, а не на угадывании направления.

| Стратегия | Механика | Откуда доход | Риск |
| --- | --- | --- | --- |
| `funding_carry` | лонг спот + шорт перп на одной бирже | ставка финансирования, которую лонги платят шортам раз в 8 ч | базис-риск, разворот фандинга |
| `cross_venue` | купить дёшево на одной бирже, продать дорого на другой | расхождение котировок между площадками | исполнение, нужен предзаведённый баланс |
| `triangular` | цикл USDT → A → B → USDT внутри одной биржи | рассогласование кросс-курса и синтетического | 3 ноги — 3 шанса на частичное исполнение |
| `stable_yield` | размещение свободного USDT в лендинг-пулы | процент по стейблкоинам, ранжирование по **risk-adjusted** APY | смарт-контракты, депег, обвал APY |
| `grid` | покупка просадок пегованной пары (USDC/USDT) | возврат к среднему | **единственная направленная**: реально может терять |

`grid` включён намеренно и с минимальным весом: аллокатору нужна хотя бы одна
рука, которая умеет проигрывать, иначе ему нечему учиться.

### Аллокатор капитала — Thompson sampling

Агент не знает заранее, какая стратегия сработает на *ваших* биржах, парах и
комиссиях. Поэтому каждая стратегия — рука многорукого бандита с нормальным
апостериорным распределением на среднюю доходность сделки (в б.п.):

- наблюдения взвешиваются по свежести (`memory_halflife_trades = 40`), поэтому
  умерший арбитраж перестаёт получать деньги, а не финансируется вечно;
- каждый цикл каждая рука тянет один сэмпл из своего апостериора, положительные
  нормируются в доли;
- `exploration_floor = 0.05` не даёт временно неудачливой руке умереть совсем.

## Команды

```bash
python3 -m usdt_agent [-c config/agent.toml] <команда>
```

| Команда | Что делает |
| --- | --- |
| `run` | основной цикл; `--cycles`, `--interval`, `--source`, `--live`, `--arm` |
| `scan` | однократно показать все идеи, уже за вычетом издержек |
| `backtest` | быстрый прогон по детерминированному симулятору |
| `report` | markdown/json-отчёт из журнала (`--json`, `-o file`) |
| `verify` | проверить хеш-цепочку журнала |
| `doctor` | связность бирж, валидность конфига, состояние блокировок live |
| `strategies` | список стратегий и их параметров |

`doctor` — первое, что стоит запустить: он честно скажет, какие биржи доступны
из вашей сети (Binance и Bybit блокируют часть регионов) и каких блокировок
не хватает для реальной торговли.

## Реальная торговля

Чтобы отправить хотя бы один настоящий ордер, должны совпасть **четыре**
независимых условия:

1. `mode = "live"` в конфиге (или флаг `--live`);
2. `export USDT_AGENT_LIVE_CONFIRM=I_UNDERSTAND_THE_RISK`;
3. в окружении лежат `BINANCE_API_KEY` и `BINANCE_API_SECRET`
   (ключи читаются **только** из окружения и никогда не логируются);
4. стратегия прошла статистический шлюз, а ордер укладывается в `--max-order`.

И даже тогда по умолчанию включён `--dry-run`: ордера пишутся в лог, но не
уходят на биржу. Настоящая отправка — только с явным `--arm`.

```bash
# посмотреть, чего не хватает
python3 -m usdt_agent -c config/agent.toml doctor

# сухой прогон по-настоящему живого режима
export USDT_AGENT_LIVE_CONFIRM=I_UNDERSTAND_THE_RISK
export BINANCE_API_KEY=... BINANCE_API_SECRET=...
python3 -m usdt_agent -c config/agent.toml run --live --max-order 25
```

Ключ на бирже создавайте **без права вывода средств** и с привязкой к IP.

## Архитектура

```
feeds/          → MarketSnapshot   опрос бирж и DefiLlama параллельно; упавший фид не валит агента
strategies/     → Opportunity      предлагают идеи с посчитанной себестоимостью; размер не назначают
allocator.py    → бюджет           Thompson sampling по стратегиям
risk.py         → Decision         единственное место, где рождается размер позиции; право вето
execution/      → Fill             paper (пессимистичная модель) | live (за четырьмя блокировками)
ledger.py       → журнал           SQLite + хеш-цепочка, устойчивая к правкам задним числом
statistics.py   → EdgeVerdict      доказано преимущество или нет
agent.py                           цикл, связывающий всё это
```

Правило учёта одно и применяется везде:

```
realized_pnl = accrued − entry_cost − exit_cost
```

`entry_cost`/`exit_cost` считает брокер относительно средней цены, поэтому
безубыточный оборот mid-to-mid даёт ровно ноль. Стратегия отвечает только на
вопрос «сколько позиция стоит сейчас относительно входа» и **не может сама
посчитать свои издержки** — прятать их негде.

## Конфигурация

Всё в `config/agent.toml` (файл безопасно коммитить — секретов там нет).
Любое значение переопределяется из окружения, `__` означает вложенность:

```bash
USDT_AGENT_RISK__MAX_OPEN_TRADES=4 \
USDT_AGENT_STARTING_EQUITY_USDT=250 \
python3 -m usdt_agent run
```

Главное, что стоит поменять под себя, — `[execution] taker_fee_bps`. Значение
по умолчанию 5 б.п. (0.05 %); при VIP-уровне или BNB-скидке оно другое, и от
него напрямую зависит, какие идеи вообще проходят порог.

## Чего агент не делает

Честный список границ:

- **Не подписывает ончейн-транзакции.** `stable_yield` находит и учитывает
  доходность, но депозит в пул требует кошелька и адаптера под протокол. Ноги с
  типом `pool` live-брокер отклоняет явно, а не «тихо пропускает».
- **Не переводит средства между биржами.** `cross_venue` предполагает, что
  баланс уже заведён на обе площадки — именно так эта стратегия и работает.
- **Не обещает доходности.** Симулятор моделирует комиссии, задержку и adverse
  selection, но не смоделирует остановку вывода средств на бирже.
- **Live реализован только для Binance spot.** Остальные площадки — публичные
  данные и бумажная торговля.
