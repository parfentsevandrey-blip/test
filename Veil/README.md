# Veil — VPN-клиент для Mac

Шестое приложение каталога (см. [манифест](../MANIFESTO.md)). Это аналог Happ, v2rayN и Hiddify, сделанный
как родная программа для macOS: Swift 6, SwiftUI, Liquid Glass, русский интерфейс. Вставляете ссылку
подписки от провайдера и нажимаете большую кнопку. Veil сам:
- разбирает все форматы ссылок;
- проверяет, какой сервер быстрее;
- держит соединение и переподключается, если что-то пошло не так.

Veil, как и Happ, не продаёт серверы: нужна подписка или ссылка от вашего провайдера.

Протоколы обслуживает [Xray-core](https://github.com/XTLS/Xray-core) (MPL-2.0) — тот же движок, что внутри
Happ. Это второе осознанное исключение из правила «без сторонних кодов», как llama.cpp в Synapse: ядро
собирается **из исходников** вместе с приложением. Всё остальное написано с нуля:
- разбор ссылок и подписок;
- маршрутизация;
- системный прокси;
- помощник для TUN;
- проверка задержки;
- сторож связи;
- интерфейс.

> **Установка без предупреждений macOS.** Проще всего через [Harbor](../Harbor/) — каталог всех наших приложений.
> Поставьте его одной командой в Терминале
> `curl -fsSL https://github.com/parfentsevandrey-blip/test/releases/download/catalog/install.sh | bash`
> и установите Veil из каталога: обновления будут приходить сами, данные и настройки сохранятся.
> Без Harbor: `curl -fsSL https://github.com/parfentsevandrey-blip/test/releases/download/catalog/install.sh | bash -s -- veil`.

## Чем лучше Happ на Mac

| | Happ | Veil |
|---|---|---|
| Интерфейс | перенесён с телефона | родное окно Mac: Liquid Glass, строка меню, перетаскивание, QR-код с экрана |
| Стабильность | падает, зависает, оставляет Mac без интернета | ядро — отдельная программа: упало — Veil перезапустит; сторож помощника сам выключит прокси, если Veil закрылся аварийно |
| Сон и смена Wi-Fi | соединение «висит» | переподключение после сна и смены сети, проверка связи каждые 20 с |
| Сервер перестал работать | вручную | автопереключение на самый быстрый сервер той же подписки |
| Задержка | ICMP/TCP-пинг | настоящая: полный HTTPS-запрос через сервер, все серверы параллельно |
| Для России | общие правила | режимы «Умный» и «Только заблокированное» по базам runetfreedom (антифильтр, re:filter) |

## Что умеет

| | |
|---|---|
| **Ссылки** | `vless://` (Reality, XTLS-Vision, XHTTP, gRPC, WebSocket, HTTPUpgrade, mKCP), `vmess://` (формат v2rayN и новый URI), `trojan://`, `ss://` (SIP002, старый base64, Shadowsocks 2022), `socks://`, `hy2://` и `hysteria2://` (обфускация Salamander, смена портов, отпечаток сертификата). Параметры Happ после `#`: описание сервера, фрагментация. |
| **Подписки** | Тело — base64, ссылки построчно или JSON-конфигурации Xray (Remnawave, Marzban). Заголовки, как у Happ: `profile-title`, `subscription-userinfo` (полоса трафика и срок), `profile-update-interval` (автообновление), `announce` (объявление провайдера), `support-url` и `profile-web-page-url` (кнопки поддержки и сайта), `routing` (профиль маршрутизации). Те же параметры строками `#имя: значение` в теле. HWID для провайдеров с лимитом устройств — случайный, не серийный номер. |
| **Импорт** | Из буфера обмена, перетаскиванием, по QR-коду на экране или на картинке, ссылками `happ://add/…`, `veil://`, `vless://` из браузера и Telegram (Veil регистрирует эти схемы). |
| **Режимы** | «Системный прокси» — браузеры и почти все программы. «Весь трафик (TUN)» — каждая программа, включая игры и терминал, с DNS через туннель. «Только локальный порт» — SOCKS5 и HTTP для ручной настройки, ничего в системе не меняется. |
| **Маршрутизация** | «Умный»: российские сайты, банки и Госуслуги — напрямую, заблокированное и закрытые для России сервисы (ИИ-чаты, YouTube) — через VPN, остальное — через VPN. «Только заблокированное»: через VPN только то, что не открывается, остальное — на полной скорости. «Всё через VPN». Профили Happ `happ://routing/add/…` из подписки или по ссылке. Свои списки «напрямую / через VPN / блокировать», блокировка рекламы. |
| **DNS** | Для зарубежных сайтов — DoH через сервер (провайдер не видит и не подменяет), для российских — DoH Яндекса напрямую. |
| **Обход DPI** | Фрагментация первого пакета TLS — глобально или из ссылки. |
| **Надёжность** | Сторож связи, автопереключение, переподключение после сна и смены сети, перезапуск ядра после сбоя, возврат системных настроек при выходе. |
| **Раздача** | Прокси для телефона или телевизора в той же сети. |
| **Поделиться** | QR-код сервера для Happ, Streisand, v2rayNG. |

## Как устроено

```
Veil/
  XRAY_VERSION              — версия ядра (v26.9.30)
  scripts/build-core.sh     — Xray-core из исходников (Go, без cgo) → Vendor/xray/xray
  scripts/build.sh          — ядро + Veil + помощник → dist/Veil.app и Veil.dmg
  Sources/VeilShared        — протокол приложения и помощника, очистка конфигурации
  Sources/VeilHelper        — помощник с правами root (служба launchd)
  Sources/Veil/Core
    Links.swift             — разбор ссылок всех форматов (вручную: эмодзи и неэкранированные символы ломают URLComponents)
    Subscription.swift      — загрузка подписок, заголовки и параметры Happ, JSON-конфигурации, базы сайтов
    Routing.swift           — режимы, профили Happ, правила, чтение категорий geosite/geoip прямо из protobuf
    XrayConfig.swift        — конфигурация ядра: исходящие для всех протоколов, DNS, TUN, метрики, тестер задержки
    Core.swift              — ядро отдельной программой, журнал, счётчики трафика, проверки через сервер
    Ping.swift              — настоящая задержка (ядро-тестер, по порту на сервер) и TCP-пинг
    HelperClient.swift      — установка помощника паролем администратора и обмен с ним
  Sources/Veil/Views        — окно (кнопка, сервер, скорость, режимы | подписки и серверы), меню, настройки, журнал
```

- **Ядро — отдельная программа.** Если оно упадёт на капризном сервере, Veil это заметит и перезапустит
  его, а сам продолжит работать. Ядро не умеет «отключаться наполовину».
- **Помощник** ставится один раз, пароль запрашивает сама macOS. Это служба с правами root, которая умеет
  только включать системный прокси и DNS и запускать ядро в режиме TUN. Изменения системы она делает через
  SystemConfiguration, запоминая прежние настройки пользователя, и возвращает их ровно такими, какими они
  были.
  - Отвечает только тому пользователю, который её поставил: проверяет uid собеседника на сокете.
  - Для TUN запускает свою копию ядра, принадлежащую root.
  - Из конфигурации удаляет всё, чем ядро могло бы читать или писать файлы.
  - Каждые 5 секунд проверяет порт прокси: если Veil закрылся аварийно, через 15 секунд возвращает
    настройки сети, и Mac не остаётся без интернета.
- **TUN** — встроенный в Xray (utun, маршруты 0/1…128/1 с защитой от петли, исходящие привязаны к физическому
  интерфейсу). DNS системы на это время направляется в туннель, после выключения возвращается прежний.
- **Без баз сайтов** ядро не запустилось бы с правилами `geosite:`. Поэтому Veil читает список категорий
  из скачанных файлов (protobuf, без ядра) и в конфигурацию берёт только те, что действительно есть.

## Сборка

```sh
cd Veil
./scripts/build.sh          # → dist/Veil.app и dist/Veil.dmg
```

Нужны Xcode 26 и Go (нужная версия Go для ядра скачается сама).

## Проверки

CI на macOS (`.github/workflows/veil-macos.yml`) проверяет настоящую работу приложения.

- **`--selftest-logic`** (без сети и ядра):
  - ссылки всех форматов, включая IPv6, эмодзи, параметры Happ, VMess с числовым портом и SS 2022 с экранированием;
  - подписки: base64, строки `#параметров`, JSON и Clash;
  - профили Happ, правила маршрутизации, чтение категорий баз, очистка конфигурации для root;
  - сборка ссылки обратно без потерь.
- **`--selftest-core`** — на раннере поднимается настоящий сервер Xray:
  - 14 вариантов протоколов и транспортов, включая Reality Vision, Reality XHTTP, Hysteria 2 и Shadowsocks 2022;
  - для каждой ссылки: разбор → конфигурация → проверка ядром → подключение → запрос через сервер → счётчики трафика;
  - задержка всех серверов одним тестером;
  - подписка по HTTP с заголовками;
  - скачивание баз runetfreedom и проверка, что ядро принимает конфигурацию в каждом режиме маршрутизации (прокси и TUN).
- **`--selftest-helper`** — помощник запускается с правами root, как после установки:
  - системный прокси виден в `scutil --proxy` и выключается с возвратом прежних настроек;
  - сторож: если «Veil упал», прокси выключается сам;
  - TUN: обычный `curl` без прокси проходит через туннель, DNS направлен в туннель, после остановки всё как было.
- **`--demo-ui`** — скриншоты с живым подключением через сервер стенда.
