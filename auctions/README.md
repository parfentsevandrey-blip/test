# Объекты торгов — еженедельный документ

Генератор Word-документа по лотам торгов Москвы и Подмосковья
(investmoscow.ru / torgi.mos.ru).

На каждый объект документ даёт:

| Поле | Источник |
|---|---|
| описание объекта | пишется вручную в `data/descriptions.json` |
| точный адрес | карточка лота |
| начальная цена | карточка лота |
| цена за кв. м. | карточка лота |
| дата окончания приёма заявок | карточка лота (МСК) |
| дата проведения торгов | карточка лота (МСК) |
| задаток в рублях | вкладка «Сведения о процедуре» |
| локация | скриншот Яндекс Карт с меткой, масштаб подобран так, чтобы было видно ближайшее метро |
| фото объекта | все фото из объявления, по 6 на лист |

Готовый файл: `out/Торги_Москва_и_Подмосковье.docx`.

## Как добавить объект

```bash
ID=obj6
URL=https://investmoscow.ru/tenders/tender/20188709

# 1. данные лота: цены, даты, задаток, координаты, метро, список фото
python3 fetch_object.py "$URL" $ID

# 2. страницы-сетки для съёмки фото — их нужно запушить, снимает их не этот
#    контейнер, а браузер ридера, поэтому они должны быть доступны по HTTP
python3 tools/make_grid.py assets/$ID/images.txt tools/grids/$ID 6
git add auctions && git commit -m "grids for $ID" && git push

# 3. карта + сетки (шесть фото за один скриншот), затем нарезка
python3 tools/capture_all.py <branch> $ID
python3 tools/slice_grid.py assets/$ID/grids assets/$ID/photos_raw
python3 prep_images.py assets/$ID/photos_raw assets/$ID/photos --bg ff00ff

# 4. описание объекта и порядок — в data/descriptions.json, дальше сборка
python3 tools/make_entries.py      # пересобирает data/objects.json
node build_doc.js
```

## Почему так сложно с картинками

`investmoscow.ru` и `torgi.mos.ru` (IP 94.79.51.0/24) сбрасывают TCP-соединения
из этой сети — не работают ни `curl`, ни headless Chromium. Пробиться получается
только через ридер `r.jina.ai`, который сам ходит на сайт и отдаёт готовый
скриншот или HTML.

Ридер, однако, жёстко лимитирует запросы, поэтому фото снимаются не по одному, а
пачками: страница-сетка с шестью фото в слотах 1024×800 на пурпурном фоне
выкладывается в этот репозиторий, открывается через `htmlpreview.github.io`
(`raw.githubusercontent.com` отдаёт HTML как `text/plain`, а githack показывает
заставку) и снимается одним скриншотом на всю высоту. Фото приходят в исходном
разрешении 1024×768.

Данные лота берутся не из вёрстки, а из полезной нагрузки страницы: Nuxt кладёт
всю модель в `<script id="__NUXT_DATA__">`, откуда цены, даты, задаток,
координаты и метро читаются в том виде, в каком их отдал сервер.

## Время

Сайт показывает даты в часовом поясе браузера, поэтому у ридера (UTC) они
выглядят на три часа раньше. В документе стоит московское время из полей
`procedureInfo` самого лота.

## Вёрстка

Высоты фотолистов заданы жёстко: страница разбивается на строки с точной
высотой (`w:trHeight … hRule="exact"`), разрыв страницы висит на заголовке
раздела, у заголовка фиксированный интерлиньяж. На каждый лист заложено ~1,7 см
запаса: Word и LibreOffice считают высоты чуть по-разному, а перебор даже на
один твип уносит целый ряд фото на следующую страницу.

Проверка вёрстки локально (LibreOffice, не Word — расхождения возможны):

```bash
soffice --headless --convert-to pdf --outdir out out/Торги_Москва_и_Подмосковье.docx
```

## Файлы

```
data/descriptions.json       описания объектов и порядок — правится вручную
data/objects.json            собирается tools/make_entries.py, не править руками
build_doc.js                 сборка .docx (npm-пакет docx)
fetch_object.py              данные лота из __NUXT_DATA__ + список фото
prep_images.py               обрезка фона, JPEG, манифест размеров
tools/make_grid.py           страницы-сетки для съёмки
tools/capture_grids.py       скриншоты сеток через r.jina.ai
tools/capture_map.py         карта с подбором масштаба по ближайшему метро
tools/capture_all.py         карта + сетки для нескольких объектов подряд
tools/slice_grid.py          нарезка сеток на отдельные фото
tools/make_entries.py        сборка data/objects.json из lot.json + описаний
assets/<id>/                 lot.json, карта, фото и сырые captures объекта
```
